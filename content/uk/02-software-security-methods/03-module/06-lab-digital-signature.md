## Теоретичні відомості

### 1 Концепція електронного цифрового підпису

Електронний цифровий підпис (ЕЦП) — це математичний механізм, що забезпечує:

- **Автентичність**: підтвердження особи автора документа
- **Цілісність**: виявлення будь-яких змін у документі
- **Неспростовність**: автор не може відмовитися від свого підпису

```
┌─────────────────────────────────────────────────────────────────────┐
│                     ЕЛЕКТРОННИЙ ЦИФРОВИЙ ПІДПИС                     │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│  ФОРМУВАННЯ ПІДПИСУ (автор):                                        │
│  Документ M ──► [HASH] ──► H(M) ──► [SIGN з d] ──► Підпис S         │
│                                      (закритий ключ)                │
│                                                                     │
│  ПЕРЕВІРКА ПІДПИСУ (будь-хто):                                      │
│  Документ M ──► [HASH] ──► H(M) ─────────┐                          │
│                                          ├──► [==] ──► дійсний?     │
│  Підпис S ───► [VERIFY з e] ──► H′ ──────┘                          │
│                 (відкритий ключ)                                    │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

### 2 Схема підпису RSA

Схема RSA використовує ті самі ключі, що й для шифрування, але в іншому порядку:

**Ключі:**

- Відкритий ключ: (e, n) — для перевірки підпису
- Закритий ключ: (d, n) — для формування підпису

**Формування підпису:**

```
S = H(M)^d mod n
```

де:

- M — повідомлення
- H(M) — хеш повідомлення
- d — закрита експонента
- n — модуль RSA
- S — цифровий підпис

**Перевірка підпису:**

```
H'(M) = S^e mod n
Підпис дійсний, якщо H'(M) == H(M)
```

### 3 Роль хеш-функції

Безпосереднє підписування повідомлення M має проблеми:

1. **Повільно**: RSA працює з числами, меншими за n; великі документи потребують багато операцій
2. **Небезпечно**: атака множення — можна створити підпис для добутку двох підписаних повідомлень

Хеш-функція вирішує обидві проблеми:

- Фіксований розмір виходу (256 біт для SHA-256)
- Лавинний ефект унеможливлює підробку

```
Без хешу:  S1 = M1^d, S2 = M2^d  →  S1 · S2 = (M1 · M2)^d mod n
           добуток двох справжніх підписів — справжній підпис
           документа M1 · M2, якого автор ніколи не бачив

З хешем:   S1 · S2 = (H(M1) · H(M2))^d — це підпис ЧИСЛА H(M1)·H(M2)
           щоб ним скористатися, треба знайти документ M3,
           у якого H(M3) = H(M1) · H(M2) mod n, тобто прообраз хешу
```

### 4 Стандарт PKCS#1

PKCS#1 (Public-Key Cryptography Standards) визначає формат підпису:

```
┌─────────────────────────────────────────────────────────────────────┐
│                    ФОРМАТ PKCS#1 v1.5                               │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│  EM = 0x00 || 0x01 || PS || 0x00 || T                               │
│                                                                     │
│  0x00 0x01  — заголовок (вказує на підпис)                          │
│  PS         — padding з байтів 0xFF (мінімум 8 байт)                │
│  0x00       — розділювач                                            │
│  T          — DigestInfo (OID алгоритму хешу + хеш)                 │
│                                                                     │
│  Приклад DigestInfo для SHA-256:                                    │
│  30 31 30 0D 06 09 60 86 48 01 65 03 04 02 01    -- OID SHA-256     │
│  05 00                                           -- NULL            │
│  04 20 [32 байти хешу]                           -- OCTET STRING    │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```
Для навчальних цілей використовуємо спрощену схему без PKCS#1.

### 5 Властивості цифрового підпису

Таблиця 1 — Властивості цифрового підпису

| Властивість | Опис | Як досягається |
|----|----|----|
| **Автентичність** | Підпис може створити тільки власник закритого ключа | Операція S = H(M)^d mod n |
| **Цілісність** | Будь-яка зміна документа змінює хеш | Лавинний ефект хеш-функції |
| **Неспростовність** | Автор не може відмовитися від підпису | Закритий ключ відомий тільки автору |

## Приклад виконання

### Крок 1. Структура програми

```cpp
#include <iostream>
#include <string>
#include <stdexcept>

using u64 = unsigned long long;

// Ключова пара RSA для цифрового підпису.
// Модуль n тримаємо меншим за 2^31, щоб добуток вмістився у 64 біти.
class RSAKeyPair {
public:
    RSAKeyPair(u64 p, u64 q, u64 e = 17) : e_(e) {
        n_ = p * q;
        u64 phi = (p - 1) * (q - 1);

        if (gcd(e_, phi) != 1) {
            throw std::runtime_error("e та phi(n) не взаємно прості");
        }
        d_ = modInverse(e_, phi);
    }

    u64 modulus() const { return n_; }
    u64 publicExponent() const { return e_; }   // відкритий ключ: (e, n)
    u64 privateExponent() const { return d_; }  // закритий ключ:  (d, n)

    static u64 gcd(u64 a, u64 b) {
        while (b != 0) {
            u64 t = a % b;
            a = b;
            b = t;
        }
        return a;
    }

    // Обернений елемент за модулем, розширений алгоритм Евкліда
    static u64 modInverse(u64 a, u64 m) {
        long long oldR = static_cast<long long>(a), r = static_cast<long long>(m);
        long long oldS = 1, s = 0;

        while (r != 0) {
            long long q = oldR / r;
            long long tmp = oldR - q * r;  oldR = r;  r = tmp;
            tmp = oldS - q * s;            oldS = s;  s = tmp;
        }

        if (oldR != 1) {
            throw std::runtime_error("Оберненого елемента не існує");
        }
        long long mod = static_cast<long long>(m);
        return static_cast<u64>(((oldS % mod) + mod) % mod);
    }

    // Швидке модульне піднесення до степеня
    static u64 modPow(u64 base, u64 exp, u64 modulus) {
        u64 result = 1;
        base %= modulus;

        while (exp > 0) {
            if (exp & 1ULL) result = (result * base) % modulus;
            exp >>= 1;
            base = (base * base) % modulus;
        }
        return result;
    }

private:
    u64 n_ = 0, e_ = 0, d_ = 0;
};
```
### Крок 2. Хешування повідомлення

```cpp
#include <string>
#include <cstdint>

// Клас SHA256 узято з лабораторної роботи №7 — підключіть його файл до проєкту.
// Потрібен лише метод, що повертає хеш рядка у шістнадцятковому вигляді.
std::string sha256(const std::string& message);

using u64 = unsigned long long;

// Перетворює перші 8 байтів хешу на 64-бітне число.
// Саме це число далі підписується: підписувати весь 256-бітний хеш
// навчальним ключем неможливо, бо він має бути меншим за модуль n.
u64 hashToNumber(const std::string& message) {
    std::string hex = sha256(message);
    u64 value = 0;

    for (int i = 0; i < 16; ++i) {           // 16 hex-символів = 8 байтів
        char c = hex[i];
        int digit = (c >= '0' && c <= '9') ? c - '0'
                  : (c >= 'a' && c <= 'f') ? c - 'a' + 10
                                           : c - 'A' + 10;
        value = (value << 4) | static_cast<u64>(digit);
    }
    return value;
}

// Хеш має бути меншим за модуль, інакше операція піднесення до степеня
// втрачає однозначність. У реальних системах цю задачу розв'язує
// доповнення за стандартом PKCS#1, а не просте відкидання старших біт.
u64 truncateHash(u64 hashValue, u64 n) {
    return hashValue % n;
}
```

### Крок 3. Формування та перевірка підпису

```cpp
#include <string>

using u64 = unsigned long long;

u64 hashToNumber(const std::string& message);   // з кроку 2
u64 truncateHash(u64 hashValue, u64 n);         // з кроку 2

// Формування підпису: S = H(M)^d mod n
// Підписує лише власник закритого ключа
u64 sign(const std::string& message, u64 d, u64 n) {
    u64 h = truncateHash(hashToNumber(message), n);
    return RSAKeyPair::modPow(h, d, n);
}

// Перевірка підпису: H' = S^e mod n, далі порівняння з H(M)
// Перевірити може будь-хто, маючи лише відкритий ключ
bool verify(const std::string& message, u64 signature, u64 e, u64 n) {
    u64 expected = truncateHash(hashToNumber(message), n);
    u64 recovered = RSAKeyPair::modPow(signature, e, n);
    return expected == recovered;
}
```

### Крок 4. Демонстрація роботи

```cpp
#include <iostream>
#include <string>

int main() {
    std::cout << "============================================================\n";
    std::cout << "ДЕМОНСТРАЦІЯ ЦИФРОВОГО ПІДПИСУ RSA\n";
    std::cout << "============================================================\n";

    // Малі прості числа взято для наочності; у реальних системах
    // модуль має довжину 2048 біт і більше
    u64 p = 10007, q = 10009;
    RSAKeyPair keys(p, q, 17);

    u64 n = keys.modulus();
    u64 e = keys.publicExponent();
    u64 d = keys.privateExponent();

    std::cout << "\nПараметри RSA:\n";
    std::cout << "  p = " << p << ", q = " << q << "\n";
    std::cout << "  n = " << n << "\n";
    std::cout << "  e = " << e << " (відкрита експонента)\n";
    std::cout << "  d = " << d << " (закрита експонента)\n";

    std::string document = "Договір купівлі-продажу №123";

    std::cout << "\n------------------------------------------------------------\n";
    std::cout << "ФОРМУВАННЯ ПІДПИСУ\n";
    std::cout << "------------------------------------------------------------\n";
    std::cout << "Документ: \"" << document << "\"\n";
    std::cout << "Хеш (обрізаний): "
              << truncateHash(hashToNumber(document), n) << "\n";

    u64 signature = sign(document, d, n);
    std::cout << "Підпис S = " << signature << "\n";

    std::cout << "\n------------------------------------------------------------\n";
    std::cout << "ПЕРЕВІРКА ПІДПИСУ\n";
    std::cout << "------------------------------------------------------------\n";
    std::cout << "Результат: "
              << (verify(document, signature, e, n) ? "ПІДПИС ДІЙСНИЙ"
                                                   : "ПІДПИС НЕДІЙСНИЙ")
              << "\n";

    std::cout << "\n------------------------------------------------------------\n";
    std::cout << "ВИЯВЛЕННЯ МОДИФІКАЦІЇ\n";
    std::cout << "------------------------------------------------------------\n";
    std::string modified = "Договір купівлі-продажу №124";  // змінено один символ
    std::cout << "Модифікований документ: \"" << modified << "\"\n";
    std::cout << "Результат: "
              << (verify(modified, signature, e, n) ? "ПІДПИС ДІЙСНИЙ"
                                                   : "ПІДПИС НЕДІЙСНИЙ")
              << "\n";

    std::cout << "\n------------------------------------------------------------\n";
    std::cout << "СПРОБА ПІДРОБКИ ПІДПИСУ\n";
    std::cout << "------------------------------------------------------------\n";
    u64 fake = signature + 1;
    std::cout << "Підроблений підпис: " << fake << "\n";
    std::cout << "Результат: "
              << (verify(document, fake, e, n) ? "ПІДПИС ДІЙСНИЙ"
                                               : "ПІДПИС НЕДІЙСНИЙ")
              << "\n";

    return 0;
}
```

| 17 | p=227, q=229 | Реалізувати мультипідпис: два підписувачі підписують один документ. |
| 18 | p=233, q=239 | Порівняти RSA-підпис з ECDSA (описати теоретично, реалізувати RSA). |
| 19 | p=241, q=251 | Реалізувати підпис із сертифікатом (включити публічний ключ у підписаний блок). |
| 20 | p=257, q=263 | Продемонструвати важливість випадковості: що буде, якщо використати однакові p і q? |

## Контрольні запитання

Запитання згруповано за рівнями навчальних досягнень. Для позитивної оцінки студент має відповісти на запитання середнього рівня, оцінка «добре» потребує відповідей достатнього рівня, оцінка «відмінно» — високого.

### Середній рівень (репродуктивний)

1. Які три властивості забезпечує електронний цифровий підпис?
2. Яким ключем формується підпис і яким перевіряється?
3. Навіщо хешувати повідомлення перед підписом?
4. Чим підпис RSA відрізняється від шифрування RSA?
5. Що таке неспростовність (non-repudiation)?
6. Що таке сертифікат відкритого ключа?
7. Як виявити модифікацію підписаного документа?
8. Що таке PKCS#1?

### Достатній рівень (конструктивно-варіативний)

1. Що станеться, якщо підписувати документ без попереднього хешування?
2. Чому для підпису достатньо хешу, а не всього документа?
3. Чому відкритий ключ використовують для перевірки, а не для формування підпису?
4. Як досягається неспростовність і за яких умов вона втрачається?
5. Яку проблему розв'язує доповнення за PKCS#1 і що буде без нього?
6. Навіщо потрібен центр сертифікації, якщо відкритий ключ і так відкритий?
7. Як захиститися від підробки підпису методом повтору (replay attack)?
8. Як перевірити реалізацію підпису на документі, змінений на один біт?

### Високий рівень (творчий)

1. Поясніть повний ланцюжок довіри: від сертифіката користувача до кореневого центру сертифікації. Де саме він може розірватися?
2. Скомпрометовано закритий ключ, яким за рік підписано сотні документів. Опишіть порядок дій і поясніть роль списку відкликаних сертифікатів.
3. Порівняйте ЕЦП на основі RSA та на основі еліптичних кривих за розміром підпису, швидкодією та поширеністю.
4. Сформулюйте, чим юридично значущий підпис відрізняється від технічно коректного, і які вимоги додає законодавство.
