## Теоретичні відомості

### 1 Призначення криптографічних хеш-функцій

Хеш-функція — це функція, яка перетворює вхідне повідомлення довільної довжини на вихідний рядок фіксованої довжини (дайджест). Криптографічна хеш-функція повинна мати такі властивості:

- **Детермінованість**: однакове повідомлення завжди дає однаковий хеш
- **Швидкість**: обчислення хешу має бути ефективним
- **Стійкість до прообразу**: за хешем неможливо відновити повідомлення
- **Стійкість до колізій**: важко знайти два різних повідомлення з однаковим хешем
- **Лавинний ефект**: зміна одного біта повідомлення кардинально змінює хеш

### 2 Структура SHA-256

SHA-256 (Secure Hash Algorithm 256-bit) належить до сімейства SHA-2, розробленого NSA у 2001 році.

```
┌─────────────────────────────────────────────────────────────────────┐
│                      АЛГОРИТМ SHA-256                               │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│  Повідомлення ──► [PADDING] ──► [РОЗБИТТЯ] ──► [ОБРОБКА] ──► Хеш    │
│                                  512 біт      64 раунди    256 біт  │
│                                                                     │
│  ЕТАПИ:                                                             │
│  1. Доповнення повідомлення до кратного 512 біт                     │
│  2. Розбиття на блоки по 512 біт                                    │
│  3. Ініціалізація 8 робочих змінних (H0-H7)                         │
│  4. Для кожного блоку:                                              │
│     - Розширення 16 слів до 64 слів                                 │
│     - 64 раунди функції стиснення                                   │
│     - Додавання результату до H0-H7                                 │
│  5. Конкатенація H0-H7 → 256-бітний хеш                             │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

### 3 Доповнення повідомлення (Padding)

Повідомлення доповнюється за схемою:

1. Додати біт `1` після повідомлення
2. Додати нулі, щоб довжина стала на 64 біти менше кратної 512
3. Додати 64-бітне представлення довжини початкового повідомлення

```
Оригінал:     M (L біт)
Доповнене:    M || 1 || 0...0 || L(64 біти)
              ↑    ↑    ↑         ↑
              |    |    |         Довжина у бітах (big-endian)
              |    |    Нулі для вирівнювання
              |    Обов'язковий біт "1"
              Повідомлення
```
**Приклад для "abc":**

- Довжина: 24 біти (3 байти)
- Потрібно: 512 - 64 - 24 - 1 = 423 нульових біти
- Результат: `61626380 00000000 ... 00000018` (у hex)

Якщо довжина повідомлення від 448 до 511 біт за модулем 512, після біта `1` для 64-бітної довжини вже не лишається місця, і доповнення займає цілий додатковий блок. Саме тому третій тестовий вектор NIST має рівно 448 біт: він перевіряє цей граничний випадок.

### 4 Функції раунду

SHA-256 використовує шість логічних функцій:

```
// Функції вибору та більшості
#define Ch(x,y,z)  ((x & y) ^ (~x & z))
#define Maj(x,y,z) ((x & y) ^ (x & z) ^ (y & z))

// Функції обертання (Σ - sigma)
#define ROTR(x,n)  ((x >> n) | (x << (32-n)))

#define Σ0(x)  (ROTR(x,2) ^ ROTR(x,13) ^ ROTR(x,22))
#define Σ1(x)  (ROTR(x,6) ^ ROTR(x,11) ^ ROTR(x,25))
#define σ0(x)  (ROTR(x,7) ^ ROTR(x,18) ^ (x >> 3))
#define σ1(x)  (ROTR(x,17) ^ ROTR(x,19) ^ (x >> 10))
```

### 5 Константи алгоритму

### 6 Цикл стиснення (один раунд)

```
┌─────────────────────────────────────────────────────────────────────┐
│                            РАУНД SHA-256                            │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│  T1 = h + Σ1(e) + Ch(e,f,g) + K[i] + W[i]                           │
│  T2 = Σ0(a) + Maj(a,b,c)                 (усе додавання — mod 2³²)  │
│                                                                     │
│   до раунду:  a      b      c      d      e      f      g      h    │
│                ╲      ╲      ╲             ╲      ╲      ╲          │
│   після:     T1+T2  a      b      c     d+T1   e      f      g      │
│              = a'   = b'   = c'   = d'   = e'   = f'   = g'   = h'  │
│                                                                     │
│  Вісім слів працюють як зсувний регістр: кожне зсувається на        │
│  одну позицію праворуч, а по-справжньому обчислюються лише          │
│  два нові значення — a' = T1 + T2 і e' = d + T1.                    │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

### Крок 1. Структура програми

```cpp
#include <iostream>
#include <cstdint>
#include <cstring>
#include <iomanip>
#include <sstream>

// Функції обертання вправо
#define ROTR(x, n) (((x) >> (n)) | ((x) << (32 - (n))))

// Логічні функції SHA-256
#define Ch(x, y, z)  (((x) & (y)) ^ (~(x) & (z)))
#define Maj(x, y, z) (((x) & (y)) ^ ((x) & (z)) ^ ((y) & (z)))
#define Sigma0(x)    (ROTR(x, 2) ^ ROTR(x, 13) ^ ROTR(x, 22))
#define Sigma1(x)    (ROTR(x, 6) ^ ROTR(x, 11) ^ ROTR(x, 25))
#define sigma0(x)    (ROTR(x, 7) ^ ROTR(x, 18) ^ ((x) >> 3))
#define sigma1(x)    (ROTR(x, 17) ^ ROTR(x, 19) ^ ((x) >> 10))

class SHA256 {
private:
    uint32_t H[8];  // Стан хешу
    uint8_t buffer[64];  // Буфер для неповного блоку
    uint64_t bitLength;  // Довжина повідомлення в бітах
    uint32_t bufferLength;  // Заповнення буфера

    // Раундові константи K
    static const uint32_t K[64];

    void processBlock(const uint8_t* block);

public:
    SHA256();
    void update(const uint8_t* data, size_t length);
    std::string finalize();
};
```

### Крок 3. Обробка одного блоку (64 раунди)

```cpp
void SHA256::processBlock(const uint8_t* block) {
    uint32_t W[64];  // Розширений масив слів
    uint32_t a, b, c, d, e, f, g, h;

    // Перші 16 слів — з блоку (big-endian)
    for (int i = 0; i < 16; i++) {
        W[i] = (block[i*4] << 24) | (block[i*4+1] << 16) |
               (block[i*4+2] << 8) | block[i*4+3];
    }

    // Розширення до 64 слів
    for (int i = 16; i < 64; i++) {
        W[i] = sigma1(W[i-2]) + W[i-7] + sigma0(W[i-15]) + W[i-16];
    }

    // Ініціалізація робочих змінних
    a = H[0]; b = H[1]; c = H[2]; d = H[3];
    e = H[4]; f = H[5]; g = H[6]; h = H[7];

    // 64 раунди
    for (int i = 0; i < 64; i++) {
        uint32_t T1 = h + Sigma1(e) + Ch(e,f,g) + K[i] + W[i];
        uint32_t T2 = Sigma0(a) + Maj(a,b,c);
        h = g;
        g = f;
        f = e;
        e = d + T1;
        d = c;
        c = b;
        b = a;
        a = T1 + T2;
    }

    // Додавання до поточного хешу
    H[0] += a; H[1] += b; H[2] += c; H[3] += d;
    H[4] += e; H[5] += f; H[6] += g; H[7] += h;
}
```
### Крок 4. Доповнення та фіналізація

```cpp
void SHA256::update(const uint8_t* data, size_t length) {
    for (size_t i = 0; i < length; i++) {
        buffer[bufferLength++] = data[i];
        if (bufferLength == 64) {
            processBlock(buffer);
            bitLength += 512;
            bufferLength = 0;
        }
    }
}

std::string SHA256::finalize() {
    // Додати довжину оброблених бітів + залишок у буфері
    bitLength += bufferLength * 8;

    // Padding: додати біт 1
    buffer[bufferLength++] = 0x80;

    // Якщо не вистачає місця для довжини (8 байт), обробити блок
    if (bufferLength > 56) {
        while (bufferLength < 64) buffer[bufferLength++] = 0;
        processBlock(buffer);
        bufferLength = 0;
    }

    // Заповнити нулями до позиції 56
    while (bufferLength < 56) buffer[bufferLength++] = 0;

    // Додати довжину (big-endian, 64 біти)
    for (int i = 7; i >= 0; i--) {
        buffer[bufferLength++] = (bitLength >> (i * 8)) & 0xff;
    }

    processBlock(buffer);

    // Формування результату
    std::stringstream ss;
    for (int i = 0; i < 8; i++) {
        ss << std::hex << std::setfill('0') << std::setw(8) << H[i];
    }
    return ss.str();
}
```
### Крок 5. Тестування

```cpp
std::string sha256(const std::string& message) {
    SHA256 hasher;
    hasher.update(reinterpret_cast<const uint8_t*>(message.c_str()),
                  message.length());
    return hasher.finalize();
}

// Той самий хеш, але 32 байтами замість 64 шістнадцяткових символів.
// Потрібен там, де хеш є не текстом для показу, а даними: ключем,
// вкладеним повідомленням, аргументом HMAC (лабораторна робота №10).
std::vector<unsigned char> sha256Raw(const std::string& message) {
    std::string hex = sha256(message);
    std::vector<unsigned char> raw(32);

    for (int i = 0; i < 32; i++) {
        raw[i] = static_cast<unsigned char>(
            std::stoi(hex.substr(i * 2, 2), nullptr, 16));
    }

    return raw;
}

int main() {
    // Тестові вектори NIST
    std::cout << "=== Тестові вектори SHA-256 ===\n\n";

    // Тест 1: порожній рядок
    std::string test1 = "";
    std::cout << "Вхід: (порожній рядок)\n";
    std::string expect1 =
        "e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855";
    std::cout << "Хеш: " << sha256(test1) << "\n";
    std::cout << "Очік: " << expect1 << "\n\n";
```

## Порядок виконання роботи

1. Отримати в викладача номер індивідуального варіанта.

2. Реалізувати клас SHA256 згідно з наведеним алгоритмом. Переконатися, що використовуються правильні типи даних (uint32_t для 32-бітних слів).

3. Реалізувати всі шість логічних функцій (Ch, Maj, Σ0, Σ1, σ0, σ1).

4. Реалізувати процедуру доповнення (padding) повідомлення. Перевірити на короткому тексті "abc".

5. Реалізувати функцію обробки блоку (64 раунди). Звернути увагу на правильний порядок байтів (big-endian).

6. Перевірити реалізацію на трьох офіційних тестових векторах NIST.

7. Продемонструвати лавинний ефект: обчислити хеші двох повідомлень, що відрізняються на один символ. Порахувати, скільки біт змінилося у хеші.

8. Виконати індивідуальне завдання згідно з варіантом.

9. Оформити звіт та зробити висновок.

## Контрольні запитання

Запитання згруповано за рівнями навчальних досягнень. Для позитивної оцінки студент має відповісти на запитання середнього рівня, оцінка «добре» потребує відповідей достатнього рівня, оцінка «відмінно» — високого.

### Середній рівень (репродуктивний)

1. Який розмір виводу має SHA-256? Скільки це байтів і шістнадцяткових символів?
2. Скільки раундів виконується під час обробки одного блоку?
3. Який розмір блоку обробляє SHA-256?
4. Для чого потрібне доповнення (padding) повідомлення?
5. Що таке лавинний ефект?
6. Що таке колізія хеш-функції?
7. Назвіть три властивості криптографічної хеш-функції.
8. Де застосовуються хеш-функції в реальних системах?

### Достатній рівень (конструктивно-варіативний)

1. Чому хеш-функція незворотна, хоча складається з оборотних операцій?
2. Чим SHA-256 відрізняється від MD5 і чому MD5 більше не вважають безпечним?
3. Чи можлива колізія для SHA-256 теоретично? Оцініть складність її пошуку.
4. Що таке HMAC і чим він відрізняється від простого хешування зі склеюванням ключа?
5. Чому хеші паролів зберігають із «сіллю» і що саме вона унеможливлює?
6. Чому для зберігання паролів рекомендують повільні функції, а не SHA-256?
7. Як перевірити реалізацію на офіційних тестових векторах NIST?
8. Як хеш-функції використовуються в блокчейні?

### Високий рівень (творчий)

1. Поясніть, чому довжина повідомлення обов'язково входить у доповнення, і яку атаку це унеможливлює.
2. Оцініть, скільки спроб у середньому потрібно для пошуку колізії SHA-256 за парадоксом днів народження, і що це означає практично.
3. Запропонуйте схему перевірки цілісності великого архіву файлів на основі хешування. Обґрунтуйте вибір структури.
4. Сформулюйте критерії, за якими обирають хеш-функцію для нової системи, і поясніть, чому «найновіша» не завжди означає «найкраща».
