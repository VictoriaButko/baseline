## 1 Симетричне шифрування

**Симетричне шифрування** — криптографічна система, в якій для шифрування та дешифрування використовується **один і той самий ключ**.

```
┌─────────────────────────────────────────────────────────────────────┐
│                       СИМЕТРИЧНА КРИПТОСИСТЕМА                      │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│         Аліса                                           Боб         │
│           │          ЗАХИЩЕНИЙ канал (заздалегідь)       │          │
│           ◄────────────────── ключ K ────────────────────►          │
│           │                                              │          │
│           ▼                                              ▼          │
│    P ──►[E_K]──► C ────── ВІДКРИТИЙ канал ──────► C ──►[D_K]──► P   │
│                             │                                       │
│                             ▼                                       │
│                    Єва бачить лише C                                │
│                                                                     │
│  E — шифрування, D — розшифрування, K — один спільний ключ          │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

## 2 Проблема розподілу ключів

Головна проблема симетричного шифрування — **як безпечно передати ключ?**

Якщо є захищений канал для передачі ключа, навіщо тоді шифрування? Відповідь у тому, що ключ короткий і передається один раз, заздалегідь: 32 байти на флешці чи під час особистої зустрічі захистять потім гігабайти листування через звичайний інтернет.

Друга частина проблеми — масштаб. Кожна пара учасників потребує власного ключа, тож для n учасників ключів треба n(n − 1)/2. Для 10 співробітників це 45 ключів, для 1000 — уже 499 500, і кожен треба доставити таємно й вчасно замінювати.

**Історичні рішення:**
- Кур'єри з дипломатичною поштою
- Попередній обмін ключами при особистій зустрічі
- Книжкові шифри (ключ — сторінка книги)

**Сучасні рішення:**
- Протокол Діффі-Геллмана (1976): дві сторони домовляються про спільний ключ відкритим каналом
- Гібридні системи: асиметрична криптографія доставляє ключ, симетрична шифрує дані (у TLS 1.3 — ECDHE + AES-GCM)
- Центри розподілу ключів (Kerberos у доменах Windows): кожен учасник має ключ лише з центром

## 4 Мережа Фейстеля

**Мережа Фейстеля** (Horst Feistel, IBM, 1973) — архітектура блочного шифру, де блок ділиться на дві половини.

```
        L₀ (половина)          R₀ (половина)
            │                      │
            │          ┌───────────┤
            │          ▼           │
            │       ┌─────┐        │
            │       │  F  │◄── K₁  │   ключ раунду
            │       └──┬──┘        │
            ▼          │           │
            ⊕◄─────────┘           │
            │                      │
            └─────────┐ ┌──────────┘
                      ╳                половини міняються місцями
            ┌─────────┘ └──────────┐
            ▼                      ▼
        L₁ = R₀            R₁ = L₀ ⊕ F(R₀, K₁)
            │                      │
           ...  повторюємо n раундів з ключами K₂, K₃, …
```

Розшифрування: маючи L₁ і R₁, отримуємо R₀ = L₁, а L₀ = R₁ ⊕ F(L₁, K₁). Функцію F обертати не потрібно — її просто обчислюють ще раз.

**Властивості:**
1. **Оборотність**: дешифрування — ті ж операції у зворотному порядку
2. **Функція F може бути будь-якою**: не обов'язково оборотною
3. **Простота реалізації**: однаковий код для шифрування/дешифрування

**Шифри на основі мережі Фейстеля:**
- DES
- Blowfish
- Twofish
- ГОСТ 28147-89 (32 раунди)

Ключова властивість мережі Фейстеля: **функція раунду F може бути якою завгодно** —
навіть необоротною. Оборотність забезпечує сама схема, бо на кожному раунді одна
половина проходить без змін, а друга додається до неї за модулем 2. Розшифрування —
та сама процедура з раундовими ключами у зворотному порядку. Саме тому апаратна
реалізація DES шифрує й розшифровує одним блоком логіки.

Ціна цієї зручності — за один раунд змінюється лише половина блоку, тому раундів
потрібно багато: у DES їх 16.

## 5 SP-мережі

**SP-мережа** — альтернативна архітектура, де весь блок обробляється одночасно.

```
              Вхідний блок (128 біт)
                      │
                      ⊕ ◄──────────── ключ раунду Kᵢ
                      │
      ┌───────────────┴───────────────┐
      │  S-блоки: нелінійна заміна    │
      │  ┌───┐ ┌───┐ ┌───┐ ... ┌───┐  │
      │  │ S │ │ S │ │ S │     │ S │  │
      │  └───┘ └───┘ └───┘     └───┘  │
      └───────────────┬───────────────┘
                      │
      ┌───────────────┴───────────────┐
      │  P-шар: перемішування бітів   │
      └───────────────┬───────────────┘
                      │
                     ...   повторюємо n раундів
                      │
              Вихідний блок (128 біт)
```

**Компоненти:**
- **S-блок (Substitution box)**: нелінійна заміна, забезпечує конфузію
- **P-шар (Permutation layer)**: перемішування бітів, забезпечує дифузію

**Шифри на основі SP-мереж:**
- AES
- Serpent
- PRESENT
- Калина (ДСТУ 7624:2014) — український стандарт, за будовою близький до AES

Таблиця 1 — Порівняння двох архітектур

| Ознака | Мережа Фейстеля | SP-мережа |
|--------|-----------------|-----------|
| Що обробляється за раунд | половина блоку | увесь блок |
| Вимоги до функції раунду | будь-яка, навіть необоротна | кожен крок має бути оборотним |
| Розшифрування | та сама схема, ключі навпаки | окрема обернена схема |
| Потрібна кількість раундів | більша (16 у DES) | менша (10 у AES-128) |
| Апаратна реалізація | один блок логіки на обидві дії | два різні блоки |
| Представники | DES, Blowfish, ГОСТ | AES, Serpent, PRESENT |

## 6 Конфузія та дифузія

Клод Шеннон (1949) сформулював два принципи стійкого шифру:

**Конфузія** — зв'язок між ключем та шифротекстом має бути складним.
- Досягається S-блоками (нелінійна заміна)
- Зміна одного біта ключа → зміна багатьох бітів шифротексту

**Дифузія** — зміна одного біта відкритого тексту → зміна багатьох бітів шифротексту.
- Досягається перестановками та змішуванням
- "Розмиває" статистичні властивості

```
      Конфузія                    Дифузія
    (Ключ → Шифр)            (Текст → Шифр)

    K: 10110...              P: 10110...
        ↓                        ↓
    Складний                 Один біт змінено
    зв'язок                      ↓
        ↓                    P: 10111...
    C: ?????                     ↓
                             C: повністю інший!
```

## 7 Лавинний ефект

**Лавинний ефект** (Avalanche effect) — зміна одного біта входу повинна змінювати приблизно 50% бітів виходу.

```cpp
// Демонстрація лавинного ефекту.
// Програма збирається разом із реалізацією DES з лабораторної роботи №5:
// звідти беруться des_encrypt і всі таблиці алгоритму.
#include <iostream>
#include <bitset>
#include <cstdint>

uint64_t des_encrypt(uint64_t plaintext, uint64_t key);  // реалізація з ЛР5

int countDifferentBits(uint64_t a, uint64_t b) {
    return static_cast<int>(std::bitset<64>(a ^ b).count());
}

int main() {
    uint64_t key = 0x133457799BBCDFF1ULL;

    uint64_t text1 = 0x4141414141414141ULL;  // блок з літер 'A'
    uint64_t text2 = text1 ^ 1ULL;           // той самий блок, змінено один біт

    uint64_t cipher1 = des_encrypt(text1, key);
    uint64_t cipher2 = des_encrypt(text2, key);

    int diff = countDifferentBits(cipher1, cipher2);
    std::cout << "Різних бітів: " << diff << " з 64 ("
              << (diff * 100.0 / 64) << "%)\n";
    std::cout << "Зміна одного біта входу змінює близько половини бітів виходу\n";

    return 0;
}
```

Результат роботи програми:

```
Різних бітів: 31 з 64 (48.4375%)
Зміна одного біта входу змінює близько половини бітів виходу
```

Один змінений біт відкритого тексту змінив 31 біт шифротексту з 64 — майже
рівно половину. Саме цього й вимагають від блочного шифру: за шифротекстом не
видно, наскільки схожі між собою відповідні відкриті тексти.

**Завдання 2.** Лавинний ефект.

Дослідіть лавинний ефект:
1. Візьміть будь-який текст (16 байт)
2. Зашифруйте його AES
3. Змініть 1 біт тексту
4. Зашифруйте знову
5. Порахуйте % змінених бітів

Для кроків 2 і 4 не обов'язково писати AES самому — досить OpenSSL (є в Git Bash, WSL, Linux і macOS). Літери G і F відрізняються рівно одним бітом:

```bash
printf 'SIXTEEN BYTE MSG' | openssl enc -aes-128-ecb -nopad \
    -K 000102030405060708090a0b0c0d0e0f | xxd -p
printf 'SIXTEEN BYTE MSF' | openssl enc -aes-128-ecb -nopad \
    -K 000102030405060708090a0b0c0d0e0f | xxd -p
```

Режим ECB тут доречний: шифруємо рівно один блок і хочемо побачити саме перетворення блочного шифру.
