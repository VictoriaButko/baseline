## Навіщо потрібна операційна система?

Уявіть, що ви купили новий комп'ютер без операційної системи. У вас є процесор, пам'ять, диск — але що з цим робити? Щоб запустити найпростішу програму, вам довелося б:

1. Написати код, який ініціалізує процесор
2. Налаштувати контролер пам'яті
3. Запрограмувати контролер диска для читання даних
4. Створити власний формат зберігання файлів
5. Написати драйвер для клавіатури та монітора

І це лише для "Hello, World"! Кожна наступна програма вимагала б того самого. А якщо дві програми захочуть працювати одночасно? Хаос.

**Операційна система** вирішує цю проблему, беручи на себе всю "брудну роботу" зі спілкування з обладнанням.

## Визначення операційної системи

**Операційна система (ОС)** — це програмне забезпечення, яке:
1. Керує апаратними ресурсами комп'ютера
2. Надає сервіси для прикладних програм
3. Забезпечує інтерфейс для користувача

```
┌─────────────────────────────────────────────────────────────┐
│                      КОРИСТУВАЧ                             │
│         (вводить команди, запускає програми)                │
└─────────────────────────┬───────────────────────────────────┘
                          │
                          ▼
┌─────────────────────────────────────────────────────────────┐
│                  ПРИКЛАДНІ ПРОГРАМИ                         │
│        (браузер, редактор, ігри, ваш код)                   │
└─────────────────────────┬───────────────────────────────────┘
                          │ Системні виклики (API)
                          ▼
┌─────────────────────────────────────────────────────────────┐
│                  ОПЕРАЦІЙНА СИСТЕМА                         │
│  ┌─────────────┐ ┌─────────────┐ ┌─────────────────────┐    │
│  │  Керування  │ │  Керування  │ │     Файлова         │    │
│  │  процесами  │ │   пам'яттю  │ │     система         │    │
│  └─────────────┘ └─────────────┘ └─────────────────────┘    │
│  ┌─────────────┐ ┌─────────────┐ ┌─────────────────────┐    │
│  │   Драйвери  │ │   Безпека   │ │      Мережа         │    │
│  │  пристроїв  │ │             │ │                     │    │
│  └─────────────┘ └─────────────┘ └─────────────────────┘    │
└─────────────────────────┬───────────────────────────────────┘
                          │
                          ▼
┌─────────────────────────────────────────────────────────────┐
│                 АПАРАТНЕ ЗАБЕЗПЕЧЕННЯ                       │
│      (CPU, RAM, HDD/SSD, мережева карта, GPU...)            │
└─────────────────────────────────────────────────────────────┘
```

## Ключові поняття

### Ядро (Kernel)

**Ядро** — центральна частина ОС, яка завжди знаходиться в оперативній пам'яті та має ексклюзивний доступ до апаратного забезпечення.

Ядро — це єдина програма, якій "дозволено все". Воно може:
- Виконувати будь-які інструкції процесора
- Звертатися до будь-якої ділянки пам'яті
- Безпосередньо керувати пристроями

**Практичний приклад**: Коли ви зберігаєте файл у Word, програма не пише на диск напряму. Вона просить ядро: "Запиши ці байти у файл X". Ядро перевіряє права доступу, знаходить вільне місце на диску, записує дані та оновлює файлову систему.

```bash
# Подивитися версію ядра Linux
uname -r

# Де знаходиться ядро
ls -la /boot/vmlinuz*

# Розмір ядра Linux (~10-15 МБ в стисненому вигляді)
ls -lh /boot/vmlinuz-$(uname -r)
```

### Процес

**Процес** — це екземпляр програми, що виконується. Кожен процес має:
- Унікальний ідентифікатор (PID)
- Власний адресний простір пам'яті
- Стан виконання (виконується, очікує, зупинений)
- Відкриті файли та мережеві з'єднання

```
┌─────────────────────────────────────────┐
│            ПРОЦЕС (PID: 1234)           │
├─────────────────────────────────────────┤
│ високі адреси                           │
│  Стек (stack) — локальні змінні         │
│        ↓ росте до менших адрес          │
│                                         │
│        ↑ росте до більших адрес         │
│  Купа (heap) — пам'ять від malloc       │
│  ──────────────────────────────         │
│  Глобальні змінні (data, bss)           │
│  ──────────────────────────────         │
│  Код програми (text)                    │
│ низькі адреси (адреса 0 не відображена) │
└─────────────────────────────────────────┘
  а ще в ядрі про процес зберігається:
  відкриті файли (0 — stdin, 1 — stdout, 2 — stderr),
  поточний каталог, змінні середовища, власник, права
```

Стек і купа ростуть назустріч одне одному з протилежних кінців адресного простору — так обидва можуть збільшуватися, не знаючи заздалегідь, скільки місця знадобиться кожному. Саму карту можна побачити: `cat /proc/self/maps` показує пам'ять процесу `cat`, що виконує цю команду, з рядками `[heap]` і `[stack]`.

**Практичний приклад**: Відкрийте браузер Chrome. Вкладки різних сайтів, як правило, працюють в окремих процесах. Якщо одна вкладка "зависне", інші продовжують працювати. Це ізоляція процесів в дії.

```bash
# Подивитися всі процеси
ps aux

# Знайти процеси браузера
ps aux | grep -i chrome

# Інтерактивний монітор
htop
```

### Ресурси

**Ресурс** — це будь-який компонент системи, який може використовуватися процесами:

| Ресурс | Приклад | Характеристика |
|--------|---------|----------------|
| Процесор (CPU) | Intel i7, AMD Ryzen | Обмежена кількість ядер |
| Пам'ять (RAM) | 16 ГБ DDR4 | Обмежений обсяг |
| Диск | SSD 512 ГБ | Обмежений простір |
| Мережа | Ethernet, Wi-Fi | Обмежена пропускна здатність |
| Пристрої | Принтер, камера | Часто лише один користувач |

ОС виступає **арбітром ресурсів**: вирішує, який процес отримає ресурс, на який час, у якому порядку.

**Практичний приклад**: Ви запускаєте компіляцію великого проекту та одночасно слухаєте музику. Обидва процеси хочуть CPU. ОС розподіляє час: компілятор отримує більше (бо потребує обчислень), музичний плеєр — менше (бо здебільшого чекає на дані з диска).

### Системний виклик (System Call)

**Системний виклик** — це інтерфейс між прикладною програмою та ядром ОС. Це єдиний легальний спосіб попросити ядро виконати привілейовану операцію.

```
  Прикладна програма
         │
         │  write(fd, buffer, size)
         ▼
  ┌──────────────────┐
  │  Бібліотека C    │  ← glibc, musl
  │  (libc)          │
  └────────┬─────────┘
           │  syscall інструкція
           ▼
  ════════════════════  ← Межа User/Kernel mode
           │
           ▼
  ┌──────────────────┐
  │      ЯДРО        │
  │  sys_write()     │
  └──────────────────┘
```

**Основні категорії системних викликів:**

| Категорія | Приклади | Призначення |
|-----------|----------|-------------|
| Процеси | fork, exec, exit, wait | Створення та керування процесами |
| Файли | open, read, write, close | Робота з файлами |
| Пам'ять | mmap, brk, munmap | Виділення пам'яті |
| Мережа | socket, connect, send, recv | Мережеві операції |
| Пристрої | ioctl, read, write | Керування пристроями |

**Практичний приклад**: Програма хоче прочитати файл `/etc/passwd`:

```c
// Псевдокод того, що відбувається
int fd = open("/etc/passwd", O_RDONLY);  // glibc викличе openat, №257
char buffer[1024];
int bytes = read(fd, buffer, 1024);       // read, №0
close(fd);                                 // close, №3
```

Кожен виклик — це перехід у режим ядра, перевірка прав, виконання операції, повернення в режим користувача. Номери — для x86-64: ядро розрізняє виклики саме за числом у регістрі, а назви існують лише для людей. Старий виклик `open` (№2) досі є, але сучасна бібліотека C замість нього викликає `openat`.

```bash
# Відстежити системні виклики програми
strace ls -la

# Порахувати виклики за типом
strace -c ls -la
```

## П'ять основних функцій ОС

### 1. Керування процесами

ОС відповідає за весь життєвий цикл процесу:

```
    ┌───────┐
    │  New  │ ← Процес створено
    └───┬───┘
        │ admit
        ▼
    ┌───────┐  dispatch   ┌─────────┐   exit   ┌────────────┐
    │ Ready │────────────→│ Running │─────────→│ Terminated │
    └───────┘←────────────└────┬────┘          └────────────┘
        ↑    timeout/preempt   │
        │                      │ I/O request
        │     I/O complete     ▼
        └──────────────────┌─────────┐
                           │ Waiting │
                           └─────────┘
```

Завершитися процес може лише зі стану Running: щоб викликати `exit()`, треба виконуватися. Детально стани розбираємо в модулі 2.

**Задачі керування процесами:**
- Створення нових процесів (fork)
- Завершення процесів (exit, kill)
- Планування — вибір, який процес виконувати
- Синхронізація — координація паралельних процесів
- Комунікація — обмін даними між процесами

**Практичний приклад — веб-сервер:**

```
                    ┌─────────────────┐
                    │  master (root)  │  під час запуску:
                    │  PID 1000       │  читає конфіг, відкриває порт 80
                    └────────┬────────┘
                             │ fork() — один раз, на старті
              ┌──────────────┼──────────────┐
              ▼              ▼              ▼
        ┌──────────┐   ┌──────────┐   ┌──────────┐
        │ Worker 1 │   │ Worker 2 │   │ Worker 3 │  www-data
        │ PID:1001 │   │ PID:1002 │   │ PID:1003 │
        └──────────┘   └──────────┘   └──────────┘
              ▲              ▲              ▲
              └──── HTTP-запити від клієнтів ┘
```

Nginx створює worker-процеси один раз, під час запуску, — зазвичай по одному на ядро процесора. Запити приймають самі воркери, головний процес у їхній обробці не бере участі. Якщо воркер впаде, головний процес запустить новий, а інші тим часом працюють далі.

### 2. Керування пам'яттю

ОС розподіляє оперативну пам'ять між процесами та забезпечує ізоляцію.

**Віртуальна пам'ять** — ключова концепція:

```
   Процес A                     Процес B
   Віртуальна пам'ять           Віртуальна пам'ять
  ┌─────────────┐              ┌─────────────┐
  │ 0x401000    │              │ 0x401000    │
  │ (код)       │              │ (код)       │
  ├─────────────┤              ├─────────────┤
  │ 0x404000    │              │ 0x404000    │
  │ (дані)      │              │ (дані)      │
  └──────┬──────┘              └──────┬──────┘
         │                            │
         │    MMU (трансляція)        │
         ▼                            ▼
  ┌────────────────────────────────────────┐
  │           Фізична пам'ять (RAM)        │
  │  ┌─────┐ ┌─────┐ ┌─────┐ ┌─────┐       │
  │  │ A   │ │ B   │ │ A   │ │ B   │ ...   │
  │  │код  │ │код  │ │дані │ │дані │       │
  │  └─────┘ └─────┘ └─────┘ └─────┘       │
  └────────────────────────────────────────┘
```

Два процеси можуть мати дані за однаковою віртуальною адресою — і не заважати одне одному: ОС відображає ці адреси на різні фізичні сторінки. Сторінку з адресою 0 ядро навмисно не відображає в жоден процес — тому звернення за нульовим вказівником (`NULL`) не читає сміття, а одразу дає `Segmentation fault`.

**Практичний приклад**: Чому ви можете відкрити 50 вкладок Chrome на комп'ютері з 8 ГБ RAM, коли кожна "хоче" 500 МБ? Тому що:
1. Віртуальна пам'ять дозволяє виділяти більше, ніж є фізично
2. Не вся виділена пам'ять використовується одночасно
3. Невикористані сторінки вивантажуються на диск (swap)

```bash
# Подивитися використання пам'яті
free -h

# Топ процесів за пам'яттю
ps aux --sort=-%mem | head -10

# Детальна карта пам'яті процесу
cat /proc/self/maps
```

### 3. Керування файловою системою

ОС організовує зберігання даних у вигляді ієрархії файлів та каталогів.

**Структура файлової системи Linux:**

```
/
├── bin/      ← Базові команди (ls, cp, mv) — нині посилання на usr/bin
├── boot/     ← Ядро та завантажувач
├── dev/      ← Файли пристроїв
├── etc/      ← Конфігураційні файли
├── home/     ← Домашні каталоги користувачів
│   └── user/
├── lib/      ← Бібліотеки
├── proc/     ← Віртуальна ФС (інформація про процеси)
├── sys/      ← Віртуальна ФС (інформація про систему)
├── tmp/      ← Тимчасові файли
├── usr/      ← Програми користувача
│   ├── bin/
│   ├── lib/
│   └── share/
└── var/      ← Змінні дані (логи, бази)
    └── log/
```

На сучасних Ubuntu, Debian і Fedora каталоги `/bin`, `/sbin` і `/lib` — лише символьні посилання на `/usr/bin`, `/usr/sbin` і `/usr/lib`: колись їх розділили, бо система не вміщалася на один диск, а тепер знову злили. Перевірте: `ls -l /` покаже `bin -> usr/bin`.

**Принцип UNIX: "Все є файлом"**

```bash
# Звичайний файл
cat /etc/hostname

# Пристрій (весь диск): sda, nvme0n1 або vda у віртуальній машині
ls -la /dev/sda /dev/nvme0n1 /dev/vda 2>/dev/null

# Процес (інформація про PID 1)
cat /proc/1/cmdline

# Мережева статистика
cat /proc/net/tcp

# Апаратна інформація: MAC-адреси мережевих інтерфейсів
# (імена на кшталт enp0s3 чи wlp2s0 — eth0 на сучасних системах буває рідко)
grep . /sys/class/net/*/address
```

**Практичний приклад**: Як дізнатися температуру CPU без спеціальних програм?

```bash
# Файл у /sys містить температуру в мілі-градусах
cat /sys/class/thermal/thermal_zone0/temp
# Виведе: 45000 (означає 45°C); у віртуальній машині датчика може не бути
```

### 4. Керування пристроями (I/O)

ОС забезпечує уніфікований інтерфейс для роботи з різноманітним обладнанням.

```
  Прикладна програма
         │
         │  write(fd, data, len)
         ▼
  ┌──────────────────────────────────────────────────────────┐
  │                         Ядро ОС                          │
  ├──────────────────────────────────────────────────────────┤
  │                                                          │
  │   VFS  — єдиний інтерфейс: open, read, write, close      │
  │     │                                                    │
  │   ext4 · vfat · NFS            ← файлові системи         │
  │     │                                                    │
  │   блочний рівень · TCP/IP      ← черги, кеш, протоколи   │
  │     │                                                    │
  │   NVMe · usb-storage · e1000   ← драйвери пристроїв      │
  │     │                                                    │
  └──────────────────────────────────────────────────────────┘
        ▼
   SSD · флешка · мережева карта
```

**Драйвер** — це модуль ядра, який "перекладає" універсальні команди ОС на мову конкретного пристрою. Файлова система — не драйвер: ext4 знає, де на диску лежать файли й каталоги, але сам диск не чіпає, а передає запити нижче — блочному рівню й драйверу контролера.

**Практичний приклад**: Як Linux визначає нову USB-флешку?

```
1. Ви вставляєте флешку
2. USB-контролер генерує переривання
3. Драйвер USB-контролера опитує новий пристрій
4. Пристрій повідомляє свій клас — mass storage
5. Ядро підключає драйвер usb-storage і бачить новий диск
6. Ядро створює у /dev (файлова система devtmpfs) файл /dev/sdb
7. Служба udev налаштовує права й додає зручні посилання,
   наприклад /dev/disk/by-label/MYFLASH
8. udisks монтує файлову систему в /media/<користувач>/…
```

Поширене непорозуміння — що файли в `/dev` створює udev. Створює їх саме ядро, а udev лише «доводить до ладу»: вирішує, кому дозволено користуватися пристроєм, і дає йому стабільні імена, які не зміняться, якщо вставити флешки в іншому порядку.

```bash
# Переглянути підключені блочні пристрої
lsblk

# Журнал подій ядра (видно підключення пристроїв)
dmesg | tail -20

# USB-пристрої
lsusb
```

### 5. Забезпечення безпеки та захисту

ОС контролює доступ до ресурсів і захищає користувачів та процеси один від одного.

**Рівні захисту:**

```
┌─────────────────────────────────────────────────┐
│  1. Аутентифікація                              │
│     Хто ти? (логін/пароль, біометрія)           │
├─────────────────────────────────────────────────┤
│  2. Авторизація                                 │
│     Що тобі дозволено? (права, ролі)            │
├─────────────────────────────────────────────────┤
│  3. Ізоляція процесів                           │
│     Процеси не бачать пам'ять один одного       │
├─────────────────────────────────────────────────┤
│  4. Контроль доступу до файлів                  │
│     rwx права для user/group/others             │
├─────────────────────────────────────────────────┤
│  5. Аудит                                       │
│     Журналювання подій для аналізу              │
└─────────────────────────────────────────────────┘
```

**Права доступу в Linux:**

```
-rwxr-xr-x 1 user group 4096 Jan 15 10:30 script.sh
│└┬┘└┬┘└┬┘
│ │  │  └── others: read + execute
│ │  └───── group: read + execute
│ └──────── owner: read + write + execute
└────────── тип файлу (- = звичайний файл)
```

**Практичний приклад**: Чому звичайний користувач не може видалити системні файли?

```bash
# Спроба видалити системний файл
rm /usr/bin/ls
# rm: remove write-protected regular file '/usr/bin/ls'? y
# rm: cannot remove '/usr/bin/ls': Permission denied

# Права самого файлу
ls -l /usr/bin/ls
# -rwxr-xr-x 1 root root 142312 Apr  5  2024 /usr/bin/ls

# Права каталогу, у якому він лежить
ls -ld /usr/bin
# drwxr-xr-x 2 root root 69632 Sep 12 10:40 /usr/bin
```

Вирішальні тут права **каталогу**, а не файлу. Видалити файл — означає змінити каталог: викреслити з нього запис з іменем. Тому потрібне право запису в каталог, а воно в `/usr/bin` є лише в root. Звідси несподіваний наслідок: з власного каталогу можна видалити навіть чужий файл, доступний лише для читання, — `rm` тільки перепитає. Щоб таке не траплялося в спільних каталогах на кшталт `/tmp`, на них ставлять «липкий біт» `t`: `ls -ld /tmp` покаже `drwxrwxrwt`.

## Два погляди на ОС

### ОС як "розширена машина" (Extended Machine)

Для програміста ОС — це набір зручних абстракцій:

| Реальність | Абстракція ОС |
|------------|---------------|
| Сектори диска, контролери | Файли та каталоги |
| Фізичні адреси пам'яті | Віртуальний адресний простір |
| Переривання, порти I/O | Системні виклики |
| Різні моделі принтерів | Єдиний інтерфейс друку |

### ОС як "менеджер ресурсів" (Resource Manager)

Для системи ОС — це арбітр, який розподіляє ресурси:

```
        Процес A ────┐
                     │
        Процес B ────┼────→ [ ОС ] ────→ CPU (4 ядра)
                     │         │
        Процес C ────┘         ├────→ RAM (16 ГБ)
                               │
                               └────→ Диск, мережа...
```

ОС вирішує:
- **Хто** отримає ресурс
- **Скільки** (квота, ліміт)
- **Коли** (планування)
- **Як** вирішувати конфлікти (блокування, черги)


## 🎯 Міні-проект (30 хв)

### Завдання: Детектив системних викликів

Станьте "детективом" операційної системи — дослідіть, які системні виклики роблять різні програми, та створіть порівняльний звіт.

**Кроки:**

1. Порівняйте системні виклики простих команд (якщо `strace` немає: `sudo apt install strace`):
```bash
# Створіть директорію для дослідження
mkdir ~/syscall-detective && cd ~/syscall-detective

# Порівняйте ls vs cat vs echo
strace -c ls 2>&1 | tail -20 > ls_syscalls.txt
strace -c cat /etc/hostname 2>&1 | tail -20 > cat_syscalls.txt
strace -c echo "test" 2>&1 | tail -20 > echo_syscalls.txt
```

2. Дослідіть, які syscalls найчастіші для кожної команди:
```bash
# Виведіть топ-3 syscalls для кожної команди
echo "=== Топ syscalls для ls ===" > report.txt
head -5 ls_syscalls.txt >> report.txt
echo "" >> report.txt

echo "=== Топ syscalls для cat ===" >> report.txt
head -5 cat_syscalls.txt >> report.txt
echo "" >> report.txt

echo "=== Топ syscalls для echo ===" >> report.txt
head -5 echo_syscalls.txt >> report.txt
```

3. Знайдіть найбільшого "споживача" ресурсів:
```bash
# Знайдіть топ-5 процесів за CPU та RAM
echo "=== Топ процеси ===" >> report.txt
echo "По CPU:" >> report.txt
ps aux --sort=-%cpu | head -6 >> report.txt
echo "" >> report.txt
echo "По RAM:" >> report.txt
ps aux --sort=-%mem | head -6 >> report.txt
```

4. Дослідіть реальний syscall в деталях:
```bash
# Подивіться, що саме робить команда при відкритті файлу
strace -e open,openat cat /etc/passwd 2>&1 | head -10
```

5. Перегляньте ваш звіт:
```bash
cat report.txt
```

**Очікуваний результат:**
Директорія `~/syscall-detective` з файлами аналізу системних викликів та звітом `report.txt`, який показує різницю між командами.

**Бонус (для допитливих):**
- Порівняйте syscalls браузера vs текстового редактора (`sudo strace -c -p PID` для вже запущеного процесу — без `sudo` Ubuntu не дозволить підключитися до чужого процесу, навіть власного: так налаштований захист `ptrace_scope`)
- Знайдіть, яка програма робить найбільше `write()` викликів
- Візуалізуйте результати у вигляді простої таблиці

## Тест для самоперевірки

Десять запитань, у кожному одна правильна відповідь. Якщо тема винесена вашій групі на самостійне опрацювання, цей самий тест публікується в Google Classroom — 10 балів, по одному за кожне запитання.

**1.** Що таке ресурс із погляду операційної системи?

- будь-який файл користувача
- вільне місце на системному розділі
- процесор, пам'ять, диск, мережа — те, за що конкурують процеси
- програма, встановлена в системі

**2.** Що входить у поняття процесу?

- програма разом із виділеною пам'яттю, станом і номером PID
- лише виконуваний файл на диску
- запис у таблиці файлової системи
- ділянка оперативної пам'яті без прив'язки до програми

**3.** Яку роль виконує драйвер?

- розподіляє процесорний час між процесами
- перекладає звернення ОС у команди конкретного пристрою
- зберігає налаштування користувача
- перевіряє права доступу до файлів

**4.** Що означає погляд на ОС як на «розширену машину»?

- ОС розподіляє обмежені ресурси між процесами
- ОС збільшує обсяг доступної пам'яті
- ОС додає процесору нові інструкції
- ОС ховає складність заліза за зручним і однаковим інтерфейсом

**5.** Що означає погляд на ОС як на «менеджера ресурсів»?

- ОС приховує від програміста роботу з портами пристроїв
- ОС розподіляє обмежені ресурси між процесами, які за них конкурують
- ОС стежить за температурою процесора
- ОС встановлює й оновлює прикладні програми

**6.** Яка утиліта покаже системні виклики, що їх робить програма?

- strace
- lsblk
- uname
- htop

**7.** До якої функції ОС належать сторінкова організація пам'яті та MMU?

- керування пам'яттю
- керування пристроями
- керування процесами
- забезпечення безпеки

**8.** До якої функції ОС належать VFS та inode?

- керування процесами
- керування файловою системою
- керування пам'яттю
- керування пристроями

**9.** До якої функції ОС належать права rwx і SELinux?

- керування пристроями
- керування процесами
- керування файловою системою
- забезпечення безпеки та захисту

**10.** Чому прикладна програма не може звернутися до диска напряму?

- прикладні мови програмування не мають таких функцій
- це заборонено ліцензією операційної системи
- диск завжди зайнятий іншими процесами
- доступ до заліза дозволений лише ядру, тому програма звертається через системний виклик
