## Чому операційні системи — це база

Операційні системи оточують нас повсюди, навіть там, де ми їх не помічаємо:

- **PlayStation 4 і 5** працюють на системі, похідній від FreeBSD
- **Nintendo Switch** — на власній мікроядерній ОС Horizon; з FreeBSD там запозичено лише окремі частини, зокрема мережевий стек
- **Бортові комп'ютери Tesla** працюють під Linux
- **Android** — це ядро Linux з надбудовою для мобільних пристроїв (понад 3 млрд активних пристроїв)
- **macOS та iOS** — нащадки UNIX через NeXTSTEP; macOS навіть має офіційний сертифікат UNIX 03, якого немає в Linux
- **Близько 90% сайтів**, чию ОС удається визначити, працюють на Unix-подібних системах, і щонайменше дві третини з них — достовірно Linux (W3Techs, 2026)
- **Усі 500 суперкомп'ютерів** зі списку TOP500 працюють на Linux — так щороку з листопада 2017
- **SpaceX Dragon** — космічний корабель на Linux
- **Більшість банкоматів** — на Windows

Навіть смартфон, розумний годинник, роутер, холодильник, автомобіль — усе працює під керуванням операційної системи.

## Що таке операційна система

**Операційна система (ОС)** — це комплекс програм, що керує апаратним забезпеченням комп'ютера та надає сервіси для прикладних програм.

### Аналогія: ОС як менеджер готелю

Уявіть ОС як **менеджера готелю**:

- **Гості (програми)** хочуть користуватися кімнатами (пам'ять), рестораном (процесор), басейном (диск), Wi-Fi (мережа)
- **Менеджер (ОС)** розподіляє ресурси, щоб усім вистачило
- Гості не знають один про одного і **не можуть зайти в чужу кімнату** (ізоляція)
- Менеджер вирішує конфлікти та забезпечує порядок (арбітраж)
- VIP-гості (системні процеси) мають пріоритет

```
┌────────────────────────────────────────────────────────────────┐
│                    ОС ЯК МЕНЕДЖЕР ГОТЕЛЮ                       │
│                                                                │
│   Готель (Комп'ютер)                                           │
│   ┌───────────────────────────────────────────────────────┐    │
│   │                                                       │    │
│   │   Кімнати (RAM)    Ресторан (CPU)    Басейн (Disk)    │    │
│   │   ┌───┐ ┌───┐      ┌─────────┐       ┌─────────┐      │    │
│   │   │ A │ │ B │      │ столики │       │ доріжки │      │    │
│   │   └───┘ └───┘      └─────────┘       └─────────┘      │    │
│   │         │                │                 │          │    │
│   │         └────────────────┴─────────────────┘          │    │
│   │                          │                            │    │
│   │                    ┌─────▼─────┐                      │    │
│   │                    │ Менеджер  │ ← ОС                 │    │
│   │                    │ (Ядро)    │                      │    │
│   │                    └───────────┘                      │    │
│   └───────────────────────────────────────────────────────┘    │
│                                                                │
│   Менеджер:                                                    │
│   • Реєструє гостей (створює процеси)                          │
│   • Видає ключі (виділяє пам'ять)                              │
│   • Бронює столики (планує CPU)                                │
│   • Не пускає в чужі кімнати (ізоляція)                        │
└────────────────────────────────────────────────────────────────┘
```

### Дві ключові ролі ОС

**1. Абстракція** — приховує складність апаратного забезпечення

Замість коду для кожної моделі диска (SSD Samsung, HDD Western Digital, NVMe Intel), ви просто відкриваєте файл — ОС подбає про решту.

```
Без ОС:                          З ОС:
─────────                        ─────
if (disk_model == "Samsung") {   open("file.txt")
    samsung_read_sector(...)     // ОС сама визначить
} else if (disk_model == "WD") { // який диск і як читати
    wd_read_sector(...)
}
```

**2. Арбітраж** — розподіляє обмежені ресурси

Коли 50 програм хочуть процесор одночасно, ОС вирішує, хто отримає час. Коли двоє хочуть писати в один файл — ОС координує доступ.

## Базові поняття

### Ядро (Kernel)

**Ядро** — серце ОС, програма, яка **завжди** працює в пам'яті та має повний доступ до апаратного забезпечення.

Коли ви "встановлюєте Linux", ви фактично встановлюєте:

| Компонент | Опис |
|-----------|------|
| **Ядро Linux** | Файл `/boot/vmlinuz-…` (10–15 МБ у стисненому вигляді) плюс тисячі модулів у `/lib/modules/` — драйвери, з яких завантажується лише потрібне |
| **Системні утиліти GNU** | `ls`, `cp`, `cat`, `grep`, `bash` |
| **Init-система** | systemd, OpenRC |
| **Графічне середовище** | GNOME, KDE (опціонально) |
| **Пакетний менеджер** | apt, dnf, pacman |

Технічно "Linux" — це лише ядро, а повну систему з утилітами GNU називають GNU/Linux. Утім, GNU не обов'язковий: Android і Alpine Linux працюють на тому самому ядрі зовсім без утиліт GNU — там свої бібліотеки й свій набір команд.

### Процес

**Процес** — програма, що виконується. Програма — файл на диску. Процес — активна сутність в пам'яті.

```
┌────────────────────────────────────────────────────────────────┐
│                       ПРОГРАМА vs ПРОЦЕС                       │
├────────────────────────────────────────────────────────────────┤
│                                                                │
│   Програма (файл)              Процес (виконання)              │
│   ────────────────             ───────────────────             │
│   /usr/bin/bash                PID 1234                        │
│   • Статична                   • Динамічний                    │
│   • На диску                   • В пам'яті                     │
│   • Один файл                  • Може бути багато екземплярів  │
│                                                                │
│   Одна програма → багато процесів:                             │
│   три відкриті термінали — три процеси bash з одного файлу     │
└────────────────────────────────────────────────────────────────┘
```

Коли ви запускаєте браузер:

1. ОС створює процес з унікальним **PID** (Process ID)
2. Виділяє **пам'ять** для коду та даних
3. Завантажує код з диска
4. Додає в **чергу планувальника**
5. Процес починає виконуватися

```bash
# Подивитися всі процеси
ps aux

# Порахувати кількість процесів
ps aux | wc -l
# Типова система: 200-400 процесів

# Знайти конкретний процес
ps aux | grep firefox

# Дерево процесів
pstree
```

### Системний виклик (System Call)

**Системний виклик** — спосіб, яким програма просить ОС виконати привілейовану операцію.

**Аналогія: замовлення в ресторані**
- Ви не йдете на кухню самі — робите замовлення через офіціанта
- Офіціант (syscall) передає його кухарю (ядру)
- Кухар готує і повертає страву

```
┌────────────────────────────────────────────────────────────────┐
│                        СИСТЕМНИЙ ВИКЛИК                        │
├────────────────────────────────────────────────────────────────┤
│                                                                │
│   Програма                                                     │
│      │                                                         │
│      │ open("file.txt")  ← виклик функції бібліотеки           │
│      │                                                         │
│      ▼                                                         │
│   Бібліотека (libc)                                            │
│      │                                                         │
│      │ syscall(SYS_openat, ...)  ← інструкція переходу в ядро  │
│      │                                                         │
│   ───┼─────────────────── User Mode / Kernel Mode ───────      │
│      │                                                         │
│      ▼                                                         │
│   Ядро                                                         │
│      │                                                         │
│      └── Перевіряє права → відкриває файл → повертає           │
│          дескриптор: невелике число, наприклад 3               │
└────────────────────────────────────────────────────────────────┘
```

Приклади системних викликів:

| Syscall | Призначення |
|---------|-------------|
| `open()` | Відкрити файл |
| `read()` / `write()` | Читати / писати дані |
| `fork()` | Створити новий процес |
| `execve()` | Запустити програму |
| `socket()` | Працювати з мережею |
| `mmap()` | Відобразити файл в пам'ять |

Системних викликів у Linux кілька сотень; повний перелік — у `man 2 syscalls`. Найцікавіше, що їх можна побачити наживо. Утиліта `strace` показує кожен виклик, який програма робить до ядра:

```bash
strace -e trace=openat,read,write,close cat /etc/hostname
```

```
...
openat(AT_FDCWD, "/etc/hostname", O_RDONLY) = 3
read(3, "my-laptop\n", 131072)          = 10
write(1, "my-laptop\n", 10)             = 10
read(3, "", 131072)                     = 0
close(3)                                = 0
```

Перед цим фрагментом `cat` ще відкриває бібліотеки, тож рядків у вас буде більше. Ось і вся «магія» `cat`: відкрити файл, читати, доки `read` не поверне 0, і писати прочитане в дескриптор 1. Файлу дісталося число 3, бо 0, 1 і 2 від народження зайняті: це стандартні введення, виведення і потік помилок. Бібліотечна функція `open()` насправді викликає `openat` — тому шукати в `strace` треба саме його.

## Карта курсу: що розберемо далі

Кожне з цих понять має окрему лекцію, тут — лише суть, щоб бачити картину цілком.

| Тема | Суть | Детально |
|------|------|----------|
| **Функції ОС** | П'ять напрямів: керування процесами, пам'яттю, файловою системою, пристроями й безпекою. Команда `free -h`, наприклад, показує роботу керування пам'яттю | лекція 2 |
| **Вимоги до ОС** | Надійність, безпека, ефективність, масштабованість, портативність — і вони суперечать одна одній | лекція 3 |
| **Еволюція ОС** | Від пакетної обробки через розподіл часу, ПК і смартфони до контейнерів | лекція 4 |
| **Режими процесора** | Програма працює в режимі користувача без прямого доступу до заліза, ядро — в режимі ядра. Перейти з одного в інший можна лише через системний виклик — тому пряме звернення програми до диска процесор просто заблокує | лекція 5 |
| **Архітектура ядра** | Монолітне ядро (Linux, FreeBSD) — усі служби в режимі ядра. Мікроядро (QNX, MINIX) — у режимі ядра мінімум, решта служб працює як звичайні процеси. Гібридне (Windows NT, macOS XNU) — проміжний варіант | лекція 6 |

## Коротка історія

### 1969: UNIX (Bell Labs)

**Кен Томпсон** і **Денніс Рітчі** створили систему, що заклала фундамент:

- Ієрархічна файлова система з коренем `/`
- Командний інтерпретатор (shell), що сам є звичайною програмою
- Принцип «все є файлом»: і файл на диску, і термінал читаються тим самим `read()`
- Конвеєри `|` (з 1973 року): маленькі програми, з'єднані в ланцюжок, виконують велику роботу
- З 1973 року — мова C, яку Рітчі розробив саме для UNIX: ядро переписали нею, і систему вперше вдалося перенести на інший тип комп'ютера

> «UNIX is basically a simple operating system, but you have to be a genius to understand the simplicity.»
>
> — Dennis Ritchie

### 1991: Linux (Linus Torvalds)

21-річний студент з Фінляндії опублікував:

> *"I'm doing a (free) operating system (just a hobby, won't be big and professional like gnu)..."*

Сьогодні Linux — найпоширеніша ОС: сервери, смартфони, суперкомп'ютери, космічні апарати, автомобілі.

## Перше знайомство з CLI

Командний рядок — потужний інструмент. Чому CLI?

- **Швидкість** — досвідчений користувач працює швидше за миші
- **Автоматизація** — команди можна об'єднувати в скрипти
- **Віддалений доступ** — SSH з будь-якої точки світу
- **Точність** — команда робить саме те, що написано
- **Документованість** — скрипт = документація

```bash
# Базові команди для знайомства
whoami         # Хто я?
pwd            # Де я? (Print Working Directory)
ls -la         # Що тут є?
date           # Дата і час
uptime         # Час роботи системи
ps aux | wc -l # Кількість процесів
uname -a       # Інформація про систему
cat /etc/os-release  # Інформація про дистрибутив
```

**Демонстрація htop**: `F5` — дерево процесів, `F9` — kill, `q` — вихід.

## 🎯 Міні-проект (30 хв)

### Завдання: Створення "паспорта" вашої операційної системи

Створіть текстовий файл з повною інформацією про вашу ОС — це буде ваш перший системний звіт, який можна зберегти для порівняння в майбутньому.

Команди нижче — для Linux. Якщо на вашому комп'ютері Windows, найпростіше встановити WSL (у PowerShell від адміністратора: `wsl --install`, далі перезавантаження) — отримаєте справжній Ubuntu в окремому вікні. Без встановлення підійде JSLinux у браузері.

**Кроки:**

1. Створіть файл `os-passport.txt` для збереження результатів:
```bash
# Створіть заголовок файлу
echo "=== ПАСПОРТ ОПЕРАЦІЙНОЇ СИСТЕМИ ===" > ~/os-passport.txt
echo "Дата створення: $(date)" >> ~/os-passport.txt
echo "" >> ~/os-passport.txt
```

2. Зберіть базову інформацію про систему:
```bash
echo "--- Інформація про ОС ---" >> ~/os-passport.txt
uname -a >> ~/os-passport.txt
cat /etc/os-release >> ~/os-passport.txt 2>/dev/null
echo "" >> ~/os-passport.txt
```

3. Додайте інформацію про ресурси:
```bash
echo "--- Ресурси системи ---" >> ~/os-passport.txt
echo "Процесор:" >> ~/os-passport.txt
cat /proc/cpuinfo | grep "model name" | head -1 >> ~/os-passport.txt
echo "Пам'ять:" >> ~/os-passport.txt
free -h >> ~/os-passport.txt
echo "Диски:" >> ~/os-passport.txt
df -h >> ~/os-passport.txt
echo "" >> ~/os-passport.txt
```

4. Зберіть статистику процесів:
```bash
echo "--- Статистика процесів ---" >> ~/os-passport.txt
echo "Кількість процесів: $(ps aux | wc -l)" >> ~/os-passport.txt
echo "Топ-5 по пам'яті:" >> ~/os-passport.txt
ps aux --sort=-%mem | head -6 >> ~/os-passport.txt
echo "" >> ~/os-passport.txt
```

5. Перегляньте результат:
```bash
cat ~/os-passport.txt
```

**Очікуваний результат:**
Файл `os-passport.txt` у вашій домашній директорії з повною інформацією про вашу ОС: назва, версія ядра, процесор, пам'ять, диски та топ процесів.

**Бонус (для допитливих):**
- Додайте до паспорта інформацію про мережеві інтерфейси (`ip addr` або `ifconfig`)
- Додайте список завантажених модулів ядра (`lsmod | wc -l`)
- Порівняйте паспорти з колегами — чиї системи схожі?

## Тест для самоперевірки

Десять запитань, у кожному одна правильна відповідь. Якщо тема винесена вашій групі на самостійне опрацювання, цей самий тест публікується в Google Classroom — 10 балів, по одному за кожне запитання.

**1.** Чим процес відрізняється від програми?

- програма — це процес, завантажений у пам'ять
- відмінності немає, це синоніми
- процес — це програма, що виконується: код разом із пам'яттю, станом і номером PID
- процес — це файл програми, записаний на диску

**2.** Навіщо потрібен режим користувача, якщо в режимі ядра можливостей більше?

- щоб програми працювали швидше
- щоб економити оперативну пам'ять
- щоб підтримувати графічний інтерфейс
- щоб помилка або зловмисний код програми не дістали прямого доступу до заліза

**3.** Яку архітектуру ядра має Linux?

- монолітну
- мікроядро
- екзоядро
- гібридну

**4.** Яку архітектуру ядра мають Windows NT і macOS?

- вони не мають ядра
- монолітну
- мікроядро
- гібридну

**5.** Що станеться, якщо процес спробує звернутися до диска напряму, без системного виклику?

- операцію буде заблоковано: у режимі користувача прямий доступ до заліза заборонений
- ядро автоматично перетворить її на системний виклик
- операція виконається, але повільніше
- диск поверне дані без перевірки прав

**6.** Що таке системний виклик?

- виклик функції зі стандартної бібліотеки мови
- запит програми до ядра на операцію, яку вона не може виконати сама
- сигнал від пристрою до процесора
- команда, введена в оболонці

**7.** Яка команда покаже перелік процесів системи?

- lsblk
- df -h
- free -h
- ps aux

**8.** До якої функції ОС належить команда `free`?

- керування пам'яттю
- керування файловою системою
- забезпечення безпеки
- керування процесами

**9.** Який порядок появи систем правильний?

- MS-DOS (1981) → UNIX (1969) → Linux (1991)
- Linux (1991) → UNIX (1969) → MS-DOS (1981)
- UNIX (1969) → MS-DOS (1981) → Linux (1991)
- UNIX (1969) → Linux (1991) → MS-DOS (1981)

**10.** Чим мікроядро відрізняється від монолітного ядра?

- воно не підтримує драйвери пристроїв
- у режимі ядра лишається мінімум, решта служб працює в режимі користувача
- воно займає менше місця на диску
- воно працює лише на процесорах ARM

## Підсумок

| Термін | Визначення |
|--------|------------|
| **Ядро (Kernel)** | Серце ОС, повний доступ до заліза |
| **Процес (Process)** | Програма, що виконується |
| **Системний виклик (Syscall)** | Запит програми до ядра |
| **User Mode** | Режим звичайних програм (обмежений) |
| **Kernel Mode** | Режим ядра (повний доступ) |
| **Віртуальна пам'ять** | Абстракція для ізоляції процесів |
| **Планувальник (Scheduler)** | Вирішує який процес виконувати |

| Функція ОС | Приклад |
|------------|---------|
| Керування процесами | `ps`, `kill`, `htop` |
| Керування пам'яттю | `free`, `/proc/meminfo` |
| Файлова система | `ls`, `cp`, `df` |
| Керування пристроями | `lsblk`, `lsusb`, `lspci` |
| Безпека | `chmod`, `chown`, `id` |

На наступних лекціях — детально про функції ОС, вимоги та еволюцію операційних систем.
