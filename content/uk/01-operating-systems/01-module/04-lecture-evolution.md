## Від перфокарт до хмар: як еволюціонували ОС

Перші комп'ютери взагалі не мали операційних систем. Програміст особисто заходив до машинного залу, налаштовував машину під свою задачу, чекав результат і забирав роздруківку. Один користувач — одна програма — одна машина.

Сьогодні ваш смартфон одночасно:
- Відтворює музику
- Завантажує повідомлення
- Відстежує GPS-координати
- Оновлює 50+ додатків у фоні
- Відповідає на дотики за 16 мілісекунд

Як ми дійшли від перфокарт до цього? Через вісімдесят років еволюції операційних систем — від ENIAC (1945) до сьогодні.

### Покоління 1 (1945–1955): Без операційних систем

**Характеристика:** Програміст = оператор = користувач

```
┌─────────────────────────────────────────────────────────────────┐
│                    ENIAC, UNIVAC (1945-1955)                    │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│    Програміст                    Комп'ютер                      │
│    ┌───────┐                     ┌──────────────────┐           │
│    │       │ ──кабелі, ───────▶  │ ░░░░░░░░░░░░░░░░ │           │
│    │       │   перемикачі        │ ░░░ ENIAC ░░░░░░ │           │
│    │       │ ◀──роздруківка───   │ ░░░ 27 тонн ░░░░ │           │
│    └───────┘                     │ ░ 17 468 ламп ░░ │           │
│                                  └──────────────────┘           │
│                                                                 │
│    Очікування результату: години або дні                        │
│    Нова задача: кілька днів перекомутації                       │
└─────────────────────────────────────────────────────────────────┘
```

ENIAC не мав навіть поняття «програма в пам'яті»: щоб розв'язати нову задачу, його фізично перемикали — переставляли кабелі та сотні перемикачів. Цю роботу виконували шість жінок-математикинь — Кетлін Макналті, Джин Дженнінгс, Бетті Снайдер, Марлін Веськофф, Френсіс Біляс і Рут Ліхтерман, — фактично перші програмісти в історії. Перфокарти ENIAC використовував лише для введення даних. Ідея зберігати програму в пам'яті поруч із даними — архітектура фон Неймана — втілилася в наступних машинах, і саме вона зробила можливою операційну систему: програму, що завантажує інші програми.

**Проблеми:**
- Комп'ютер коштував мільйони, а простоював 90% часу
- Програміст витрачав години на підготовку, а обчислення тривали хвилини
- Помилка в перфокарті = повторення всього процесу

### Покоління 2 (1955–1965): Пакетна обробка (Batch Processing)

**Ключова ідея:** Оператор збирає завдання у "пакет" і запускає їх послідовно.

**Монітор** (monitor) — так називали резидентну програму, що автоматично завантажувала наступне завдання з пакета. Першою такою системою вважають GM-NAA I/O (1956), створену в General Motors і North American Aviation для IBM 704.

```
┌─────────────────────────────────────────────────────────────────┐
│                    ПАКЕТНА ОБРОБКА (1955-1965)                  │
│                                                                 │
│  Програмісти здають завдання              Оператор              │
│                                                                 │
│  ┌───┐ ┌───┐ ┌───┐                       ┌──────────┐           │
│  │Job│ │Job│ │Job│  ──────────────────▶  │ Оператор │           │
│  │ 1 │ │ 2 │ │ 3 │                       │    👤    │           │
│  └───┘ └───┘ └───┘                       └────┬─────┘           │
│                                               │                 │
│                                               ▼                 │
│                                    ┌─────────────────────┐      │
│                                    │   Мейнфрейм IBM     │      │
│                                    │                     │      │
│                                    │  Job1 ▶ Job2 ▶ Job3 │      │
│                                    │      (послідовно)   │      │
│                                    └─────────────────────┘      │
│                                               │                 │
│                                               ▼                 │
│                                    Результати через години      │
└─────────────────────────────────────────────────────────────────┘
```

**Приклади систем:**
- FMS (Fortran Monitor System)
- IBSYS для IBM 7090/7094

**Переваги:**
- Комп'ютер працює безперервно (менше простоїв)
- Стандартизований процес запуску програм

**Недоліки:**
- Повільний зворотний зв'язок (результат через години/дні)
- CPU простоює під час вводу/виводу

### Покоління 3 (1965–1980): Мультипрограмування та Time-sharing

**Революційна ідея:** Поки одна програма чекає на диск — CPU виконує іншу!

```
┌─────────────────────────────────────────────────────────────────┐
│                    МУЛЬТИПРОГРАМУВАННЯ                          │
│                                                                 │
│   Без мультипрограмування:             З мультипрограмуванням:  │
│                                                                 │
│   CPU  ████░░░░░░░░████░░░░░░░░        ████████████████████     │
│   I/O  ░░░░████████░░░░████████        ░░░░████░░░░████░░░░     │
│                                                                 │
│        Job1    I/O   Job1   I/O        Job1 Job2 Job1 Job2      │
│                                                                 │
│   Використання CPU: ~30%               Використання CPU: ~90%   │
└─────────────────────────────────────────────────────────────────┘
```

**Time-sharing (розподіл часу):**

Кілька користувачів працюють з одним комп'ютером одночасно через термінали.

```
┌─────────────────────────────────────────────────────────────────┐
│                        TIME-SHARING                             │
│                                                                 │
│     Термінали користувачів                                      │
│                                                                 │
│     ┌─────┐  ┌─────┐  ┌─────┐  ┌─────┐                          │
│     │ T1  │  │ T2  │  │ T3  │  │ T4  │                          │
│     │ 👤  │  │ 👤  │  │ 👤  │  │ 👤  │                          │
│     └──┬──┘  └──┬──┘  └──┬──┘  └──┬──┘                          │
│        │        │        │        │                             │
│        └────────┴────────┴────────┘                             │
│                    │                                            │
│                    ▼                                            │
│     ┌────────────────────────────────────────┐                  │
│     │            МЕЙНФРЕЙМ                   │                  │
│     │  ┌─────┬─────┬─────┬─────┬─────┐       │                  │
│     │  │ U1  │ U2  │ U3  │ U4  │ U1  │ ...   │                  │
│     │  │20ms │20ms │20ms │20ms │20ms │       │                  │
│     │  └─────┴─────┴─────┴─────┴─────┘       │                  │
│     │     Швидке перемикання (time slice)    │                  │
│     └────────────────────────────────────────┘                  │
│                                                                 │
│     Кожен користувач "думає", що має весь комп'ютер             │
└─────────────────────────────────────────────────────────────────┘
```

**Революційні системи цієї ери:**

| Рік | Система | Значення |
|-----|---------|----------|
| 1961 | CTSS (MIT) | Перша система розподілу часу: кілька користувачів одночасно за терміналами |
| 1964 | IBM OS/360 | Одна ОС для цілої лінійки машин і мультипрограмування в промислових масштабах; досвід її розробки лягав у книжку Брукса «Міфічний людино-місяць» |
| 1965 | Multics | Проєкт time-sharing із захистом пам'яті; система запрацювала 1969 |
| 1968 | THE (Дейкстра) | Шарувата архітектура: кожен рівень системи користується лише нижчим |
| 1969 | **UNIX** | Народження всіх сучасних ОС |
| 1973 | UNIX мовою C | Портативність — ОС можна перенести на іншу машину |

UNIX виріс з Multics буквально: коли 1969 року Bell Labs вийшла з надто амбітного проєкту, Кен Томпсон і Денніс Рітчі взялися зробити «щось простіше» на старому міні-комп'ютері PDP-7. Сама назва — гра слів: Multics («багато»), Unics («одне»).

**UNIX — поворотний момент:**

```

│                    РОДОВЕ ДЕРЕВО UNIX (1969)                   │
│                                                                │

│                       (Bell Labs, 1969)                        │
│                            │                                   │
│              ┌─────────────┼─────────────┐                     │
│              │             │             │                     │

│          (1977)         (AT&T)       (Microsoft)               │

│    │         │       │     │                                   │
│    ▼         ▼       ▼     ▼                                   │
│ FreeBSD   NetBSD   macOS  Solaris                              │
│ OpenBSD           (через NeXT)                                 │
│    │                                                           │
│    └───────────────────────┐                                   │

│              │  але UNIX-подібна система       │               │
│              │                                 │               │
```

Спільна для всієї родини ідея — **філософія UNIX**, яку Дуґ Макілрой, винахідник конвеєрів, сформулював так:

> «Пишіть програми, які роблять одну річ і роблять її добре. Пишіть програми, що працюють разом. Пишіть програми, що обробляють текстові потоки, бо це універсальний інтерфейс.»

Саме тому в Linux `ls | grep log | wc -l` складається з трьох крихітних програм, а не з однієї великої.

### Покоління 4 (1980–2000): Персональні комп'ютери та GUI

**Зміна парадигми:** Один комп'ютер — один користувач.

```
┌─────────────────────────────────────────────────────────────────┐
│                   ЕРА ПЕРСОНАЛЬНИХ КОМП'ЮТЕРІВ                  │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│   1981: IBM PC + MS-DOS              1984: Apple Macintosh      │
│   ┌─────────────────────┐            ┌─────────────────────┐    │
│   │ C:\> dir            │            │ File  Edit  View    │    │
│   │ C:\> copy a.txt b.tx│            │  ┌──────┐ ┌──────┐  │    │
│   │ C:\> _              │            │  │ Docs │ │ Trash│  │    │
│   │                     │            │  └──────┘ └──────┘  │    │
│   │  Командний рядок    │            │ Графічний інтерфейс │    │
│   └─────────────────────┘            └─────────────────────┘    │
│                                                                 │
│   1985: Windows 1.0     1991: Linux      1995: Windows 95       │
│   GUI для DOS           Open Source      Масовий успіх GUI      │
└─────────────────────────────────────────────────────────────────┘
```

**Ключові події:**

| Рік | Подія | Значення |
|-----|-------|----------|
| 1973 | Xerox Alto | Вікна, іконки й миша — у дослідницькій лабораторії Xerox PARC |
| 1981 | IBM PC + MS-DOS | Стандартизація апаратури |
| 1984 | Macintosh | GUI для масового користувача |
| 1985 | Windows 1.0 | Microsoft входить у GUI |
| 1991 | **Linux 0.01** | Початок революції Open Source |
| 1995 | Windows 95 | "Start" меню, 32-біт, Plug & Play |

Дві історії цієї епохи люблять переказувати. MS-DOS Microsoft не писала: 1981 року компанія купила в Seattle Computer Products систему 86-DOS (робоча назва — QDOS, «швидка і брудна ОС») приблизно за 75 тисяч доларів і вже потім продала IBM ліцензію. А графічний інтерфейс Apple не вигадала: 1979 року Стів Джобс побачив Xerox Alto і повернувся з ідеєю, яка стала Macintosh.

**Народження Linux:**

```bash
# Повідомлення Лінуса Торвальдса, 25 серпня 1991:
# comp.os.minix newsgroup

"Hello everybody out there using minix -
I'm doing a (free) operating system (just a hobby, won't be big and
professional like gnu) for 386(486) AT clones."

# Сьогодні Linux:
# - основа ~90% сайтів разом з іншими Unix-подібними (W3Techs, 2026)
# - ядро Android, а це ~70% мобільних ОС (StatCounter, 2026)
# - 100% суперкомп'ютерів з TOP500 (червень 2026)
# - марсіанський гелікоптер Ingenuity
#   (сам марсохід Perseverance працює на системі реального часу VxWorks)
```

Для самих операційних систем це десятиліття запам'яталося іншим:

| Рік | Подія | Чому важливо |
|-----|-------|--------------|
| 2001 | Windows XP | Домашня Windows нарешті перейшла на ядро NT із захистом пам'яті — кінець лінійки на основі DOS |
| 2001 | Mac OS X | Під графікою Apple — UNIX-ядро XNU |

Саме віртуалізація 2000-х і зробила можливими хмари наступного покоління: один фізичний сервер ділиться між багатьма клієнтами, кожен з яких бачить власну «машину».

```
│   │ └─────┘└─────┘└─────┘   │       │ багатьох машинах        │  │
│   │ ──────── Docker ─────── │       │                         │  │
│   │ ───── спільне ядро ──── │       │ автомасштабування,      │  │
│   │        Linux            │       │ перезапуск, балансування│  │

└──────────────────────────────────────────────────────────────────┘
```

```bash
# Практичний приклад: запуск веб-сервера в контейнері
docker run -d -p 80:80 nginx

# Список запущених контейнерів
docker ps

# Кожен контейнер — ізольоване середовище з власною "ОС"
# але всі використовують спільне ядро Linux
```

Контейнери не винайшли 2013 року — Docker лише зробив зручною обгортку над механізмами, що дозрівали десятиліттями: `chroot` (UNIX, 1979) міняв процесу корінь файлової системи, FreeBSD jails (2000) і Solaris Zones (2004) ізолювали цілі середовища, а в Linux з'явилися namespaces (окремий «світ» процесів, мережі, файлових систем) і cgroups (обмеження ресурсів, 2008). Контейнер у Linux — це звичайні процеси, яким ядро обмежило видимість і ресурси. Перевірити легко: процес із контейнера видно в `ps` на хост-машині.

|-----|----------|----------------|
| **Proprietary** | Windows, macOS, iOS | Закритий код, платна ліцензія |

| **Open Source (BSD)** | FreeBSD, OpenBSD | Вільний код, дозволяє закриття |
| **Відкрите ядро + закриті сервіси** | Android | Система AOSP відкрита (Apache 2.0), а Google Play і сервіси Google — закриті |

```bash
# Кожен модуль ядра сам оголошує свою ліцензію
modinfo -F license usb-storage
# GPL

# Якщо завантажити модуль із закритою ліцензією (наприклад, драйвер NVIDIA),
# ядро позначить себе «заплямованим» (tainted): ненульове число тут
cat /proc/sys/kernel/tainted
```

Прапорець tainted — не покарання, а чесність: розробники ядра не можуть налагоджувати чужий закритий код, тому звіти про збої від такого ядра розглядають окремо.

## Практичне завдання

Дослідіть еволюцію ОС на вашій системі:

```bash
# 1. Якої "родини" ваша ОС?
uname -a

# 2. Чи UNIX-подібна система?
# Якщо є цей файл — так:
ls /etc/passwd

# 3. Чи POSIX-сумісна?
getconf _POSIX_VERSION 2>/dev/null

# 4. Яке ядро (монолітне, мікро, гібрид)?
# Linux = монолітне (модульне)
lsmod | wc -l  # Скільки модулів ядра завантажено

# 5. Дата останнього оновлення ядра
ls -la /boot/vmlinuz* 2>/dev/null || echo "Not a Linux system"

# 6. Час роботи системи (uptime)
uptime

# 7. Версія ОС
cat /etc/os-release 2>/dev/null || sw_vers 2>/dev/null
```

## 🎯 Міні-проект (30 хв)

### Завдання: Побудова родового дерева вашої ОС

Створіть візуальну "генеалогію" вашої операційної системи — від UNIX 1969 року до вашої поточної системи.

**Кроки:**

1. Визначте "ДНК" вашої системи:
```bash
mkdir ~/os-genealogy && cd ~/os-genealogy

# Створіть файл родового дерева
echo "=== РОДОВЕ ДЕРЕВО ОС ===" > family-tree.txt
echo "" >> family-tree.txt

# Визначте базову інформацію
echo "Моя система: $(uname -s) $(uname -r)" >> family-tree.txt
echo "Архітектура: $(uname -m)" >> family-tree.txt
echo "" >> family-tree.txt
```

2. Визначте UNIX-сумісність (предки):
```bash
echo "--- UNIX-СУМІСНІСТЬ ---" >> family-tree.txt

# Чи є /etc/passwd? (ознака UNIX)
if [ -f /etc/passwd ]; then
    echo "✓ /etc/passwd існує → нащадок UNIX" >> family-tree.txt
fi

# Перевірте POSIX
POSIX_VER=$(getconf _POSIX_VERSION 2>/dev/null)
if [ -n "$POSIX_VER" ]; then
    echo "✓ POSIX версія: $POSIX_VER" >> family-tree.txt
fi

# Перевірте характерні директорії UNIX
for dir in /bin /usr /var /etc /tmp; do
    if [ -d "$dir" ]; then
        echo "✓ $dir існує (UNIX-стиль)" >> family-tree.txt
    fi
done
echo "" >> family-tree.txt
```

3. Визначте покоління ОС:
```bash
echo "--- ПОКОЛІННЯ ОС ---" >> family-tree.txt

# Покоління 3: Time-sharing
echo "Time-sharing (пок. 3):" >> family-tree.txt
echo "  Процесів в системі: $(ps aux | wc -l)" >> family-tree.txt

# Покоління 6: Мобільні технології
if [ -d /sys/class/power_supply ]; then
    echo "  Підтримка батареї: ✓" >> family-tree.txt
fi

# Покоління 7: Контейнери
if command -v docker &> /dev/null; then
    echo "Контейнери (пок. 7): ✓ Docker встановлено" >> family-tree.txt
fi
if [ -d /proc/self/ns ]; then
    echo "  Namespaces: $(ls /proc/self/ns/ | tr '\n' ' ')" >> family-tree.txt
fi
echo "" >> family-tree.txt
```

4. Побудуйте візуальне дерево:
```bash
echo "--- ВІЗУАЛЬНЕ ДЕРЕВО ---" >> family-tree.txt
echo "" >> family-tree.txt
echo "UNIX (1969, Bell Labs)" >> family-tree.txt
echo "    ├── BSD (1977) ── FreeBSD, macOS" >> family-tree.txt
echo "    └── System V ─── Solaris, AIX" >> family-tree.txt
echo "" >> family-tree.txt
echo "Linux (1991) — окрема гілка: написаний з нуля," >> family-tree.txt
echo "повторює інтерфейси UNIX (POSIX), але не його код" >> family-tree.txt

# Додайте вашу систему
if [ -f /etc/os-release ]; then
    DISTRO=$(grep "^NAME=" /etc/os-release | cut -d'"' -f2)
    echo "    └── $DISTRO (ваша система)" >> family-tree.txt
fi
echo "" >> family-tree.txt
```

5. Додайте цікаві факти:
```bash
echo "--- ЦІКАВІ ФАКТИ ---" >> family-tree.txt
echo "Вік ядра Linux: $(($(date +%Y) - 1991)) років" >> family-tree.txt
echo "Ваше ядро зібрано: $(uname -v)" >> family-tree.txt
echo "Підтримуваних ФС: $(cat /proc/filesystems | wc -l)" >> family-tree.txt
echo "Модулів ядра: $(lsmod | wc -l)" >> family-tree.txt
```

6. Перегляньте результат:
```bash
cat family-tree.txt
```

**Очікуваний результат:**
Файл `family-tree.txt` з візуальним родовим деревом вашої ОС, показуючи її зв'язок з UNIX та еволюційні особливості.

**Бонус (для допитливих):**
- Знайдіть, коли саме було випущено версію вашого дистрибутива
- Порівняйте дерево Linux та macOS (якщо є доступ до Mac)
- Дослідіть, чи є у вашій системі код, який старший за 30 років

**1.** Що стало ключовою інновацією другого покоління ОС (1955-1965)?

- графічний інтерфейс
- контейнеризація
- мультипрограмування
- пакетна обробка завдань

**2.** Яку проблему розв'язало мультипрограмування?

- диски були надто повільними для пакетної обробки
- програми не вміщувалися в оперативну пам'ять
- процесор простоював під час введення-виведення, а тепер у пам'яті кілька задач
- користувачі не мали графічного інтерфейсу

**3.** Від якої гілки UNIX походять macOS і FreeBSD?

- від System V
- від BSD
- від MINIX
- від Windows NT

**4.** Ким є Linux щодо UNIX?

- прямим нащадком вихідного коду UNIX
- гілкою BSD
- UNIX-подібною системою, написаною з нуля під впливом MINIX
- комерційною версією System V

**5.** Який порядок подій правильний?

- MS-DOS (1981) → Linux (1991) → Docker (2013)
- MS-DOS (1981) → Docker (2013) → Linux (1991)
- Linux (1991) → MS-DOS (1981) → Docker (2013)
- Docker (2013) → MS-DOS (1981) → Linux (1991)

**6.** Чим система реального часу відрізняється від звичайної?

- вона гарантує граничний час реакції, а не просто високу середню швидкість
- вона працює швидше за будь-яку настільну систему
- вона підтримує лише один процес одночасно
- вона не має ядра й планувальника

**7.** Яка з систем належить до вбудованих?

- Android
- FreeRTOS
- Ubuntu Server
- macOS

**8.** Чим серверна ОС відрізняється від настільної за пріоритетами?

- вона не підтримує кількох користувачів
- на першому місці графічний інтерфейс і мультимедіа
- вона не потребує оновлень безпеки
- на першому місці безвідмовна робота, мережа й керування з командного рядка

**9.** Що принесло сьоме покоління ОС (2010-ті)?

- мобільні системи з сенсорним екраном
- пакетну обробку завдань
- персональні комп'ютери й графічний інтерфейс
- контейнери й оркестрацію: Docker і Kubernetes

**10.** Який висновок дає історія розвитку операційних систем?

- сучасні ОС не мають нічого спільного з UNIX
- базові концепції — процеси, пам'ять, файли, введення-виведення — не змінюються десятиліттями
- еволюція ОС завершилася з появою хмарних систем
- кожне покоління повністю відкидає ідеї попереднього
