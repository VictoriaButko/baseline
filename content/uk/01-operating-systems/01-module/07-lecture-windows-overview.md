## Від MS-DOS до Windows 11

Windows — найпопулярніша операційна система для персональних комп'ютерів з часткою ринку ~70%. За 40 років Microsoft пройшла шлях від простої оболонки над DOS до складної гібридної ОС.

```
┌─────────────────────────────────────────────────────────────────┐
│                    ЕВОЛЮЦІЯ WINDOWS                             │
│                                                                 │
│  1985──1990──1995──2000──2001──2006──2009──2012──2015──2021     │
│    │     │     │     │     │     │     │     │     │     │      │
│    ▼     ▼     ▼     ▼     ▼     ▼     ▼     ▼     ▼     ▼      │
│   1.0   3.0   95    Me    XP  Vista   7     8    10    11       │
│    │     │     │     │     │     │     │     │     │     │      │
│   DOS   DOS   DOS  DOS   NT    NT    NT    NT    NT    NT       │
│   based      32bit      kernel                                  │
│                         │                                       │
│                         └────────────────────────────────────── │
│                            Всі сучасні Windows базуються        │
│                            на архітектурі NT                    │
│                                                                 │
│   Дві лінії:                                                    │
│   • DOS-based: Win 1.0 → 3.x → 95 → 98 → Me (кінець 2000)       │
```

### Ключові віхи

| Рік | Версія | Значення |
|-----|--------|----------|
| 1985 | Windows 1.0 | Перша версія, графічна оболонка над DOS |
| 1990 | Windows 3.0 | Комерційний успіх, 10 млн копій |
| 1993 | Windows NT 3.1 | Нове ядро, 32-біт, захищений режим |
| 1995 | Windows 95 | Start меню, 32-біт API, Plug & Play |
| 2001 | Windows XP | Злиття NT та домашньої лінії, масовий успіх |
| 2009 | Windows 7 | "Виправлений Vista", золотий стандарт |
| 2015 | Windows 10 | «Остання версія Windows», оновлення двічі на рік; підтримку завершено 14.10.2025 |
| 2021 | Windows 11 | Новий UI, вимоги TPM 2.0 і Secure Boot |

Фразу про «останню версію Windows» 2015 року сказав співробітник Microsoft на конференції розробників, і компанія довго її не спростовувала: планувалося, що далі Windows 10 лише оновлюватиметься. Через шість років вийшла Windows 11. А запущену з нею підтримку Android-застосунків Microsoft згорнула вже в березні 2025 року.

## Архітектура Windows NT

Windows NT (New Technology) — це повністю нова ОС, розроблена з нуля в 1988-1993 роках командою під керівництвом Девіда Катлера (раніше — головного архітектора VMS у DEC). Існує жарт, що WNT — це VMS, у якій кожну літеру зсунули на одну вперед абеткою: V→W, M→N, S→T. Випадково чи ні, спадок VMS в архітектурі NT справді помітний — від планувальника з пріоритетами до моделі введення-виведення.

Чому ядро NT називають гібридним, ми розібрали в лекції 6. Тут — з чого воно складається.

## Основні компоненти ядра Windows

```
│   ┌────────────────────────────────────────────────────────┐    │
│   │   Один і той же код ядра                               │    │
│   └──────────────────────────┬─────────────────────────────┘    │
│                              │                                  │
│                              ▼                                  │
│   ┌─────────────────────────────────────────────────────────┐   │

│   │   • Специфіка платформи                                 │   │
│   └─────────────────────────────────────────────────────────┘   │
│            │                                   │                │
│            ▼                                   ▼                │
│   ┌───────────────────────┐          ┌─────────────────┐        │
```

Спершу HAL був дуже потрібен: перша NT 3.1 працювала не лише на x86, а й на процесорах MIPS і Alpha, згодом на PowerPC. Розробку NT узагалі починали на процесорі Intel i860 — саме щоб команда не прив'язалася до x86. Потім Windows на кілька десятиліть звузилася до x86, а тепер знову повертається до ARM.

### Windows Kernel (ntoskrnl.exe)

Файл **ntoskrnl.exe** — серце Windows. Містить:

| Компонент | Функція |
|-----------|---------|
| **Scheduler** | Планування потоків, а не процесів |
| **Interrupt Dispatcher** | Обробка апаратних переривань |
| **Exception Handler** | Обробка виключень (access violation, etc.) |
| **DPC/APC** | Відкладене виконання процедур |

## Процеси в Windows

Windows використовує **потоки (threads)** як одиниці планування, а не процеси. Linux, до речі, так само планує потоки: для його планувальника кожен потік — окрема задача (task). Різниця — у термінах і в тому, як система описує процес.

```
┌─────────────────────────────────────────────────────────────────┐
│                    ПРОЦЕС WINDOWS                               │
│                                                                 │
│   ┌──────────────────────────────────────────────────────────┐  │
│   │                    PROCESS (chrome.exe)                  │  │
│   │                                                          │  │
│   │   PID: 1234                                              │  │
│   │   Приватний віртуальний простір для програми:            │  │
│   │     2 ГБ у 32-бітній Windows, 128 ТБ у 64-бітній         │  │
│   │                                                          │  │
│   │   ┌─────────┐  ┌─────────┐  ┌─────────┐  ┌─────────┐     │  │
│   │   │ Thread  │  │ Thread  │  │ Thread  │  │ Thread  │     │  │
│   │   │   #1    │  │   #2    │  │   #3    │  │   #4    │     │  │
│   │   │ (main)  │  │ (UI)    │  │ (network│  │ (render)│     │  │
│   │   └─────────┘  └─────────┘  └─────────┘  └─────────┘     │  │
│   │                                                          │  │
│   │   Handle table: файли, реєстр, об'єкти ядра              │  │
│   │   Security token: права користувача                      │  │
│   │                                                          │  │
│   └──────────────────────────────────────────────────────────┘  │
│                                                                 │
│   Потік = одиниця планування                                    │
│   Процес = контейнер для потоків + ресурсів                     │
└─────────────────────────────────────────────────────────────────┘
```

**PowerShell команди для роботи з процесами:**

```powershell
# Список процесів
Get-Process

# Детальна інформація
Get-Process chrome | Format-List *

# Потоки процесу
(Get-Process chrome).Threads.Count

# Топ за пам'яттю
Get-Process | Sort-Object WorkingSet -Descending | Select-Object -First 10

# Створити новий процес
Start-Process notepad.exe

# Завершити процес
Stop-Process -Name "notepad"
```

## Реєстр Windows (Registry)

Централізована база даних конфігурації системи.

```
┌────────────────────────────────────────────────────────────────┐
│                    СТРУКТУРА РЕЄСТРУ                           │
│                                                                │
│   HKEY_LOCAL_MACHINE (HKLM)                                    │
│   ├── HARDWARE        ← Виявлене обладнання (volatile)         │
│   ├── SAM             ← Security Account Manager               │
│   ├── SECURITY        ← Політики безпеки                       │
│   ├── SOFTWARE        ← Налаштування програм (для всіх)        │
│   │   ├── Microsoft                                            │
│   │   │   └── Windows                                          │
│   │   │       └── CurrentVersion                               │
│   │   └── ...                                                  │
│   └── SYSTEM          ← Конфігурація завантаження              │
│       └── CurrentControlSet                                    │
│           └── Services                                         │
│                                                                │
│   HKEY_CURRENT_USER (HKCU)                                     │
│   ├── SOFTWARE        ← Налаштування програм (для користувача) │
│   ├── Environment     ← Змінні середовища                      │
│   └── ...                                                      │
│                                                                │
│   HKEY_CLASSES_ROOT (HKCR)                                     │
│   └── Асоціації файлів, COM об'єкти                            │
│                                                                │
│   HKEY_USERS (HKU)                                             │
│   └── Профілі всіх користувачів                                │
└────────────────────────────────────────────────────────────────┘
```

Реєстр — не одна «база даних», а набір файлів-вуликів (hives): `SYSTEM`, `SOFTWARE`, `SAM`, `SECURITY` лежать у `C:\Windows\System32\config`, а налаштування кожного користувача — у файлі `NTUSER.DAT` в його профілі. Під час завантаження ядро монтує ці файли в єдине дерево, яке ви бачите в `regedit`. Звідси й практичний наслідок: пошкоджений файл `SYSTEM` не дасть Windows завантажитися — до цього ми повернемося в лабораторній про відновлення ОС.

**Робота з реєстром:**

```powershell
# Читання ключа
Get-ItemProperty "HKLM:\SOFTWARE\Microsoft\Windows NT\CurrentVersion"

# Перегляд версії Windows
(Get-ItemProperty "HKLM:\SOFTWARE\Microsoft\Windows NT\CurrentVersion").ProductName

# Список служб з реєстру
Get-ChildItem "HKLM:\SYSTEM\CurrentControlSet\Services" | Measure-Object

# Змінні середовища
Get-ItemProperty "HKCU:\Environment"
```

```cmd
:: CMD команди
reg query "HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion" /v ProductName
reg query "HKLM\SYSTEM\CurrentControlSet\Services" /s
```

### Master File Table: у NTFS усе — файл

Серце NTFS — таблиця **MFT (Master File Table)**. Кожен файл і каталог — це запис у ній розміром 1 КБ з атрибутами: ім'я, мітки часу, права, а головне — дані. Для великих файлів запис лише вказує, в яких кластерах диска лежить вміст. Але файл розміром у кілька сотень байтів NTFS зберігає *прямо всередині* запису MFT — на диску для нього навіть не виділяється окремий кластер.

Цікаво, що службові структури самої файлової системи — теж файли з записами в MFT: `$MFT` (сама таблиця), `$LogFile` (журнал), `$Bitmap` (карта вільних кластерів). Та сама ідея «все є файлом», що й в UNIX, лише реалізована інакше.

**Практичні команди:**

```powershell
# Інформація про диск
Get-Volume

# NTFS-специфічні атрибути
Get-Item C:\Windows\System32\cmd.exe | Format-List *

# Права доступу (ACL)
Get-Acl C:\Windows\System32\cmd.exe | Format-List

# Alternate Data Streams
Get-Item file.txt -Stream *

# Жорсткі посилання
fsutil hardlink list C:\Windows\System32\cmd.exe
```

## 🎯 Міні-проект (30 хв)

### Завдання: Створення Windows System Reporter

Створіть PowerShell-скрипт, який автоматично збирає повну інформацію про архітектуру Windows-системи та зберігає її у звіт.

**Кроки:**

1. Створіть директорію для проекту:
```powershell
New-Item -Path "$env:USERPROFILE\WinReporter" -ItemType Directory -Force
Set-Location "$env:USERPROFILE\WinReporter"
```

2. Створіть скрипт збору інформації:
```powershell
# Збираємо дані про систему
$Report = @{
    GeneratedAt = Get-Date
    ComputerName = $env:COMPUTERNAME
    UserName = $env:USERNAME
}

# Інформація про ОС (Get-CimInstance замість застарілого Get-WmiObject,
# якого вже немає в PowerShell 7)
$OS = Get-CimInstance Win32_OperatingSystem
$Report.OSName = $OS.Caption
$Report.OSVersion = $OS.Version
$Report.OSBuild = $OS.BuildNumber
$Report.OSArchitecture = $OS.OSArchitecture

# Інформація про залізо
$Report.TotalRAM = [math]::Round($OS.TotalVisibleMemorySize / 1MB, 2)
$Report.FreeRAM = [math]::Round($OS.FreePhysicalMemory / 1MB, 2)
$Report.CPUCores = (Get-CimInstance Win32_Processor).NumberOfCores
```

3. Додайте інформацію про процеси та служби:
```powershell
# Топ-5 процесів за RAM
$Report.TopProcesses = Get-Process |
    Sort-Object WorkingSet -Descending |
    Select-Object -First 5 Name, @{N='RAM_MB';E={[math]::Round($_.WorkingSet/1MB)}}

# Кількість служб
$Services = Get-Service
$Report.RunningServices = ($Services | Where-Object Status -eq "Running").Count
$Report.StoppedServices = ($Services | Where-Object Status -eq "Stopped").Count
```

4. Додайте інформацію про диски:
```powershell
# Інформація про томи
$Report.Volumes = Get-Volume |
    Where-Object DriveLetter |
    Select-Object DriveLetter, FileSystemType,
        @{N='Size_GB';E={[math]::Round($_.Size/1GB, 2)}},
        @{N='Free_GB';E={[math]::Round($_.SizeRemaining/1GB, 2)}}
```

5. Згенеруйте текстовий звіт:
```powershell
$TextReport = @"
========================================
    WINDOWS SYSTEM REPORT
========================================
Generated: $($Report.GeneratedAt)
Computer: $($Report.ComputerName)
User: $($Report.UserName)

--- OPERATING SYSTEM ---
Name: $($Report.OSName)
Version: $($Report.OSVersion)
Build: $($Report.OSBuild)
Architecture: $($Report.OSArchitecture)

--- HARDWARE ---
Total RAM: $($Report.TotalRAM) GB
Free RAM: $($Report.FreeRAM) GB
CPU Cores: $($Report.CPUCores)

--- SERVICES ---
Running: $($Report.RunningServices)
Stopped: $($Report.StoppedServices)

--- TOP PROCESSES BY RAM ---
$($Report.TopProcesses | Format-Table -AutoSize | Out-String)

--- DISK VOLUMES ---
$($Report.Volumes | Format-Table -AutoSize | Out-String)
========================================
"@

$TextReport | Out-File "SystemReport.txt"
Write-Host "Report saved to SystemReport.txt" -ForegroundColor Green
```

6. Перегляньте результат:
```powershell
Get-Content "SystemReport.txt"
```

**Очікуваний результат:**
Файл `SystemReport.txt` у директорії `WinReporter` з повним звітом про архітектуру вашої Windows-системи.

**Бонус (для допитливих):**
- Додайте до звіту інформацію з реєстру (встановлені програми)
- Згенеруйте HTML-версію звіту з таблицями та кольорами
- Налаштуйте автоматичний запуск через Task Scheduler щодня

## Тест для самоперевірки

Десять запитань, у кожному одна правильна відповідь. Якщо тема винесена вашій групі на самостійне опрацювання, цей самий тест публікується в Google Classroom — 10 балів, по одному за кожне запитання.

**1.** Яку задачу розв'язує рівень апаратної абстракції HAL?

- прискорює доступ до відеокарти в іграх
- керує правами доступу до файлів
- зберігає налаштування системи між перезавантаженнями
- ховає відмінності обладнання, тож ядро не переписують під кожну платформу

**2.** У якому файлі міститься ядро Windows?

- services.exe
- ntoskrnl.exe
- ntdll.dll
- hal.dll

**3.** Що таке файли з розширенням `.sys` у Windows?

- резервні копії реєстру
- бібліотеки прикладних програм
- журнали системних подій
- драйвери пристроїв

**4.** Що є одиницею планування у Windows?

- потік
- завдання (job)
- процес
- служба

**5.** Який менеджер Windows Executive відповідає за ACL і токени доступу?

- Object Manager
- Security Reference Monitor
- I/O Manager
- Process Manager

**6.** У чому суть об'єктної моделі Windows?

- об'єкти зберігаються лише в оперативній пам'яті
- кожен процес отримує власну копію ядра
- файли, процеси, ключі реєстру — усе подано об'єктами з іменами та правами
- усі програми пишуться об'єктно-орієнтованими мовами

**7.** Чим різняться гілки реєстру HKEY_LOCAL_MACHINE та HKEY_CURRENT_USER?

- перша зберігає налаштування всієї системи, друга — налаштування поточного користувача
- перша існує лише в серверних редакціях
- перша зберігає налаштування користувача, друга — системні
- вони дублюють одна одну для надійності

**8.** Яка перевага NTFS над FAT32 для сервера?

- відсутність обмежень на кількість розділів
- підтримка старих версій MS-DOS
- журналювання та списки контролю доступу ACL
- менший розмір службових структур

**9.** Який процес виступає контейнером для системних служб Windows?

- hal.dll
- svchost.exe
- ntdll.dll
- explorer.exe

**10.** Яка команда PowerShell покаже десять процесів, що найбільше навантажують процесор?

- Get-Service | Where Status -eq Running
- Get-Volume
- Get-Process | Sort CPU -Desc | Select -First 10
- Get-Acl C:\path\file

## Підсумок

| Компонент | Призначення | Розташування |
|-----------|-------------|--------------|
| **HAL** | Апаратна абстракція | hal.dll |
| **Kernel** | Планування, переривання | ntoskrnl.exe |
| **Executive** | I/O, Memory, Process managers | ntoskrnl.exe |
| **Drivers** | Робота з пристроями | *.sys |

**Ключові особливості Windows NT:**
- Гібридне ядро (Executive + мікроядро-подібний Kernel)
- Об'єктна модель (все — об'єкт)
- Потоки як одиниці планування
- Централізований реєстр
- NTFS з журналюванням та ACL
