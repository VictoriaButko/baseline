## Hook / Захоплюючий вступ

Слово «термінал» походить від справжніх машин. У 1960–70-х до комп'ютера під'єднували **телетайп** (teletypewriter, звідси TTY) — електричну друкарську машинку, що друкувала вивід на паперовій стрічці. Потім з'явилися «скляні телетайпи» з екраном, як легендарний VT100 від DEC (1978). Ваш сучасний термінал на Linux досі прикидається VT100: коли `ls` фарбує каталоги синім, він надсилає ті самі керувальні послідовності, які розумів той апарат.

Ще кілька «скам'янілостей» з тих часів, які ви зустрінете сьогодні:

- **Ctrl+C** зупиняє програму не тому, що програма так вирішила, — сигнал надсилає ядро, побачивши цей символ у потоці з клавіатури.
- **Ctrl+S** «заморожує» термінал — це команда XOFF, якою телетайп просив комп'ютер зачекати, поки папір прокрутиться. «Розморожує» **Ctrl+Q**. Скільки студентів перезавантажували комп'ютер, випадково натиснувши Ctrl+S у редакторі!
- Сигнал **SIGHUP** («hang up» — «поклали слухавку») надходить програмам, коли розривається з'єднання, — від часів, коли термінал під'єднувався модемом телефонною лінією.

**Запитання до аудиторії**: ви запустили на сервері через SSH копіювання на дві години, і в цей момент зник Wi-Fi. Що станеться з копіюванням — і як цього уникнути?

## Консольний режим (TTY)

Linux завжди має текстовий режим, навіть без графічного інтерфейсу. На ньому тримаються сервери, аварійне відновлення, віддалений доступ і автоматизація.

```
┌─────────────────────────────────────────────────────────────────────┐
│                          ВІРТУАЛЬНІ КОНСОЛІ                         │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│  Ctrl+Alt+F1 … F6 — перемикання між віртуальними консолями          │
│                                                                     │
│  Ubuntu, Fedora (GDM):   tty1 — екран входу GDM                     │
│                          tty2 — ваш графічний сеанс                 │
│                          tty3 … tty6 — текстові консолі             │
│  Старіші системи:        tty1 … tty6 — текст, tty7 — графіка        │
│                                                                     │
│  Якщо графіка «зависла»: Ctrl+Alt+F3 → увійти → знайти й            │
│  завершити процес, що заважає → Ctrl+Alt+F2 назад у сеанс.          │
└─────────────────────────────────────────────────────────────────────┘
```

```bash
tty                         # /dev/tty3 — текстова консоль, /dev/pts/0 — псевдотермінал
who                         # хто де працює: tty2, pts/0 …
w                           # те саме плюс навантаження і поточна команда
sudo chvt 3                 # перемкнутися на tty3 командою
echo "Привіт" | sudo tee /dev/tty3    # написати на екран іншої консолі
```

### Термінал очима ядра

Є два види терміналів. **Віртуальна консоль** (`/dev/tty1`…`/dev/tty6`) — це ядро, яке само малює текст на екрані й читає клавіатуру. **Псевдотермінал** (pty) — пара файлів пристрою: у «головну» сторону пише програма-емулятор (gnome-terminal) чи сервер SSH, а в «підлеглій» (`/dev/pts/N`) працює оболонка. Для bash обидва випадки виглядають однаково.

```
┌─────────────────────────────────────────────────────────────────────┐
│                         ТЕРМІНАЛ ОЧИМА ЯДРА                         │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│  ТЕКСТОВА КОНСОЛЬ               ГРАФІЧНИЙ ТЕРМІНАЛ АБО SSH          │
│                                                                     │
│  клавіатура, екран              вікно gnome-terminal / sshd         │
│        │                                │ головна сторона pty       │
│        ▼                                ▼                           │
│  драйвер консолі ядра           /dev/ptmx ─── пара ─── /dev/pts/0   │
│        │                                                  │         │
│        ▼                                                  ▼         │
│  ┌──────────────────── tty-шар ядра + line discipline ──────────┐   │
│  │ Буферизує рядок, обробляє Backspace, а Ctrl+C перетворює на  │   │
│  │ сигнал SIGINT для процесів переднього плану; Ctrl+Z — SIGTSTP│   │
│  └──────────────────────────────────────────────────────────────┘   │
│        │                                                            │
│        ▼                                                            │
│  /dev/tty3 або /dev/pts/0 — stdin, stdout, stderr оболонки bash     │
│                                                                     │
│  Програма не знає, де вона: у консолі, у вікні чи по SSH.           │
│  Вона просто читає й пише файл пристрою терміналу.                  │
└─────────────────────────────────────────────────────────────────────┘
```

Між ними стоїть **line discipline** — частина tty-шару ядра, яка редагує рядок до натискання Enter і перетворює спеціальні символи на сигнали. Її налаштування показує `stty`:

```bash
stty -a | head -4           # intr = ^C; quit = ^\; susp = ^Z; stop = ^S; start = ^Q
ls -l /dev/pts/             # псевдотермінали відкритих вікон і SSH-сеансів
ls -l /proc/$$/fd/0         # stdin поточної оболонки — це файл терміналу
reset                       # якщо термінал «зламався» після cat двійкового файлу
```

### Коли потрібен консольний режим

| Ситуація | Що робити |
|----------|-----------|
| Графічний сеанс завис | `Ctrl+Alt+F3`, увійти, `top` → знайти й завершити процес або `sudo systemctl restart display-manager` |
| Встановлення драйвера NVIDIA з інсталятора `.run` | Зупинити графіку (`sudo systemctl isolate multi-user.target`) і працювати з консолі |
| Сервер без графіки | Уся робота — через SSH |
| Система не завантажується | Режим відновлення (recovery), оболонка initramfs, `chroot` з Live USB |

## Термінальні емулятори

**Термінальний емулятор** — графічна програма, що відкриває псевдотермінал, запускає в ньому оболонку й малює її вивід у вікні. Емулятор відповідає за шрифти, кольори, вкладки й копіювання; команди виконує оболонка.

| Емулятор | Де за замовчуванням | Особливості |
|----------|---------------------|-------------|
| **GNOME Terminal** | GNOME до версії 46 | Профілі, вкладки |
| **Ptyxis** | Fedora 41+, Ubuntu 25.10+ | Новий термінал GNOME, зручний для контейнерів |
| **Konsole** | KDE Plasma | Розділення вікна, закладки SSH |
| **Alacritty** | — | Прискорення GPU, конфігурація TOML |
| **Kitty** | — | Прискорення GPU, показ зображень у терміналі |
| **WezTerm** | — | Конфігурація Lua, вбудований мультиплексор |
| **xterm** | — | Еталонний емулятор X11 з 1984 року |

| Сполучення | Дія |
|------------|-----|
| `Ctrl+Shift+T` / `Ctrl+Shift+N` | Нова вкладка / нове вікно |
| `Ctrl+Shift+C` / `Ctrl+Shift+V` | Копіювати / вставити (`Ctrl+C` зайнятий сигналом!) |
| `Ctrl+Shift+F` | Пошук у виводі |
| `Ctrl+PageUp/PageDown` | Сусідня вкладка |
| `Shift+PageUp/PageDown` | Прокрутка виводу |
| `Ctrl++` / `Ctrl+-` | Збільшити / зменшити шрифт |

## Оболонка: Bash

**Оболонка** (shell) читає команди, розгортає в них змінні й шаблони, запускає програми та керує їхніми потоками. **Bash** (Bourne Again Shell, 1989) — оболонка проєкту GNU і стандартна інтерактивна оболонка більшості дистрибутивів.

| Оболонка | Особливості | Файл налаштувань |
|----------|-------------|------------------|
| **bash** | Стандарт Linux, сумісна з POSIX sh | `~/.bashrc` |
| **zsh** | Потужне доповнення, теми (Oh My Zsh); стандартна в macOS з 2019 року | `~/.zshrc` |
| **fish** | Підказки й підсвічування «з коробки», не сумісна з POSIX | `~/.config/fish/config.fish` |
| **dash** | Мінімальна й швидка, `/bin/sh` у Debian і Ubuntu — для скриптів | — |

```bash
echo $SHELL                 # оболонка входу з /etc/passwd
ps -p $$ -o comm=           # оболонка, в якій ви зараз
cat /etc/shells             # дозволені оболонки
chsh -s /usr/bin/zsh        # змінити оболонку входу
```

### Які файли читає bash

```
Оболонка входу (tty, SSH):             Інтерактивна, не входу (вікно терміналу):
  /etc/profile                           /etc/bash.bashrc  (у Debian і Ubuntu)
  перший знайдений з:                    ~/.bashrc
    ~/.bash_profile, ~/.bash_login,
    ~/.profile
  ~/.bash_logout — під час виходу
```

Практичне правило: змінні оточення (`PATH`, `EDITOR`) кладуть у `~/.profile` — його читає і оболонка входу, і менеджер входу графічного сеансу, тож змінні побачать усі програми. Аліаси, функції й вигляд запрошення кладуть у `~/.bashrc`: вони потрібні лише в інтерактивному терміналі. В Ubuntu `~/.profile` сам підключає `~/.bashrc`, тож усе працює й у консолі входу.

```bash
source ~/.bashrc            # застосувати зміни без нового вікна (або: . ~/.bashrc)
bash -x -c 'echo $HOME'     # показати, що саме виконує оболонка
```

## Потоки, перенаправлення й конвеєри

Кожна програма в Unix отримує три відкриті файли — **стандартні потоки** з номерами (дескрипторами) 0, 1 і 2. Саме на цьому тримається вся сила командного рядка: маленькі програми, кожна з яких робить одне, з'єднуються в ланцюжки.

```
┌─────────────────────────────────────────────────────────────────────┐
│                        ТРИ СТАНДАРТНІ ПОТОКИ                        │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│                 ┌─────────────────┐                                 │
│  0 stdin  ────► │                 │ ────► 1 stdout (звичайний вивід)│
│  клавіатура     │    програма     │                                 │
│                 │                 │ ────► 2 stderr  (помилки)       │
│                 └─────────────────┘                                 │
│                                                                     │
│  За замовчуванням усі три — термінал. Оболонка може перед           │
│  запуском підмінити будь-який із них файлом або іншою програмою.    │
│                                                                     │
│  ls /etc  /немає  > out.txt  2> err.txt                             │
│           список ──┘          └── «No such file or directory»       │
└─────────────────────────────────────────────────────────────────────┘
```

Таблиця 1 — Перенаправлення

| Запис | Що робить |
|-------|-----------|
| `команда > файл` | stdout у файл; файл перезаписується |
| `команда >> файл` | stdout дописується в кінець файлу |
| `команда 2> файл` | stderr у файл |
| `команда > файл 2>&1` | і stdout, і stderr у той самий файл |
| `команда &> файл` | те саме коротше (лише bash) |
| `команда < файл` | stdin читається з файлу |
| `команда 2>/dev/null` | викинути повідомлення про помилки |
| `a \| b` | конвеєр: stdout програми a стає stdin програми b |
| `a \| tee файл` | вивід і на екран, і у файл |

```bash
ls /etc /немає > out.txt 2> err.txt       # вивід і помилки — в різні файли
ls /etc /немає > all.txt 2>&1             # усе в один файл
ls /etc /немає 2>&1 > all.txt             # ПОМИЛКА: stderr пішов на екран

# Конвеєр: 5 найчастіших оболонок входу серед користувачів системи
cut -d: -f7 /etc/passwd | sort | uniq -c | sort -rn | head -5

# Помилки довгої команди — і на екран, і в журнал
sudo apt update 2>&1 | tee ~/apt.log
```

Порядок у записі `> файл 2>&1` важливий: оболонка обробляє перенаправлення зліва направо. Спершу stdout спрямовується у файл, потім stderr стає «копією» stdout — тобто теж файлом. У зворотному порядку stderr копіює stdout ще тоді, коли той вказує на термінал. Перевірити, куди насправді дивляться потоки процесу, можна в `/proc`: `ls -l /proc/<PID>/fd`.

Кожна програма конвеєра — окремий процес, і всі вони працюють **одночасно**: `sort` отримує дані від `cut`, щойно ті з'являються, через буфер у пам'яті ядра (pipe). Тому `cat величезний.log | grep ERROR | head -3` завершиться миттєво, щойно знайдено три рядки: `head` закриває канал, і попередні програми отримують сигнал SIGPIPE.

### Гарячі клавіші Bash (Readline)

| Сполучення | Дія |
|------------|-----|
| `Ctrl+A` / `Ctrl+E` | На початок / кінець рядка |
| `Alt+B` / `Alt+F` | На слово назад / вперед |
| `Ctrl+U` / `Ctrl+K` | Видалити до початку / до кінця рядка |
| `Ctrl+W` / `Alt+D` | Видалити слово перед / після курсора |
| `Ctrl+Y` | Вставити останнє видалене |
| `Ctrl+R` | Пошук в історії; повторне `Ctrl+R` — далі, `Ctrl+G` — скасувати |
| `!!` / `!$` | Остання команда / її останній аргумент (`sudo !!`) |
| `Ctrl+L` | Очистити екран |
| `Tab`, `Tab Tab` | Доповнення / усі варіанти |
| `Ctrl+C` | Сигнал SIGINT — перервати програму |
| `Ctrl+Z` | Сигнал SIGTSTP — призупинити; далі `fg` (на передній план), `bg` (у фон), `jobs` (список) |
| `Ctrl+D` | Кінець введення (EOF); у порожньому рядку — вихід з оболонки |

Ці клавіші дає бібліотека **Readline** — тому вони працюють не лише в bash, а й у `python3`, `psql`, `gdb`. Налаштування Readline зберігаються в `~/.inputrc`.

### Корисні налаштування

```bash
# ~/.bashrc
HISTSIZE=50000                     # команд у пам'яті
HISTFILESIZE=100000                # команд у файлі ~/.bash_history
HISTCONTROL=ignoreboth:erasedups   # без дублікатів і команд, що починаються з пробілу
shopt -s histappend                # дописувати історію, а не перезаписувати

alias ll='ls -lah'
alias ..='cd ..'
mkcd() { mkdir -p "$1" && cd "$1"; }    # функція: створити каталог і перейти в нього
```

```bash
# ~/.inputrc — налаштування Readline
$include /etc/inputrc
set completion-ignore-case on      # доповнення без урахування регістру
set show-all-if-ambiguous on       # варіанти одразу після першого Tab
```

Про аліас `rm='rm -i'` сперечаються: він рятує від помилки на своєму ноутбуці, але привчає покладатися на запит, якого на чужому сервері не буде. Надійніше — звичка перевіряти шаблон командою `ls` перед `rm`.

## Midnight Commander (mc)

**Midnight Commander** (1994) — двопанельний файловий менеджер для консолі, клон Norton Commander для DOS. Він незамінний на сервері: копіювання, пошук, перегляд архівів і файлів на іншій машині — без жодної графіки.

```
┌─────────────────────────────────────────────────────────────────────┐
│                          MIDNIGHT COMMANDER                         │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│  ┌─ ~/Документи ──────────────┐┌─ ~/Завантаження ───────────┐       │
│  │ Ім'я            Розмір     ││ Ім'я            Розмір     │       │
│  │ /..             UP--DIR    ││ /..             UP--DIR    │       │
│  │ /звіти          4096       ││ /temp           4096       │       │
│  │ /фото           4096       ││  лекція.pdf     2M         │       │
│  │  план.txt       1200       ││  архів.zip      15M        │       │
│  │  script.sh      412        ││                            │       │
│  └────────────────────────────┘└────────────────────────────┘       │
│  student@lab-vm:~/Документи$ _                                      │
│  1Help 2Menu 3View 4Edit 5Copy 6RenMov 7Mkdir 8Delete 9PullDn 10Quit│
│                                                                     │
│  Дві панелі, внизу — командний рядок і підказки F-клавіш.           │
│  Tab — перемкнути панель, F5/F6 діють з активної на іншу.           │
└─────────────────────────────────────────────────────────────────────┘
```

```bash
sudo apt install mc         # Fedora: dnf install mc, Arch: pacman -S mc
mc                          # запустити
mc /var/log ~/lab           # з заданими каталогами в панелях
mcedit файл                 # лише вбудований редактор
mcview файл                 # лише переглядач
```

| Клавіша | Дія |
|---------|-----|
| `F3` / `F4` | Переглянути / редагувати файл |
| `F5` / `F6` | Копіювати / перемістити на іншу панель |
| `F7` / `F8` | Створити каталог / видалити |
| `F9` / `F10` | Меню / вихід |
| `Tab` | Перемкнути панель |
| `Insert` або `Ctrl+T` | Позначити файл |
| `+` / `-` / `*` | Позначити за маскою / зняти / інвертувати |
| `Ctrl+O` | Сховати панелі й показати консоль |
| `Ctrl+U` | Поміняти панелі місцями |
| `Ctrl+\` | Закладки каталогів |
| `Alt+?` | Пошук файлів |
| `Alt+C` | Швидкий перехід до каталогу |

Можливості, через які mc люблять адміністратори:

- **Архіви як каталоги**: Enter на `.tar.gz`, `.zip` чи `.deb` відкриває їх, як звичайну теку, — звідти можна скопіювати окремий файл.
- **Файли на іншій машині**: у меню F9 → Left → SFTP link (або у рядку шляху `sftp://user@host/шлях`) панель показує каталог сервера, і F5 копіює між машинами.
- **Меню користувача** (F2): власні команди для поточного файлу, описані в `~/.config/mc/menu`.

Налаштування mc зберігаються в `~/.config/mc/`: `ini` (основні), `panels.ini` (панелі), `mc.keymap` (клавіші), `menu` (меню користувача). Колірні схеми — F9 → Options → Appearance.

| Альтернатива | Мова | Особливості |
|--------------|------|-------------|

## Мультиплексори: tmux і screen

**Термінальний мультиплексор** запускає всередині одного терміналу кілька сеансів оболонки й — головне — **тримає їх на сервері** незалежно від вашого з'єднання.

```
┌─────────────────────────────────────────────────────────────────────┐
│                      TMUX: СЕАНС, ВІКНА, ПАНЕЛІ                     │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│  ┌─────────────────────────┬──────────────────────────────────┐     │
│  │ панель 0: vim           │ панель 1: bash                   │     │
│  │                         │                                  │     │
│  │                         │                                  │     │
│  ├─────────────────────────┴──────────────────────────────────┤     │
│  │ панель 2: htop                                             │     │
│  │                                                            │     │
│  └────────────────────────────────────────────────────────────┘     │
│  [work] 0:code* 1:logs 2:shell            "lab-vm" 14:30 26-вер     │
│    │      └── вікна (як вкладки), * — поточне                       │
│    └── ім'я сеансу                                                  │
│                                                                     │
│  Сеанс → вікна → панелі. Сеанс живе на сервері, навіть коли         │
│  ви від'єдналися: tmux attach повертає все як було.                 │
└─────────────────────────────────────────────────────────────────────┘
```

Відповідь на запитання зі вступу. Коли з'єднання SSH рветься, сервер надсилає SIGHUP сеансу, і процеси, запущені в ньому, завершуються — копіювання зупиниться. tmux влаштований інакше: програми працюють усередині окремого **серверного процесу tmux**, який не залежить від вашого SSH-сеансу. Обрив з'єднання закриває лише «вікно» до нього, а `tmux attach` повертає все на місце. Для однієї команди без мультиплексора є `nohup команда &` (ігнорувати SIGHUP) або `systemd-run --user команда`.

```bash
sudo apt install tmux
tmux new -s work            # новий сеанс з ім'ям
# Ctrl+B, d                 # від'єднатися — сеанс живе далі
tmux ls                     # список сеансів
tmux attach -t work         # повернутися (або: tmux a)
tmux kill-session -t work   # завершити
```

| Сполучення (префікс `Ctrl+B`) | Дія |
|-------------------------------|-----|
| `c` / `n` / `p` / `0-9` | Нове вікно / наступне / попереднє / за номером |
| `%` | Поділити панель на ліву й праву |
| `"` | Поділити панель на верхню й нижню |
| `o` або стрілки | Перейти до іншої панелі |
| `z` | Розгорнути панель на все вікно й назад |
| `x` | Закрити панель |
| `[` | Режим прокрутки й копіювання (`q` — вихід) |
| `d` | Від'єднатися |
| `?` | Усі сполучення |

**GNU screen** (1987) — старший мультиплексор з префіксом `Ctrl+A`: `screen -S ім'я`, від'єднатися `Ctrl+A d`, повернутися `screen -r ім'я`. У RHEL 8 його прибрали зі стандартних репозиторіїв на користь tmux, але на старих серверах screen зустрічається досі.

## Практичне завдання

```bash

# 4. Потоки

cut -d: -f7 /etc/passwd | sort | uniq -c | sort -rn

# 5. Керування завданнями
sleep 300                   # натисніть Ctrl+Z
jobs; bg; jobs; fg          # потім Ctrl+C

# 6. mc: створіть каталог (F7), скопіюйте в нього файл (F5), перегляньте (F3),

mc

# 7. tmux: сеанс, два вікна, поділ, від'єднання й повернення
tmux new -s test
```

## 🎯 Міні-проект (30 хв)

### Завдання: Консольне середовище, яке переживає обрив з'єднання

Налаштуйте bash і tmux так, щоб робоче середовище з кількома вікнами запускалося однією командою й не зникало після відключення.

**Кроки:**

1. Додайте в кінець `~/.bashrc` налаштування історії й запрошення з гілкою git. Скрипт `git-sh-prompt` постачається разом із git і має готову функцію `__git_ps1`:
```bash
# --- мої налаштування ---
HISTSIZE=50000
HISTFILESIZE=100000
HISTCONTROL=ignoreboth:erasedups
shopt -s histappend

if [ -f /usr/lib/git-core/git-sh-prompt ]; then
    . /usr/lib/git-core/git-sh-prompt
    PS1='\[\e[32m\]\u@\h\[\e[0m\]:\[\e[34m\]\w\[\e[33m\]$(__git_ps1 " (%s)")\[\e[0m\]\$ '
fi

alias ll='ls -lah'
alias ports='ss -tuln'
mkcd() { mkdir -p "$1" && cd "$1"; }
```

2. Створіть `~/.tmux.conf`:
```bash
# Поділ, що відкриває панель у поточному каталозі, і зрозумілі символи
bind | split-window -h -c "#{pane_current_path}"
bind - split-window -v -c "#{pane_current_path}"

# Панелі — клавішами vim, миша — для прокрутки й вибору панелі
bind h select-pane -L
bind j select-pane -D
bind k select-pane -U
bind l select-pane -R
set -g mouse on

# Нумерація вікон з 1, як на клавіатурі
set -g base-index 1
setw -g pane-base-index 1

set -g default-terminal "tmux-256color"
set -g history-limit 50000
bind r source-file ~/.tmux.conf \; display "Конфігурацію перечитано"
```

3. Створіть `~/scripts/dev.sh`:
```bash
#!/usr/bin/env bash
# dev.sh — робочий сеанс tmux з трьома вікнами
SESSION=dev
mkdir -p ~/projects

if ! tmux has-session -t "$SESSION" 2>/dev/null; then
    tmux new-session -d -s "$SESSION" -n code -c ~/projects
    tmux new-window -t "$SESSION" -n logs
    tmux send-keys -t "$SESSION:logs" 'journalctl -f' C-m
    tmux new-window -t "$SESSION" -n monitor
    tmux send-keys -t "$SESSION:monitor" 'top' C-m
    tmux select-window -t "$SESSION:code"
fi

# Усередині tmux — перемкнутися, ззовні — приєднатися
if [ -n "$TMUX" ]; then
    tmux switch-client -t "$SESSION"
else
    tmux attach -t "$SESSION"
fi
```

4. Зробіть скрипт виконуваним і запустіть:
```bash
chmod +x ~/scripts/dev.sh
source ~/.bashrc
~/scripts/dev.sh
```
У сеансі: `Ctrl+B |` і `Ctrl+B -` — поділ, `Ctrl+B h/j/k/l` — перехід між панелями, `Ctrl+B 1/2/3` — вікна.

5. Перевірте головне — живучість сеансу. У вікні `code` запустіть `sleep 600; echo готово`, від'єднайтеся (`Ctrl+B d`), закрийте термінал зовсім, відкрийте новий і виконайте `~/scripts/dev.sh` — `sleep` усе ще працює. Якщо є доступ до іншої машини по SSH, повторіть те саме з обривом з'єднання.

6. Для порівняння запустіть `sleep 600` без tmux у звичайному вікні, закрийте вікно й перевірте `pgrep -a sleep` — процес зник: він отримав SIGHUP.

**Очікуваний результат:**

- `~/.bashrc` з великою історією й запрошенням, що показує гілку git.
- `~/.tmux.conf` і скрипт `dev.sh`, що відкриває сеанс із вікнами `code`, `logs`, `monitor`.
- Практичне підтвердження, що процеси в tmux переживають закриття терміналу, а поза ним — ні.

**Бонус (для допитливих):**

- Запустіть tmux на віддаленому сервері й під'єднайтеся до того самого сеансу з двох терміналів — ви побачите одне й те саме «наживо», як при парному програмуванні.
- Додайте в `dev.sh` вікно з двома панелями: `tmux split-window -h -t "$SESSION:code"`.
- Спробуйте `nohup sleep 600 &` і `systemd-run --user sleep 600` як альтернативи tmux для однієї команди: `nohup` ігнорує SIGHUP, а `systemd-run` робить команду окремою службою користувача.

**1.** Що таке TTY?

- емулятор терміналу з графічним інтерфейсом
- командний інтерпретатор
- віртуальна консоль, доступна без графічного середовища
- файловий менеджер

**2.** Яке сполучення клавіш перемкне на третю віртуальну консоль?

- Ctrl+Shift+3
- Super+3
- Ctrl+Alt+F3
- Alt+F3

**3.** Чим емулятор терміналу відрізняється від оболонки?

- емулятор працює лише в TTY
- це дві назви однієї програми
- емулятор виконує команди, а оболонка малює вікно
- емулятор — це вікно, у якому працює оболонка, а оболонка виконує команди

**4.** Яке сполучення почне пошук по історії команд bash?

- Ctrl+R
- Ctrl+U
- Ctrl+W
- Ctrl+L

**5.** Що робить Ctrl+Z у bash?

- призупиняє поточну програму, повернути її можна командою fg
- виходить із сеансу
- завершує програму без збереження
- очищає екран

**6.** Що підставляє конструкція `!!`?

- перший рядок історії
- останню виконану команду
- останній аргумент попередньої команди
- поточний каталог

**7.** У чому головна перевага tmux під час роботи на сервері?

- він замінює собою оболонку bash
- він пришвидшує виконання команд
- сеанс продовжує працювати навіть після розриву з'єднання
- він шифрує трафік між клієнтом і сервером

**8.** Який префікс за замовчуванням використовує tmux?

- Ctrl+T
- Ctrl+B
- Ctrl+A
- Alt+X

**9.** Які клавіші в Midnight Commander відповідають за копіювання та видалення?

- F9 і F10
- F6 і F7
- F3 і F4
- F5 і F8

**10.** Що робить Ctrl+O у Midnight Commander?

- закриває програму
- згортає панелі й показує командний рядок
- відкриває меню налаштувань
- перемикає активну панель

## Підсумок

| Термін | Визначення |
|--------|------------|
| **TTY** | Термінал; у Linux — віртуальна консоль ядра `/dev/tty1`…`/dev/tty6` |
| **Псевдотермінал (pty)** | Пара пристроїв `/dev/ptmx` і `/dev/pts/N` для емуляторів терміналу й SSH |

| **Емулятор терміналу** | Графічна програма, що відкриває pty й малює вивід оболонки |

| **Перенаправлення** | Підміна потоку файлом: `>`, `>>`, `2>`, `2>&1`, `<` |
| **Конвеєр** | З'єднання stdout однієї програми зі stdin іншої: `a \| b` |
| **Readline** | Бібліотека редагування рядка й історії, що дає гарячі клавіші bash |
| **SIGHUP** | Сигнал, який отримують процеси, коли зникає їхній термінал |
| **Midnight Commander** | Двопанельний консольний файловий менеджер |
| **Мультиплексор (tmux, screen)** | Кілька сеансів у одному терміналі, що переживають від'єднання |

На наступних заняттях — лабораторні роботи: оболонка mc і редактор vi, потім командні файли bash.
