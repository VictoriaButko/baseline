## Ви вбиваєте процеси щодня

Кожного разу, коли ви натискаєте "X" на зависшій програмі або відкриваєте Task Manager, щоб "вбити" Chrome, який з'їв 8 ГБ RAM, ви виконуєте операцію керування процесами.

Але що насправді відбувається, коли ви клікаєте "End Task"? Як ОС знає, який процес завершити? І чому іноді навіть це не допомагає?

### Windows: Командний рядок (tasklist, taskkill)

Для автоматизації та скриптів використовують команди CMD/PowerShell:

```cmd
:: Показати всі процеси
tasklist

:: Результат:
:: Image Name                     PID Session Name        Mem Usage
:: ========================= ======== ================ ============
:: System Idle Process              0 Services                 8 K
:: System                           4 Services               148 K
:: chrome.exe                   12456 Console            2,156,432 K

:: Фільтрація: знайти процеси Chrome
tasklist /fi "imagename eq chrome.exe"

:: Фільтрація: процеси, що використовують понад 100 МБ RAM
tasklist /fi "memusage gt 100000"

:: Показати процеси у форматі CSV (для скриптів)
tasklist /fo csv

:: Показати процеси з сервісами
tasklist /svc
```

Завершення процесів:

```cmd
:: Завершити процес за ім'ям
taskkill /im notepad.exe

:: Завершити процес за PID
taskkill /pid 12456

:: Примусове завершення (force) - як kill -9 в Linux
taskkill /f /im chrome.exe

:: Завершити процес та всі дочірні процеси (tree)
taskkill /f /t /im chrome.exe

:: Завершити всі процеси, запущені від імені конкретного користувача
taskkill /f /fi "username eq DESKTOP\John"
```

### Linux: ps (process status)

Команда `ps` - це базовий інструмент для перегляду процесів у Linux.

```bash
# Показати процеси поточного терміналу
ps
#   PID TTY          TIME CMD
#  1234 pts/0    00:00:00 bash
#  5678 pts/0    00:00:00 ps

# Показати ВСІ процеси (найпопулярніший варіант)
ps aux
# USER       PID %CPU %MEM    VSZ   RSS TTY      STAT START   TIME COMMAND
# root         1  0.0  0.1 169356 13120 ?        Ss   10:00   0:02 /sbin/init
# user      1234  0.5  2.1 458932 172456 ?       Sl   10:01   0:45 /usr/bin/chrome
# ...

# Що означають колонки:
# USER   - власник процесу
# PID    - унікальний ідентифікатор
# %CPU   - використання CPU
# %MEM   - використання RAM
# VSZ    - віртуальна пам'ять (KB)
# RSS    - фізична пам'ять (KB)
# TTY    - термінал (? = фоновий процес)
# STAT   - стан процесу (S=sleep, R=running, Z=zombie)
# START  - час запуску
# TIME   - загальний час CPU
# COMMAND - команда запуску

# Показати дерево процесів (ієрархія)
ps auxf

# Показати процеси конкретного користувача
ps -u username

# Показати тільки PID та команду
ps -eo pid,cmd

# Сортування за використанням пам'яті
ps aux --sort=-%mem | head -10

# Сортування за використанням CPU
ps aux --sort=-%cpu | head -10
```

## Завершення процесів

### Linux: kill, killall, pkill

```bash
# kill - надсилає сигнал процесу за PID
kill 1234           # Надсилає SIGTERM (15) - "завершись нормально"
kill -15 1234       # Те саме, що й вище
kill -9 1234        # Надсилає SIGKILL (9) - "вбий негайно"
kill -SIGKILL 1234  # Те саме, що й вище

# killall - завершує процеси за ім'ям
killall chrome      # Завершити всі процеси chrome
killall -9 firefox  # Примусово вбити всі процеси firefox

# pkill - завершує процеси за шаблоном
pkill chrome        # Завершити процеси, що містять "chrome"
pkill -u user       # Завершити всі процеси користувача
pkill -f "python script.py"  # За повним командним рядком

# Подивитися всі доступні сигнали
kill -l
#  1) SIGHUP       2) SIGINT       3) SIGQUIT      4) SIGILL
#  5) SIGTRAP      6) SIGABRT      7) SIGBUS       8) SIGFPE
#  9) SIGKILL     10) SIGUSR1     11) SIGSEGV     12) SIGUSR2
# 13) SIGPIPE     14) SIGALRM     15) SIGTERM     ...
```

### Найважливіші сигнали

| Сигнал | Номер | Опис | Можна перехопити? |
|--------|-------|------|-------------------|
| **SIGTERM** | 15 | "Будь ласка, завершись" (graceful shutdown) | Так |
| **SIGKILL** | 9 | "Вбий негайно" (не дає процесу зреагувати) | **Ні** |
| **SIGINT** | 2 | Переривання (Ctrl+C) | Так |
| **SIGHUP** | 1 | "Термінал закрито" (часто = перезавантаження конфігу) | Так |
| **SIGSTOP** | 19 | Призупинити процес | **Ні** |
| **SIGCONT** | 18 | Продовжити призупинений процес | Так |

```bash
# Практичний приклад: коректне завершення
kill 1234           # Спробувати SIGTERM
sleep 5             # Почекати 5 секунд
kill -0 1234 2>/dev/null && kill -9 1234  # Якщо ще живий - SIGKILL
```

## Пріоритети процесів: nice та renice

Кожен процес має пріоритет, який визначає, скільки часу CPU він отримує.

```
┌───────────────────────────────────────────────────────────────────────┐
│                    ПРІОРИТЕТИ ПРОЦЕСІВ (nice)                         │
├───────────────────────────────────────────────────────────────────────┤
│                                                                       │
│   nice value:  -20 ─────────────────────────────────────────── +19    │
│                 │                    │                          │     │
│                 ▼                    ▼                          ▼     │
│            Найвищий             Звичайний              Найнижчий      │
│            пріоритет            пріоритет              пріоритет      │
│            (root only)          (default=0)           (будь-хто)      │
│                                                                       │
│   Приклади:                                                           │
│   ┌───────────────────────────────────────────────────────────────┐   │
│   │  nice = -20  │  Системні критичні процеси (тільки root)       │   │
│   │  nice = -10  │  Важливі сервіси (тільки root)                 │   │
│   │  nice =   0  │  Звичайні програми (default)                   │   │
│   │  nice = +10  │  Фонові завдання (backup, індексація)          │   │
│   │  nice = +19  │  Найменш важливі (torrent, render у фоні)      │   │
│   └───────────────────────────────────────────────────────────────┘   │
│                                                                       │
│   Правило: Чим МЕНШЕ число → ТИМ БІЛЬШЕ пріоритет                     │
│                                                                       │
└───────────────────────────────────────────────────────────────────────┘
```

```bash
# nice - запустити процес з певним пріоритетом
nice -n 10 ./heavy_task.sh    # Низький пріоритет (+10)
nice -n -5 ./important.sh     # Високий пріоритет (-5, потрібен sudo)
sudo nice -n -20 ./critical   # Максимальний пріоритет (тільки root)

# renice - змінити пріоритет запущеного процесу
renice 10 -p 1234             # Знизити пріоритет процесу 1234
sudo renice -5 -p 1234        # Підвищити пріоритет (потрібен sudo)
renice 15 -u username         # Знизити пріоритет всіх процесів користувача

# Подивитися nice value в ps
ps -eo pid,ni,cmd | head -10
#   PID  NI CMD
#     1   0 /sbin/init
#  1234  10 /usr/bin/backup
#  5678 -10 /usr/bin/mysql
```

Що означає «на одиницю nice» на практиці? Планувальник Linux ділить процесорний час пропорційно **вагам**, і кожен крок nice змінює вагу приблизно в 1,25 раза. Два процеси з nice 0 і nice 5 на одному ядрі отримають приблизно 75 % і 25 % часу; розрахунок і таблицю ваг розібрано в темі «Параметри планування» (модуль 3).

Отже, `nice -n 19` не «зупиняє» фонову задачу, а лишає їй крихти часу, коли процесор потрібен іншим, і весь процесор — коли він вільний. Жорстко обмежити частку можна іншим механізмом — cgroups (`systemd-run --scope -p CPUQuota=20% команда`).

## Створення процесів: fork/exec vs CreateProcess

Це одна з фундаментальних відмінностей між Linux та Windows.

### Linux: fork() + exec()

Linux використовує двоетапну модель створення процесів:

```
┌──────────────────────────────────────────────────────────────────────┐
│                    LINUX: fork() + exec()                            │
├──────────────────────────────────────────────────────────────────────┤
│                                                                      │
│   1. fork() - КЛОНУВАННЯ                                             │
│                                                                      │
│   ┌─────────────────┐          ┌─────────────────┐                   │
│   │  Parent Process │   fork   │  Parent Process │                   │
│   │  PID: 1000      │ ───────► │  PID: 1000      │                   │
│   │                 │          │  fork() = 1001  │ (повертає PID)    │
│   │  ┌───────────┐  │          │  ┌───────────┐  │                   │
│   │  │  Код      │  │          │  │  Код      │  │                   │
│   │  │  Дані     │  │          │  │  Дані     │  │                   │
│   │  │  Heap     │  │          │  │  Heap     │  │                   │
│   │  │  Stack    │  │          │  │  Stack    │  │                   │
│   │  └───────────┘  │          │  └───────────┘  │                   │
│   └─────────────────┘          └─────────────────┘                   │
│                                        │                             │
│                                        │ (створюється копія)         │
│                                        ▼                             │
│                                ┌─────────────────┐                   │
│                                │  Child Process  │                   │
│                                │  PID: 1001      │                   │
│                                │  fork() = 0     │ (повертає 0)      │
│                                │  ┌───────────┐  │                   │
│                                │  │  Код      │  │ спільні сторінки  │
│                                │  │  Дані     │  │ copy-on-write:    │
│                                │  │  Heap     │  │ копія — лише при  │
│                                │  │  Stack    │  │ першому записі    │
│                                │  └───────────┘  │                   │
│                                └─────────────────┘                   │
│                                                                      │
│   2. exec() - ЗАМІНА (опціонально)                                   │
│                                                                      │
│   ┌─────────────────┐  exec    ┌─────────────────┐                   │
│   │  Child Process  │ ("/bin") │  Child Process  │                   │
│   │  PID: 1001      │ ───────► │  PID: 1001      │ (PID той самий!)  │
│   │  ┌───────────┐  │          │  ┌───────────┐  │                   │
│   │  │ Старий код│  │          │  │ Новий код │  │ (заміна!)         │
│   │  │ Старі дані│  │          │  │ Нові дані │  │ (заміна!)         │
│   │  └───────────┘  │          │  └───────────┘  │                   │
│   └─────────────────┘          └─────────────────┘                   │
│                                                                      │
└──────────────────────────────────────────────────────────────────────┘
```

**Приклад на C:**

```c
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <sys/wait.h>

int main() {
    printf("Батьківський процес: PID = %d\n", getpid());

    pid_t pid = fork();  // Створюємо копію процесу

    if (pid < 0) {
        // Помилка
        perror("fork failed");
        exit(1);
    }
    else if (pid == 0) {
        // Дочірній процес (fork повернув 0)
        printf("Дочірній процес: PID = %d, Parent PID = %d\n",
               getpid(), getppid());

        // Замінюємо себе на іншу програму
        execlp("ls", "ls", "-la", NULL);

        // Якщо exec успішний, цей код НЕ виконається
        perror("exec failed");
        exit(1);
    }
    else {
        // Батьківський процес (fork повернув PID дитини)
        printf("Батько: створив дитину з PID = %d\n", pid);

        // Чекаємо завершення дочірнього процесу
        int status;
        waitpid(pid, &status, 0);
        printf("Батько: дитина завершилась зі статусом %d\n",
               WEXITSTATUS(status));
    }

    return 0;
}
```

```bash
# Компіляція та запуск
gcc -o fork_demo fork_demo.c
./fork_demo

# Вивід:
# Батьківський процес: PID = 1234
# Батько: створив дитину з PID = 1235
# Дочірній процес: PID = 1235, Parent PID = 1234
# total 8
# drwxr-xr-x  2 user user 4096 Oct 15 14:30 .
# ...
# Батько: дитина завершилась зі статусом 0
```

Спробуйте перенаправити вивід цієї програми у файл: `./fork_demo > out.txt; cat out.txt`. Рядок «Батьківський процес» з'явиться **двічі**. Причина — буфер `printf`: коли stdout — файл, а не термінал, бібліотека C накопичує вивід у пам'яті й скидає його лише наприкінці. На момент `fork()` рядок ще в буфері, тож дитина отримує його копію й теж виводить. Виправлення — `fflush(stdout)` перед `fork()`. Це класична пастка, яка чудово показує, що `fork()` копіює **весь** стан процесу, включно з даними бібліотек.

**Чому fork+exec?**
- **Гнучкість**: між fork і exec можна налаштувати дочірній процес (переспрямування I/O, зміна середовища)
- **Ефективність**: Copy-on-Write (CoW) - фізичне копіювання відбувається лише при модифікації
- **Unix-філософія**: прості примітиви, що комбінуються

Модель не бездоганна. У багатопотоковій програмі `fork()` копіює лише потік, що його викликав, а м'ютекси, захоплені іншими потоками, так і лишаються захопленими в дитині назавжди — тому між `fork` і `exec` дозволено викликати лише мінімальний набір безпечних функцій. Великому процесу навіть із copy-on-write треба скопіювати таблиці сторінок. Дослідники Microsoft Research у статті «A fork() in the road» (HotOS 2019) доводять, що `fork` — застаріла абстракція. На практиці програми дедалі частіше запускають дітей через `posix_spawn()`, яка всередині використовує швидший `vfork`/`clone` і відразу `exec`.

### Windows: CreateProcess()

Windows використовує одноетапну модель:

```
┌──────────────────────────────────────────────────────────────────────┐
│                    WINDOWS: CreateProcess()                          │
├──────────────────────────────────────────────────────────────────────┤
│                                                                      │
│   ┌─────────────────┐                      ┌─────────────────┐       │
│   │  Parent Process │   CreateProcess      │  New Process    │       │
│   │  PID: 1000      │ ─────────────────►   │  PID: 2000      │       │
│   │                 │   ("notepad.exe")    │                 │       │
│   │  ┌───────────┐  │                      │  ┌───────────┐  │       │
│   │  │  Код A    │  │   Не клонує!         │  │  Код B    │  │       │
│   │  │  Дані A   │  │   Створює новий      │  │  Дані B   │  │       │
│   │  └───────────┘  │   процес з нуля      │  │  (нові!)  │  │       │
│   └─────────────────┘                      │  └───────────┘  │       │
│                                            └─────────────────┘       │
│                                                                      │
│   Один виклик = завантаження exe + створення процесу                 │
│                                                                      │
└──────────────────────────────────────────────────────────────────────┘
```

**Приклад на C (Windows API):**

```c
#include <windows.h>
#include <stdio.h>

int main() {
    STARTUPINFO si;
    PROCESS_INFORMATION pi;

    ZeroMemory(&si, sizeof(si));
    si.cb = sizeof(si);
    ZeroMemory(&pi, sizeof(pi));

    // Командний рядок має бути змінним буфером: CreateProcessW може
    // записувати в нього, і рядковий літерал спричинить аварію
    TCHAR cmd[] = TEXT("notepad.exe");

    // Створюємо новий процес
    if (!CreateProcess(
        NULL,                   // Ім'я модуля (NULL = з командного рядка)
        cmd,                    // Командний рядок
        NULL,                   // Атрибути безпеки процесу
        NULL,                   // Атрибути безпеки потоку
        FALSE,                  // Наслідування хендлів
        0,                      // Прапори створення
        NULL,                   // Середовище (NULL = батьківське)
        NULL,                   // Робочий каталог (NULL = поточний)
        &si,                    // Структура STARTUPINFO
        &pi))                   // Структура PROCESS_INFORMATION
    {
        printf("CreateProcess failed (%d).\n", GetLastError());
        return 1;
    }

    printf("Successfully created process with PID: %lu\n",
           pi.dwProcessId);

    // Чекаємо завершення процесу
    WaitForSingleObject(pi.hProcess, INFINITE);

    // Закриваємо хендли
    CloseHandle(pi.hProcess);
    CloseHandle(pi.hThread);

    return 0;
}
```

### Порівняння: fork/exec vs CreateProcess

| Аспект | Linux (fork/exec) | Windows (CreateProcess) |
|--------|-------------------|-------------------------|
| **Кількість етапів** | 2 (fork + exec) | 1 |
| **Клонування батька** | Так (fork) | Ні |
| **Copy-on-Write** | Так, для пам'яті батька | Не потрібне: процес будується з образу exe |
| **Гнучкість** | Висока (налаштування між fork і exec) | Параметри через структури |
| **Наслідування** | Повне клонування | Вибіркове (хендли, середовище) |
| **Типове використання** | Shell, демони, fork-сервери | Запуск програм, сервіси |
| **Складність API** | Простіший (2 прості функції) | Складніший (багато параметрів) |

## 🎯 Міні-проект (30 хв)

### Завдання: Створення Process Monitor скрипта

Створіть bash-скрипт, який моніторить процеси у вашій системі та генерує звіт.

**Кроки:**

1. Створіть скрипт:
```bash
#!/bin/bash
# process_monitor.sh - Моніторинг процесів

REPORT_FILE="$HOME/process_report_$(date +%Y%m%d_%H%M%S).txt"

echo "========================================" > $REPORT_FILE
echo "    PROCESS MONITORING REPORT" >> $REPORT_FILE
echo "    $(date)" >> $REPORT_FILE
echo "========================================" >> $REPORT_FILE
```

2. Додайте інформацію про систему:
```bash
echo "" >> $REPORT_FILE
echo "=== SYSTEM INFO ===" >> $REPORT_FILE
echo "Hostname: $(hostname)" >> $REPORT_FILE
echo "Kernel: $(uname -r)" >> $REPORT_FILE
echo "Uptime: $(uptime -p)" >> $REPORT_FILE
```

3. Зберіть статистику процесів:
```bash
echo "" >> $REPORT_FILE
echo "=== PROCESS STATISTICS ===" >> $REPORT_FILE
echo "Total processes: $(ps aux | wc -l)" >> $REPORT_FILE
# Перша літера колонки STAT — стан (R, S, D, Z, T, I); +, s, l — модифікатори
ps -eo stat= | cut -c1 | sort | uniq -c >> $REPORT_FILE
```

4. Знайдіть ТОП-5 процесів за CPU та RAM:
```bash
echo "" >> $REPORT_FILE
echo "=== TOP 5 BY CPU ===" >> $REPORT_FILE
ps aux --sort=-%cpu | head -6 >> $REPORT_FILE

echo "" >> $REPORT_FILE
echo "=== TOP 5 BY MEMORY ===" >> $REPORT_FILE
ps aux --sort=-%mem | head -6 >> $REPORT_FILE
```

5. Додайте дерево процесів поточного користувача:
```bash
echo "" >> $REPORT_FILE
echo "=== MY PROCESS TREE ===" >> $REPORT_FILE
pstree -p $USER >> $REPORT_FILE

echo "" >> $REPORT_FILE
echo "Report saved to: $REPORT_FILE"
cat $REPORT_FILE
```

6. Зробіть скрипт виконуваним та запустіть:
```bash
chmod +x process_monitor.sh
./process_monitor.sh
```

**Очікуваний результат:**
Файл `process_report_YYYYMMDD_HHMMSS.txt` зі статистикою процесів, топ-споживачами CPU та RAM, та деревом ваших процесів.

**Бонус (для допитливих):**
- Додайте моніторинг конкретного процесу (наприклад, firefox) з записом у лог кожні 5 секунд
- Реалізуйте алерт, якщо процес споживає понад 50% CPU
- Створіть аналогічний скрипт для Windows (PowerShell):
  ```powershell
  Get-Process | Sort-Object CPU -Descending | Select-Object -First 5
  ```

## Тест для самоперевірки

Десять запитань, у кожному одна правильна відповідь. Якщо тема винесена вашій групі на самостійне опрацювання, цей самий тест публікується в Google Classroom — 10 балів, по одному за кожне запитання.

**1.** Чим SIGTERM відрізняється від SIGKILL?

- SIGTERM завершує лише дочірні процеси
- SIGTERM програма може перехопити й коректно завершитися, SIGKILL перехопити неможливо
- SIGKILL можна перехопити, а SIGTERM ні
- різниці немає, це синоніми

**2.** Яка команда надішле процесу сигнал негайного завершення?

- kill -9 PID
- kill PID
- kill -CONT PID
- kill -STOP PID

**3.** Який діапазон має значення nice у Linux?

- від −20 до +19
- від 0 до 31
- від −99 до +99
- від 1 до 99

**4.** Яке значення nice відповідає найвищому пріоритету?

- 0
- −20
- +19
- +10

**5.** Чому підвищити пріоритет процесу може лише адміністратор?

- nice працює лише від імені root
- значення nice зберігається в захищеній ділянці ядра
- це обмеження файлової системи
- інакше будь-який користувач забирав би процесорний час у решти

**6.** Що робить системний виклик `fork()`?

- замінює код процесу на іншу програму
- створює новий потік у межах процесу
- завершує процес
- створює копію поточного процесу

**7.** Що робить `exec()` після `fork()`?

- копіює пам'ять батька
- заміщає образ процесу новою програмою
- закриває всі відкриті файли
- повертає керування батьківському процесу

**8.** Чим модель Windows CreateProcess відрізняється від fork/exec?

- вона спершу клонує процес, а потім заміщає його
- вона не дозволяє передавати аргументи
- вона одразу створює процес із зазначеною програмою, без проміжного клонування
- вона створює лише потоки

**9.** Що станеться з дочірнім процесом у Linux, якщо його батько завершиться?

- його усиновить процес init або systemd
- він перейде у власність користувача root
- він стане процесом-зомбі назавжди
- він завершиться разом із батьком

**10.** Яка команда Windows примусово завершить процес за іменем?

- pkill ім'я
- kill -9 ім'я
- taskkill /f /im ім'я
- tasklist /fi ім'я

## Підсумок

| Термін | Визначення |
|--------|------------|
| **PID** | Process ID - унікальний ідентифікатор процесу |
| **PPID** | Parent Process ID - PID батьківського процесу |
| **fork()** | Системний виклик Linux для клонування процесу |
| **exec()** | Заміна коду процесу на новий executable |
| **CreateProcess()** | Windows API для створення нового процесу |
| **SIGTERM** | Сигнал "завершись коректно" (можна перехопити) |
| **SIGKILL** | Сигнал "завершись негайно" (не можна перехопити) |
| **nice/renice** | Керування пріоритетом процесу (-20 до +19) |
| **Zombie** | Завершений процес, що чекає wait() від батька |
| **Orphan** | Процес, чий батько завершився (усиновлюється init або subreaper) |
| **Вага nice** | Частка процесорного часу: крок nice змінює її приблизно в 1,25 раза |
| **posix_spawn()** | Створення процесу з програмою одним викликом, без повного `fork()` |

| Операція | Linux | Windows |
|----------|-------|---------|
| Перегляд процесів | ps, top, htop | tasklist, Task Manager |
| Завершення процесу | kill, killall | taskkill |
| Створення процесу | fork + exec | CreateProcess |
| Ієрархія | Дерево (init = корінь) | Плоска модель |

На наступній лекції - алгоритми планування процесів: як ОС вирішує, який процес отримає CPU наступним.
