## Як комп'ютер реагує на події миттєво?

Натисніть будь-яку клавішу на клавіатурі. Між натисканням і появою символу на екрані проходить менше 10 мілісекунд. Клікніть мишкою — курсор реагує миттєво. Підключіть USB-флешку — система її виявить за частки секунди.

Як процесор, який виконує мільярди інструкцій на секунду, "помічає" ці події? Він же зайнятий виконанням вашої програми! Чи він постійно перевіряє клавіатуру? Мишку? Всі 15 USB-портів? Мережеву карту?

**Відповідь: Ні!** Процесор не перевіряє пристрої — пристрої самі "кричать" процесору: "Гей, у мене є дані для тебе!"

Цей механізм називається **переривання (interrupt)** — фундаментальна концепція, без якої сучасні комп'ютери працювали б у тисячі разів повільніше.

```
┌───────────────────────────────────────────────────────────────────────┐
│                    ЩО ВІДБУВАЄТЬСЯ ПРИ НАТИСКАННІ КЛАВІШІ?            │
│                                                                       │
│   ┌─────────────┐                      ┌─────────────┐                │
│   │  Клавіатура │                      │     CPU     │                │
│   │             │                      │             │                │
│   │  ┌───────┐  │   Interrupt          │  Виконую    │                │
│   │  │   A   │  │ ─────────────────►   │  програму   │                │
│   │  └───────┘  │   "СТІЙ!"            │      ↓      │                │
│   │   натиснуто │                      │  Зупинився! │                │
│   └─────────────┘                      │      ↓      │                │
│                                        │  Обробляю   │                │
│   Контролер клавіатури                 │  клавішу    │                │
│   генерує сигнал IRQ1                  │      ↓      │                │
│                                        │ Продовжую   │                │
│                                        │  програму   │                │
│                                        └─────────────┘                │
│                                                                       │
│   Час реакції: < 1 мікросекунда (0.000001 сек)                        │
│   Без переривань: процесор мав би перевіряти клавіатуру 1000 разів/с  │
│                                                                       │
└───────────────────────────────────────────────────────────────────────┘
```

**Запитання до аудиторії**: Уявіть, що ви працюєте за комп'ютером і чекаєте на терміновий дзвінок. Що ефективніше: кожні 5 секунд дивитися на телефон, чи просто чекати дзвінка? Переривання — це саме "дзвінок" для процесора!

## Що таке переривання?

**Переривання (Interrupt)** — це сигнал, що повідомляє процесор про подію, яка потребує негайної уваги. При отриманні переривання процесор тимчасово зупиняє поточну програму, обробляє подію та повертається до виконання.

### Аналогія: Лікар у приймальні

```
┌───────────────────────────────────────────────────────────────────────┐
│                    АНАЛОГІЯ: ЛІКАР І ПЕРЕРИВАННЯ                      │
│                                                                       │
│   ЛІКАР = CPU                                                         │
│   ПАЦІЄНТ = Програма, що виконується                                  │
│   МЕДСЕСТРА = Контролер переривань                                    │
│                                                                       │
│   Лікар оглядає пацієнта №1 (виконання програми)                      │
│                  │                                                    │
│                  │  ┌─────────────────────────────────────────┐       │
│                  │  │ МЕДСЕСТРА: "Терміновий випадок!"        │       │
│                  │  │ (Interrupt Request)                     │       │
│                  │  └─────────────────────────────────────────┘       │
│                  │                                                    │
│                  ▼                                                    │
│   Лікар:                                                              │
│   1. Запам'ятовує, де зупинився з пацієнтом №1 (збереження стану)     │
│   2. Біжить до терміновой кімнати (перехід до ISR)                    │
│   3. Надає першу допомогу (обробка переривання)                       │
│   4. Повертається до пацієнта №1 (відновлення виконання)              │
│                                                                       │
│   ПРІОРИТЕТИ:                                                         │
│   • Зупинка серця → найвищий (NMI — Non-Maskable Interrupt)           │
│   • Перелом ноги → середній (звичайне переривання)                    │
│   • Нежить → низький (може почекати)                                  │
│                                                                       │
└───────────────────────────────────────────────────────────────────────┘
```

### Навіщо потрібні переривання?

| Опитування (Polling) | Переривання (Interrupt-driven) |
|----------------------|--------------------------------|
| CPU сам регулярно перевіряє пристрій | Пристрій сам сповіщає CPU |
| Час витрачається на перевірки, навіть коли подій немає | CPU зайнятий лише тоді, коли подія сталася |
| Реакція залежить від частоти опитування | Реакція — мікросекунди |
| Вигідне, коли подій дуже багато | Вигідне, коли події рідкі або нерегулярні |

Останній рядок важливий: переривання не завжди краще. Мережева карта на 100 Гбіт/с отримує мільйони пакетів за секунду, і переривання на кожен пакет просто «з'їло» б процесор — система витрачала б увесь час на вхід в обробник і вихід із нього, не встигаючи обробити жодного пакета (livelock, описаний Моґулом і Рамакрішнаном 1997 року). Тому Linux для мереж використовує гібрид **NAPI**: перше переривання вимикає подальші, ядро забирає пакети опитуванням, поки вони є, і лише потім знову вмикає переривання. Те саме роблять швидкі диски NVMe й `io_uring` у режимі опитування, а в крайньому випадку — DPDK, що взагалі обходиться без переривань.

```bash
# Скільки переривань за секунду обробляє система (колонка in)
vmstat 1 5

# Подивитися переривання у вашій системі
cat /proc/interrupts

# Приклад виводу:
#            CPU0       CPU1
#   0:         45          0   IO-APIC   2-edge      timer
#   1:          3          0   IO-APIC   1-edge      i8042 (клавіатура)
#   8:          0          0   IO-APIC   8-edge      rtc0
#  12:          5          0   IO-APIC  12-edge      i8042 (мишка)
# ...
```

### Апаратні переривання (Hardware Interrupts)

Генеруються зовнішніми пристроями для сповіщення процесора про події.

```
┌───────────────────────────────────────────────────────────────────────┐
│                    АПАРАТНІ ПЕРЕРИВАННЯ                               │
│                                                                       │
│   ┌─────────────┐    ┌─────────────┐    ┌─────────────┐               │
│   │ Клавіатура  │    │    Мишка    │    │    Диск     │               │
│   │   (IRQ1)    │    │   (IRQ12)   │    │   (IRQ14)   │               │
│   └──────┬──────┘    └──────┬──────┘    └──────┬──────┘               │
│          │                  │                  │                      │
│          └──────────────────┼──────────────────┘                      │
│                             │                                         │
│                             ▼                                         │
│   ┌─────────────────────────────────────────────────────────────────┐ │
│   │              INTERRUPT CONTROLLER (PIC/APIC)                    │ │
│   │                                                                 │ │
│   │  IRQ0  IRQ1  IRQ2  ... IRQ7   IRQ8  ... IRQ15                   │ │
│   │  Timer  KBD  Cascade      |    RTC       |                      │ │
│   │    │     │     │          │     │        │                      │ │
│   │    └─────┴─────┴──────────┴─────┴────────┘                      │ │
│   │                         │                                       │ │
│   │                    Priority                                     │ │
│   │                    Encoder                                      │ │
│   │                         │                                       │ │
│   └─────────────────────────┼───────────────────────────────────────┘ │
│                             │                                         │
│                             ▼                                         │
│                      ┌───────────┐                                    │
│                      │    CPU    │                                    │
│                      │   INTR    │  ◄── Один сигнал переривання       │
│                      │   pin     │                                    │
│                      └───────────┘                                    │
│                                                                       │
│   IRQ = Interrupt Request (запит на переривання)                      │
│   PIC = Programmable Interrupt Controller (8259)                      │
│   APIC = Advanced PIC (для багатопроцесорних систем)                  │
│                                                                       │
└───────────────────────────────────────────────────────────────────────┘
```

На сучасних комп'ютерах ця картина здебільшого історична. Пристрої PCI Express (NVMe, мережеві карти, відеокарти) не мають окремих дротів переривань: вони надсилають **MSI/MSI-X** (Message Signaled Interrupts) — запис невеликого повідомлення за спеціальною адресою пам'яті, яке APIC перетворює на переривання. Пристрій може мати сотні векторів MSI-X, зазвичай по одному на кожну свою чергу, і кожен можна спрямувати на окреме ядро. У `/proc/interrupts` такі рядки позначені `PCI-MSI` або `IR-PCI-MSIX`.

**Типові IRQ у класичному PC (сумісність з 8259):**

| IRQ | Пристрій | Опис |
|-----|----------|------|
| 0 | System Timer | Таймер PIT; для планування ядро сьогодні використовує локальний таймер APIC — рядок `LOC` |
| 1 | Keyboard | Клавіатура PS/2 |
| 2 | Cascade | Каскадування до другого PIC |
| 3 | COM2/COM4 | Послідовний порт |
| 4 | COM1/COM3 | Послідовний порт |
| 6 | Floppy | Дисковод (історично) |
| 8 | RTC | Real-Time Clock |
| 12 | PS/2 Mouse | Мишка PS/2 |
| 14 | Primary IDE | Перший IDE контролер |
| 15 | Secondary IDE | Другий IDE контролер |

```bash
# Подивитися IRQ та їх статистику
cat /proc/interrupts | head -20

# Виділити найактивніші: сума лічильників усіх ядер для кожного рядка
awk 'NR > 1 { s = 0; for (i = 2; i <= NF; i++) if ($i ~ /^[0-9]+$/) s += $i; print s, $0 }' \
    /proc/interrupts | sort -rn | head -10

# Моніторинг переривань в реальному часі
watch -n 1 "cat /proc/interrupts | head -15"
```

### Програмні переривання (Software Interrupts)

Генеруються програмами за допомогою спеціальних інструкцій. Головне призначення — системні виклики.

```
┌───────────────────────────────────────────────────────────────────────┐
│                    ПРОГРАМНІ ПЕРЕРИВАННЯ                              │
│                                                                       │
│   Користувацька програма                                              │
│   ┌─────────────────────────────────────────────────────────────────┐ │
│   │                                                                 │ │
│   │   printf("Hello");  // Хочу вивести текст                       │ │
│   │         │                                                       │ │
│   │         ▼                                                       │ │
│   │   write(1, "Hello", 5);  // Системний виклик                    │ │
│   │         │                                                       │ │
│   │         ▼                                                       │ │
│   │   ┌───────────────────────────────┐                             │ │
│   │   │  mov eax, 4      ; syscall #  │  x86 Linux (32-bit)         │ │
│   │   │  mov ebx, 1      ; fd = 1     │                             │ │
│   │   │  mov ecx, msg    ; buffer     │                             │ │
│   │   │  mov edx, 5      ; length     │                             │ │
│   │   │  int 0x80        ; INTERRUPT! │ ◄── Програмне переривання   │ │
│   │   └───────────────────────────────┘                             │ │
│   │         │                                                       │ │
│   └─────────┼───────────────────────────────────────────────────────┘ │
│             │                                                         │
│   ══════════╪═══════════════════════════════════════════════════════  │
│             │ Ring 3 → Ring 0 (User → Kernel)                         │
│   ══════════╪═══════════════════════════════════════════════════════  │
│             │                                                         │
│   Ядро ОС   ▼                                                         │
│   ┌─────────────────────────────────────────────────────────────────┐ │
│   │                                                                 │ │
│   │   syscall_handler:                                              │ │
│   │   ├── Перевірка номера syscall (eax = 4 = write)                │ │
│   │   ├── Виклик sys_write()                                        │ │
│   │   ├── Виведення "Hello" на термінал                             │ │
│   │   └── Повернення результату в eax                               │ │
│   │                                                                 │ │
│   └─────────────────────────────────────────────────────────────────┘ │
│                                                                       │
│   Сучасний Linux (64-bit): інструкція syscall, номер у rax, і вже     │
│   інша таблиця — write має номер 1, а не 4                            │
│                                                                       │
│   Windows:                                                            │
│   int 0x2E або syscall/sysenter                                       │
│                                                                       │
└───────────────────────────────────────────────────────────────────────┘
```

Термінологічна пастка: у документації Linux «software interrupt» (softirq) означає зовсім інше — механізм відкладеної обробки в ядрі, про який ітиметься в розділі про нижню половину обробника. А інструкція `syscall` на x86-64 взагалі не проходить через таблицю переривань: вона одразу переходить за адресою, записаною в спеціальний регістр MSR, тому й швидша за `int 0x80`.

### Виключення (Exceptions)

Виникають під час виконання інструкцій процесора при помилках або особливих ситуаціях.

```
┌───────────────────────────────────────────────────────────────────────┐
│                    ВИКЛЮЧЕННЯ (EXCEPTIONS)                            │
│                                                                       │
│   ┌─────────────────────────────────────────────────────────────────┐ │
│   │  FAULT (Збій)                                                   │ │
│   │  ────────────────                                               │ │
│   │  • Можна виправити і повторити інструкцію                       │ │
│   │  • Приклад: Page Fault (сторінка не в RAM)                      │ │
│   │                                                                 │ │
│   │  int x = *ptr;  // ptr вказує на сторінку, якої нема в RAM      │ │
│   │       │                                                         │ │
│   │       ▼                                                         │ │
│   │  Page Fault (#14)                                               │ │
│   │       │                                                         │ │
│   │       ▼                                                         │ │
│   │  OS завантажує сторінку з диска (swap)                          │ │
│   │       │                                                         │ │
│   │       ▼                                                         │ │
│   │  Інструкція повторюється успішно                                │ │
│   └─────────────────────────────────────────────────────────────────┘ │
│                                                                       │
│   ┌─────────────────────────────────────────────────────────────────┐ │
│   │  TRAP (Пастка)                                                  │ │
│   │  ─────────────                                                  │ │
│   │  • Виконання продовжується з наступної інструкції               │ │
│   │  • Приклад: Breakpoint (INT 3)                                  │ │
│   │                                                                 │ │
│   │  int 3;  // Breakpoint для дебагера                             │ │
│   │       │                                                         │ │
│   │       ▼                                                         │ │
│   │  Breakpoint Exception (#3)                                      │ │
│   │       │                                                         │ │
│   │       ▼                                                         │ │
│   │  Дебагер зупиняє програму, показує стан                         │ │
│   │       │                                                         │ │
│   │       ▼                                                         │ │
│   │  Продовження з наступної інструкції                             │ │
│   └─────────────────────────────────────────────────────────────────┘ │
│                                                                       │
│   ┌─────────────────────────────────────────────────────────────────┐ │
│   │  ABORT (Аварійне завершення)                                    │ │
│   │  ─────────────────────────────                                  │ │
│   │  • Неможливо продовжити виконання                               │ │
│   │  • Приклад: Double Fault, Machine Check                         │ │
│   │                                                                 │ │
│   │  Hardware error або критична помилка                            │ │
│   │       │                                                         │ │
│   │       ▼                                                         │ │
│   │  Abort Exception (#8 Double Fault)                              │ │
│   │       │                                                         │ │
│   │       ▼                                                         │ │
│   │  Процес/система завершується (BSOD, Kernel Panic)               │ │
│   └─────────────────────────────────────────────────────────────────┘ │
│                                                                       │
└───────────────────────────────────────────────────────────────────────┘
```

**Типові виключення x86:**

| # | Назва | Тип | Причина |
|---|-------|-----|---------|
| 0 | Divide Error | Fault | Ділення на нуль |
| 3 | Breakpoint | Trap | Інструкція INT 3 |
| 6 | Invalid Opcode | Fault | Невідома інструкція |
| 8 | Double Fault | Abort | Виключення при обробці виключення |
| 13 | General Protection | Fault | Порушення захисту пам'яті |
| 14 | Page Fault | Fault | Сторінка відсутня в RAM |

```bash
# Викликати виключення ділення на нуль (обережно!)
# python3 -c "print(1/0)"

# Подивитися Page Faults процесу
ps -o pid,min_flt,maj_flt,cmd -p $$

# min_flt = minor faults: сторінка вже в пам'яті (кеш файлів, спільна
#           бібліотека, нова нульова сторінка), треба лише додати запис
#           у таблицю сторінок
# maj_flt = major faults: сторінку треба прочитати з диска
# Промах TLB — це не page fault: таблицю сторінок процесор обходить сам
```

## Вектор переривань (Interrupt Vector Table)

**Вектор переривань** — це таблиця, що містить адреси обробників (ISR) для кожного типу переривання.

```
┌──────────────────────────────────────────────────────────────────────┐
│              INTERRUPT DESCRIPTOR TABLE (IDT) — x86                  │
│                                                                      │
│   Пам'ять                                                            │
│   ┌───────────────────────────────────────────────────────────────┐  │
│   │                                                               │  │
│   │   IDT Register (IDTR)                                         │  │
│   │   ┌───────────────────────────┐                               │  │
│   │   │ Base: 0xFFFF8000_00000000 │ ← Адреса таблиці              │  │
│   │   │ Limit: 0x0FFF (256 × 16)  │ ← Розмір таблиці              │  │
│   │   └───────────────────────────┘                               │  │
│   │              │                                                │  │
│   │              ▼                                                │  │
│   │   ┌──────────────────────────────────────────────────────┐    │  │
│   │   │  Interrupt Descriptor Table (256 записів)            │    │  │
│   │   ├──────────────────────────────────────────────────────┤    │  │
│   │   │  Entry 0  (16 bytes): Divide Error Handler           │    │  │
│   │   │  ├── Offset (адреса ISR): 0xFFFF8000_001a2b00        │    │  │
│   │   │  ├── Segment Selector: 0x0010 (Kernel Code)          │    │  │
│   │   │  ├── Type: 0xE (Interrupt Gate)                      │    │  │
│   │   │  └── DPL: 0 (Ring 0 only)                            │    │  │
│   │   ├──────────────────────────────────────────────────────┤    │  │
│   │   │  Entry 1: Debug Exception Handler                    │    │  │
│   │   ├──────────────────────────────────────────────────────┤    │  │
│   │   │  Entry 2: NMI Handler                                │    │  │
│   │   ├──────────────────────────────────────────────────────┤    │  │
│   │   │  Entry 3: Breakpoint Handler                         │    │  │
│   │   ├──────────────────────────────────────────────────────┤    │  │
│   │   │  ...                                                 │    │  │
│   │   ├──────────────────────────────────────────────────────┤    │  │
│   │   │  Entry 14: Page Fault Handler                        │    │  │
│   │   ├──────────────────────────────────────────────────────┤    │  │
│   │   │  ...                                                 │    │  │
│   │   ├──────────────────────────────────────────────────────┤    │  │
│   │   │  Entry 32-255: External Interrupts (IRQ0-223)        │    │  │
│   │   │  Entry 32: Timer (IRQ0)                              │    │  │
│   │   │  Entry 33: Keyboard (IRQ1)                           │    │  │
│   │   │  ...                                                 │    │  │
│   │   │  Entry 128 (0x80): System Call (Linux legacy)        │    │  │
│   │   └──────────────────────────────────────────────────────┘    │  │
│   │                                                               │  │
│   └───────────────────────────────────────────────────────────────┘  │
│                                                                      │
│   Виклик переривання N:                                              │
│   1. CPU зчитує IDT[N]                                               │
│   2. Перевіряє права (DPL)                                           │
│   3. Зберігає стан (RIP, RSP, RFLAGS, CS, SS)                        │
│   4. Переходить на адресу ISR                                        │
│                                                                      │
└──────────────────────────────────────────────────────────────────────┘
```

### Як CPU знаходить обробник?

```
┌──────────────────────────────────────────────────────────────────────┐
│              ПОШУК ОБРОБНИКА ПЕРЕРИВАННЯ                             │
│                                                                      │
│   Переривання IRQ1 (клавіатура)                                      │
│          │                                                           │
│          ▼                                                           │
│   ┌───────────────────────────────────────────────────────────────┐  │
│   │  1. APIC/PIC перетворює IRQ1 → вектор 33                      │  │
│   │     (вектори 0-31 зарезервовані для exceptions)               │  │
│   └────────────────────────────┬──────────────────────────────────┘  │
│                                │                                     │
│                                ▼                                     │
│   ┌───────────────────────────────────────────────────────────────┐  │
│   │  2. CPU читає IDTR, отримує базову адресу IDT                 │  │
│   │     IDTR.base = 0xFFFF8000_80001000                           │  │
│   └────────────────────────────┬──────────────────────────────────┘  │
│                                │                                     │
│                                ▼                                     │
│   ┌───────────────────────────────────────────────────────────────┐  │
│   │  3. Обчислює адресу дескриптора:                              │  │
│   │     addr = IDTR.base + (33 × 16) = 0xFFFF8000_80001210        │  │

│                                │                                     │
│                                ▼                                     │
│   ┌───────────────────────────────────────────────────────────────┐  │
│   │  4. Читає дескриптор, витягує адресу ISR:                     │  │
│   │     ISR_addr = 0xFFFF8000_002a5c40 (keyboard_interrupt)       │  │
│   └────────────────────────────┬──────────────────────────────────┘  │
│                                │                                     │
│                                ▼                                     │
│   ┌───────────────────────────────────────────────────────────────┐  │
│   │  5. Переходить на ISR:                                        │  │
│   │     • Зберігає RIP, RSP, RFLAGS на стек                       │  │
│   │     • Завантажує новий RIP = ISR_addr                         │  │
│   │     • Виконує код обробника                                   │  │
│   └───────────────────────────────────────────────────────────────┘  │
│                                                                      │
└──────────────────────────────────────────────────────────────────────┘
```

## Пріоритети переривань

Не всі переривання однаково важливі. Система пріоритетів визначає, яке переривання обробляється першим.

```
┌─────────────────────────────────────────────────────────────────────┐
│             ПРІОРИТЕТИ ПОДІЙ У ПРОЦЕСОРІ x86 (спрощено)             │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│  Якщо кілька подій очікують на межі інструкцій, процесор бере:      │
│                                                                     │
│   1. Скидання процесора, Machine Check (#18) — апаратна помилка     │
│   2. Системні події: SMI (режим керування платформою), INIT         │
│   3. Пастки налагодження від попередньої інструкції (#DB)           │
│   4. NMI — немасковане переривання: watchdog, помилки пам'яті       │
│   5. Масковані апаратні переривання (IRQ), якщо IF = 1;             │
│      між собою їх упорядковує APIC: чим більший номер вектора,      │
│      тим вищий клас пріоритету                                      │
│   6. Збої наступної інструкції: #PF, #GP, #UD тощо                  │
│                                                                     │
│  Системний виклик — це не «переривання з низьким пріоритетом»,      │
│  а звичайна інструкція: він стається тоді, коли програма його       │
│  виконує, і з апаратними перериваннями не змагається.               │
│                                                                     │
│  У класичному контролері 8259 діяв фіксований порядок IRQ:          │
│  0 (таймер) > 1 (клавіатура) > 2 → 8…15 (другий контролер) > 3…7    │
└─────────────────────────────────────────────────────────────────────┘
```

### Маскування переривань

```
┌───────────────────────────────────────────────────────────────────────┐
│              МАСКУВАННЯ ПЕРЕРИВАНЬ                                    │
│                                                                       │
│   ┌────────────────────────────────┐                                  │
│   │  RFLAGS Register               │                                  │
│   │  ┌───┬───┬───┬───┬───┬───────┐ │                                  │
│   │  │...│ IF│...│...│...│       │ │   IF = Interrupt Flag            │
│   │  └───┴─┬─┴───┴───┴───┴───────┘ │                                  │
│   │        │                       │                                  │
│   │        ├── IF = 1: Переривання дозволені                          │
│   │        └── IF = 0: Переривання заборонені (крім NMI)              │
│   └────────────────────────────────┘                                  │
│                                                                       │
│   CLI (Clear Interrupt Flag):  IF = 0  ← Заборонити переривання       │
│   STI (Set Interrupt Flag):    IF = 1  ← Дозволити переривання        │
│                                                                       │
│   КРИТИЧНА СЕКЦІЯ (Critical Section):                                 │
│   ┌─────────────────────────────────────────────────────────────────┐ │
│   │  cli              ; Заборонити переривання                      │ │
│   │  ; ... критичний код ...                                        │ │
│   │  ; Наприклад, оновлення таблиці сторінок                        │ │
│   │  ; Переривання тут можуть призвести до race condition           │ │
│   │  sti              ; Дозволити переривання                       │ │
│   └─────────────────────────────────────────────────────────────────┘ │
│                                                                       │
│   NMI (Non-Maskable Interrupt):                                       │
│   • НЕ можна заблокувати через IF                                     │
│   • Завжди обробляється негайно                                       │
│   • Використовується для критичних ситуацій                           │
│   • Приклад: watchdog timer, hardware failure                         │
│                                                                       │
│   APIC (Advanced PIC):                                                │
│   • Дозволяє маскувати окремі IRQ                                     │
│   • Встановлює пріоритети для кожного IRQ                             │
│   • Підтримує багатопроцесорні системи                                │
│                                                                       │
└───────────────────────────────────────────────────────────────────────┘
```

### Вкладені переривання

```
┌──────────────────────────────────────────────────────────────────────┐
│              ВКЛАДЕНІ ПЕРЕРИВАННЯ (Nested Interrupts)                │
│                                                                      │
│   Основний процес          Переривання          Час                  │
│   ────────────────         ───────────          ────►                │
│                                                                      │
│   ┌───────────────┐                                                  │
│   │ Програма      │                                                  │
│   │ виконується   │                                                  │
│   └───────┬───────┘                                                  │
│           │                                                          │
│           │ IRQ1 (клавіатура, пріоритет 5)                           │
│           ▼                                                          │
│   ┌───────────────┐                                                  │
│   │ Обробка IRQ1  │                                                  │
│   │ ────────────  │                                                  │
│   │               │ IRQ0 (таймер, пріоритет 10 — ВИЩИЙ)              │
│   │               ▼                                                  │
│   │   ┌───────────────┐                                              │
│   │   │ Обробка IRQ0  │  ← IRQ1 призупинено!                         │
│   │   │ ────────────  │                                              │
│   │   │ Оновлення     │                                              │
│   │   │ системного    │                                              │
│   │   │ часу          │                                              │
│   │   └───────┬───────┘                                              │
│   │           │ IRET (повернення)                                    │
│   │           ▼                                                      │
│   │ Продовження │                                                    │
│   │ обробки IRQ1│                                                    │
│   └───────┬─────┘                                                    │
│           │ IRET (повернення)                                        │
│           ▼                                                          │
│   ┌───────────────┐                                                  │
│   │ Продовження   │                                                  │
│   │ програми      │                                                  │
│   └───────────────┘                                                  │
│                                                                      │
│   Правило класичної моделі: переривання з ВИЩИМ пріоритетом може     │
│   перервати обробник переривання з НИЖЧИМ пріоритетом                │
│                                                                      │
└──────────────────────────────────────────────────────────────────────┘
```

Так вкладені переривання працюють у класичній моделі та в багатьох мікроконтролерах (контролер NVIC у ARM Cortex-M). **Linux на x86 так не робить**: з версії 2.6.35 обробники апаратних переривань завжди виконуються із забороненими на цьому ядрі перериваннями, тож один обробник не перериває інший. Це спрощує ядро й обходиться дешево саме тому, що обробники дуже короткі, а вся тривала робота винесена в нижню половину. Переривання NMI при цьому все одно може настати будь-коли.

```
│   │  │  pop rax, rbx, rcx, ...                                   │  │ │
│   │  │                                                           │  │ │
│   │  │  iretq          ; Повернення з переривання                │  │ │
│   │  └───────────────────────────────────────────────────────────┘  │ │
│   └─────────────────────────────────────────────────────────────────┘ │

│   │  • RIP (продовжити з перерваної інструкції)                     │ │

│   │  • RFLAGS (відновити IF — дозволити переривання)                │ │

│   │  • SS (user stack segment)                                      │ │

│                                                                       │
└───────────────────────────────────────────────────────────────────────┘
```

## Interrupt Service Routine (ISR)

**ISR (Interrupt Service Routine)** або **Interrupt Handler** — це функція, яка викликається при виникненні переривання.

### Вимоги до ISR

```
┌───────────────────────────────────────────────────────────────────────┐
│              ВИМОГИ ДО ISR                                            │
│                                                                       │
│   ┌─────────────────────────────────────────────────────────────────┐ │
│   │  1. ШВИДКІСТЬ                                                   │ │
│   │  ───────────────────                                            │ │
│   │  • ISR має виконуватися якомога швидше                          │ │
│   │  • Тривалі операції → відкладена обробка (bottom half)          │ │
│   │  • Типовий час: мікросекунди, не мілісекунди                    │ │
│   │                                                                 │ │
│   │  Чому? Поки ISR виконується, інші переривання можуть            │ │
│   │        бути заблоковані або відкладені                          │ │
│   └─────────────────────────────────────────────────────────────────┘ │
│                                                                       │
│   ┌─────────────────────────────────────────────────────────────────┐ │
│   │  2. АТОМАРНІСТЬ                                                 │ │
│   │  ────────────────                                               │ │
│   │  • ISR не може бути перервана (зазвичай)                        │ │
│   │  • Не може блокуватися (sleep, wait)                            │ │
│   │  • Не може викликати функції, що блокуються                     │ │
│   │                                                                 │ │
│   │  Заборонено в ISR:                                              │ │
│   │  × msleep(), mutex_lock(), kmalloc(GFP_KERNEL) — можуть заснути │ │
│   │  × Операції з файлами, копіювання в простір користувача         │ │
│   │  × Довгі цикли; дозволено kmalloc(GFP_ATOMIC) і спін-блокування │ │
│   └─────────────────────────────────────────────────────────────────┘ │
│                                                                       │
│   ┌─────────────────────────────────────────────────────────────────┐ │
│   │  3. ЗАХИСТ СПІЛЬНИХ ДАНИХ                                       │ │
│   │  ─────────────────                                              │ │
│   │  • Linux не викликає обробник однієї лінії на двох ядрах разом  │ │
│   │  • Але дані, спільні з іншим кодом драйвера, треба захищати     │ │
│   │  • spin_lock_irqsave() — спін-блокування із забороною IRQ       │ │
│   └─────────────────────────────────────────────────────────────────┘ │
│                                                                       │
│   ┌─────────────────────────────────────────────────────────────────┐ │
│   │  4. EOI (End of Interrupt)                                      │ │
│   │  ────────────────────────                                       │ │
│   │  • Обов'язково повідомити контролер про завершення              │ │
│   │  • Інакше наступні переривання не будуть оброблені              │ │
│   └─────────────────────────────────────────────────────────────────┘ │
│                                                                       │
└───────────────────────────────────────────────────────────────────────┘
```

### Приклад ISR (Linux Kernel стиль)

```c
// Спрощений приклад обробника для умовного пристрою «кнопка».
// Реальну клавіатуру PS/2 уже обслуговує драйвер i8042, тож цей код —
// лише ілюстрація API ядра

#include <linux/interrupt.h>

// Верхня половина: виконується одразу, із забороненими перериваннями
static irqreturn_t button_irq(int irq, void *dev)
{
    struct button *b = dev;

    b->last_status = readl(b->regs + STATUS);   // прочитати регістр пристрою
    writel(IRQ_ACK, b->regs + STATUS);          // підтвердити пристрою
    return IRQ_WAKE_THREAD;                     // решту — у потоці
}

// Нижня половина: звичайний потік ядра, тут можна спати
static irqreturn_t button_thread(int irq, void *dev)
{
    struct button *b = dev;

    input_report_key(b->input, KEY_ENTER, b->last_status & PRESSED);
    input_sync(b->input);                       // передати подію системі введення
    return IRQ_HANDLED;
}

static int button_probe(struct button *b)
{
    // IRQF_ONESHOT: не вмикати лінію знову, доки не завершився потік
    return request_threaded_irq(b->irq, button_irq, button_thread,
                                IRQF_ONESHOT, "lab-button", b);
}
```

Підтвердження контролеру переривань (EOI) драйвер сам не надсилає: це робить загальний код ядра після повернення з обробника. Функція `request_threaded_irq` — сучасний спосіб розділити обробник на дві половини: верхня лише забирає дані з пристрою, а нижня працює в окремому потоці ядра з іменем `irq/<номер>-lab-button`, який видно в `ps`.

### Top Half vs Bottom Half

```
┌───────────────────────────────────────────────────────────────────────┐
│              TOP HALF vs BOTTOM HALF                                  │
│                                                                       │
│   ┌─────────────────────────────────────────────────────────────────┐ │
│   │  TOP HALF (Interrupt Handler)                                   │ │
│   │  ─────────────────────────────                                  │ │
│   │                                                                 │ │
│   │  • Виконується негайно при перериванні                          │ │
│   │  • Переривання заборонені (або лише вищого пріоритету)          │ │
│   │  • Має бути максимально швидким                                 │ │
│   │                                                                 │ │
│   │  Що робить:                                                     │ │
│   │  ✓ Прочитати дані з пристрою                                    │ │
│   │  ✓ Зберегти в буфер                                             │ │
│   │  ✓ Підтвердити переривання (ACK)                                │ │
│   │  ✓ Запланувати bottom half                                      │ │
│   │                                                                 │ │
│   │  Час: < 100 мікросекунд                                         │ │
│   └─────────────────────────────────────────────────────────────────┘ │
│                              │                                        │
│                              │ schedule                               │
│                              ▼                                        │
│   ┌─────────────────────────────────────────────────────────────────┐ │
│   │  BOTTOM HALF (Deferred Work)                                    │ │
│   │  ───────────────────────────                                    │ │
│   │                                                                 │ │
│   │  • Виконується пізніше, коли CPU вільний                        │ │
│   │  • Переривання дозволені                                        │ │
│   │  • Може виконуватися довше                                      │ │
│   │                                                                 │ │
│   │  Що робить:                                                     │ │
│   │  ✓ Обробка даних з буфера                                       │ │
│   │  ✓ Копіювання до user space                                     │ │
│   │  ✓ Оновлення статистики                                         │ │
│   │  ✓ Виклик callbacks                                             │ │
│   │                                                                 │ │
│   │  Механізми в Linux:                                             │ │
│   │  • Softirqs — фіксований набір: мережа, таймери, блоки          │ │
│   │  • Tasklets — застаріли, з 6.9 їх замінюють BH workqueues       │ │
│   │  • Work queues — у потоках kworker, можуть спати                │ │
│   │  • Threaded IRQs — потік irq/N-ім'я на кожен обробник           │ │
│   │                                                                 │ │
│   │  Час: мілісекунди допустимі                                     │ │
│   └─────────────────────────────────────────────────────────────────┘ │
│                                                                       │
│   ПРИКЛАД: Мережева карта                                             │
│   ────────────────────────                                            │
│   Top Half:  Зберегти пакет у ring buffer, ACK переривання            │
│   Bottom Half: TCP/IP обробка, копіювання до socket buffer            │
│                                                                       │
└───────────────────────────────────────────────────────────────────────┘
```

### Завдання: Дослідження переривань у вашій системі

Проведіть детальний аналіз переривань у вашій системі Linux та створіть звіт.

**Кроки:**

1. Створіть робочу директорію та базовий скрипт:
```bash
mkdir ~/interrupt-lab && cd ~/interrupt-lab

cat > analyze_interrupts.sh << 'EOF'
#!/bin/bash
echo "=== АНАЛІЗ ПЕРЕРИВАНЬ ==="
echo "Дата: $(date)"
echo "Система: $(uname -r)"
echo ""
EOF
chmod +x analyze_interrupts.sh
```

2. Додайте аналіз поточних переривань:
```bash
cat >> analyze_interrupts.sh << 'EOF'
echo "--- Топ-10 активних переривань ---"
cat /proc/interrupts | head -1
cat /proc/interrupts | tail -n +2 | \
    awk '{sum=0; for(i=2;i<=NF-3;i++) sum+=$i; print sum, $0}' | \
    sort -rn | head -10 | cut -d' ' -f2-
echo ""

echo "--- Типи переривань ---"
cat /proc/interrupts | grep -E "IO-APIC|MSI|PCI" | wc -l
echo "IO-APIC/MSI/PCI переривань: $(cat /proc/interrupts | grep -E 'IO-APIC|MSI|PCI' | wc -l)"
echo ""
EOF
```

3. Додайте тест активності клавіатури. Вбудована клавіатура ноутбука зазвичай працює через контролер `i8042`, зовнішня USB-клавіатура — через контролер USB `xhci_hcd`; сумуємо лічильники всіх ядер:
```bash
cat >> analyze_interrupts.sh << 'EOF'
echo "--- Тест: переривання клавіатури ---"
count_irq() {
    grep -E "$1" /proc/interrupts | head -1 |
        awk '{ s = 0; for (i = 2; i <= NF; i++) if ($i ~ /^[0-9]+$/) s += $i; print s }'
}
DEV=$(grep -q i8042 /proc/interrupts && echo i8042 || echo xhci_hcd)
BEFORE=$(count_irq "$DEV")
echo "Натисніть кілька клавіш протягом 5 секунд ($DEV)..."
sleep 5
AFTER=$(count_irq "$DEV")
echo "Переривань за 5 секунд: $((AFTER - BEFORE))"
echo ""
EOF
```

4. Додайте аналіз softirqs:
```bash
cat >> analyze_interrupts.sh << 'EOF'
echo "--- Softirqs (відкладена обробка) ---"
cat /proc/softirqs | head -10
echo ""

echo "--- IRQ Affinity (прив'язка до CPU) ---"
for irq in $(ls /proc/irq/ | grep -E '^[0-9]+$' | head -5); do
    if [ -f /proc/irq/$irq/smp_affinity_list ]; then
        NAME=$(awk -v n="$irq:" '$1 == n { print $NF }' /proc/interrupts)
        AFFINITY=$(cat /proc/irq/$irq/smp_affinity_list)
        echo "  IRQ $irq ($NAME): CPU $AFFINITY"
    fi
done
echo ""
EOF
```

5. Додайте підсумок:
```bash
cat >> analyze_interrupts.sh << 'EOF'
echo "--- Підсумок ---"
TOTAL_INTERRUPTS=$(cat /proc/interrupts | tail -n +2 | \
    awk '{sum=0; for(i=2;i<=NF-3;i++) sum+=$i; total+=sum} END{print total}')
echo "Загальна кількість оброблених переривань: $TOTAL_INTERRUPTS"
echo ""
echo "=== КІНЕЦЬ АНАЛІЗУ ==="
EOF

./analyze_interrupts.sh | tee interrupt_report.txt
```

**Очікуваний результат:**
Файл `interrupt_report.txt` з детальною інформацією про переривання у вашій системі: найактивніші IRQ, типи переривань, тест клавіатури та аналіз softirqs.

**Бонус (для допитливих):**
- Порівняйте кількість переривань під час простою та під час активної роботи (копіювання великого файлу)
- Знайдіть IRQ вашої мережевої карти та спостерігайте за ним під час завантаження файлу
- Дослідіть, як змінюється кількість переривань при підключенні USB-пристрою

## Тест для самоперевірки

Десять запитань, у кожному одна правильна відповідь. Якщо тема винесена вашій групі на самостійне опрацювання, цей самий тест публікується в Google Classroom — 10 балів, по одному за кожне запитання.

**1.** Чим механізм переривань кращий за постійне опитування пристроїв?

- опитування неможливе на багатоядерних процесорах
- процесор не витрачає час на перевірки, а реагує лише тоді, коли подія сталася
- переривання працюють без участі ядра
- переривання не потребують обробника

**2.** Що таке IRQ?

- адреса обробника переривання
- таблиця всіх переривань системи
- запит на переривання від апаратного пристрою
- сигнал завершення обробки

**3.** Для чого призначена таблиця IDT?

- вона зіставляє номер переривання з адресою його обробника
- вона описує підключені пристрої
- вона містить пріоритети процесів
- вона зберігає чергу необроблених переривань

**4.** Яке переривання не можна замаскувати?

- програмне переривання INT
- переривання від клавіатури
- переривання від таймера
- NMI

**5.** Чим Fault відрізняється від Trap?

- Fault виникає лише в режимі користувача
- після Fault інструкцію повторюють, після Trap виконання йде з наступної
- Trap завжди завершує процес
- після Fault виконання йде далі, після Trap інструкцію повторюють

**6.** До якого типу винятків належить page fault?

- Abort: процес завершується негайно
- Trap: виконання продовжується з наступної інструкції
- це не виняток, а апаратне переривання
- Fault: сторінку підвантажують і повторюють інструкцію

**7.** Чому обробник переривання має бути максимально коротким?

- процесор не дозволяє виконувати понад сто інструкцій
- довгий обробник не вміщується в таблицю IDT
- поки він виконується, інші переривання чекають або втрачаються
- він займає багато місця в пам'яті ядра

**8.** У чому суть поділу обробника на верхню та нижню половини?

- верхня працює в режимі користувача, нижня — в режимі ядра
- верхня обробляє апаратні переривання, нижня — програмні
- це два незалежні обробники того самого пристрою
- верхня швидко приймає дані з перериваннями заборонені, нижня доопрацьовує їх пізніше

**9.** Яке переривання має найвищий пріоритет?

- машинна перевірка апаратної помилки процесора
- переривання від клавіатури
- програмне переривання системного виклику
- переривання від таймера

**10.** Яка команда покаже статистику переривань у Linux?

- vmstat 1
- pstree
- cat /proc/interrupts
- cat /proc/stat

## Підсумок

| Термін | Визначення |
|--------|------------|
| **Переривання (Interrupt)** | Сигнал, що сповіщає CPU про подію, яка потребує уваги |
| **IRQ (Interrupt Request)** | Запит на переривання від апаратного пристрою |
| **IDT (Interrupt Descriptor Table)** | Таблиця з адресами обробників переривань |
| **ISR (Interrupt Service Routine)** | Функція-обробник конкретного переривання |
| **NMI (Non-Maskable Interrupt)** | Переривання, яке не можна ігнорувати |
| **Exception (Виключення)** | Переривання, викликане помилкою при виконанні інструкції |
| **Fault** | Виключення, яке можна виправити і повторити інструкцію |
| **Trap** | Виключення, після якого виконання продовжується далі |
| **Top Half** | Швидка частина обробника, виконується негайно |
| **Bottom Half** | Відкладена обробка, виконується пізніше |

| Тип переривання | Джерело | Приклад |
|-----------------|---------|---------|
| Апаратне | Зовнішній пристрій | Клавіатура, мишка, диск |
| Програмне | Інструкція INT N | Системний виклик (INT 0x80) |
| Виключення | CPU при помилці | Ділення на 0, Page Fault |

| Подія | Можна маскувати? | Примітка |
|-------|------------------|----------|
| Machine Check | Ні | Найвищий пріоритет, апаратна помилка |
| NMI | Ні: прапорець IF на нього не діє | Watchdog, помилки пам'яті |
| Апаратні IRQ | Так, прапорцем IF або в APIC | MSI-X у сучасних пристроях PCIe |
| Виключення | Ні, це наслідок інструкції | #PF, #GP, #DE |
| Системний виклик | — | Звичайна інструкція `syscall`, а не подія з пріоритетом |

| Термін | Визначення |
|--------|------------|
| **MSI/MSI-X** | Переривання як запис повідомлення в пам'ять; сотні векторів на пристрій |
| **NAPI** | Гібрид переривань і опитування в мережевому стеку Linux |
| **Threaded IRQ** | Нижня половина обробника в окремому потоці ядра |

На наступній лекції — керування процесами: створення, завершення, міжпроцесна комунікація.
