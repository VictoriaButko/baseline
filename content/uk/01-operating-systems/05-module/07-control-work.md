**Мета:** перевірити засвоєння матеріалу модулів 1-5: будова та функції ОС, паралельність, планування процесів, віртуальна пам'ять, управління пристроями.

**Тривалість:** 2 академічні години.

**Дозволено:** власний конспект, шпаргалки з матеріалів курсу, комп'ютер для практичної частини. **Заборонено:** готові відповіді з мережі, обмін файлами між студентами.

## Структура роботи

Робота складається з трьох частин, які перевіряють різні рівні засвоєння.

```
┌─────────────────────────────────────────────────────────────────────┐
│                    СТРУКТУРА КОНТРОЛЬНОЇ РОБОТИ                     │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│   ЧАСТИНА 1. ТЕСТ                              10 балів             │
│   10 запитань із варіантами, по 1 балу.                             │
│   Перевіряє: знання означень і фактів.                              │
│   Час: 15 хвилин.                                                   │
│                                                                     │
│   ЧАСТИНА 2. КОРОТКІ ВІДПОВІДІ ТА РОЗРАХУНКИ   12 балів             │
│   4 завдання по 3 бали: обчислення й пояснення.                     │
│   Перевіряє: уміння застосувати формулу та обґрунтувати.            │
│   Час: 35 хвилин.                                                   │
│                                                                     │
│   ЧАСТИНА 3. ПРАКТИЧНЕ ЗАВДАННЯ                 8 балів             │
│   Робота в системі за індивідуальним варіантом.                     │
│   Перевіряє: уміння діяти, а не переказувати.                       │
│   Час: 30 хвилин.                                                   │
│                                                                     │
│   РАЗОМ: 30 балів                                                   │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

Таблиця 1 — Переведення балів в оцінку

| Бали | Оцінка | Що це означає |
|------|--------|---------------|
| 27-30 | 5 (відмінно) | усі частини виконано, розрахунки обґрунтовано |
| 21-26 | 4 (добре) | є неточності в поясненнях або одна помилка в розрахунку |
| 15-20 | 3 (задовільно) | тест складено, практична частина виконана частково |
| менше 15 | не зараховано | робота підлягає перескладанню |

## Що треба повторити

Перелік тем для підготовки — водночас це перелік того, що перевіряється.

| Модуль | Ключові питання |
|--------|-----------------|
| 1. Основи ОС | ядро, процес, системний виклик, режими процесора, архітектури ядра, вимоги до ОС |
| 2. Паралельність | конкурентність і паралелізм, процеси й потоки, стани процесу, перемикання контексту, переривання |
| 3. Планування | рівні планування, критерії, алгоритми та їх розрахунок, динамічні пріоритети, гарантії обслуговування |
| 4. Віртуальна пам'ять | трансляція адрес, таблиці сторінок, TLB, сторінкові відмови, алгоритми заміщення, пробуксовка |
| 5. Пристрої | блокові й символьні пристрої, DMA, буферизація, відкладений запис, драйвери |

## Зразок варіанта

### Частина 1. Приклади тестових запитань

**1.** Що є одиницею планування у Windows?

- потік
- завдання
- процес
- служба

**2.** Скільки переривань потрібно для читання блока 4 КіБ через DMA?

- одне на кожен байт
- одне на кожні 512 байтів
- одне на весь блок
- жодного

**3.** Що означає повернення `write()` з успіхом у Linux за замовчуванням?

- дані поставлено в чергу пристрою
- дані скопійовано в кеш сторінок, на носій вони потраплять пізніше
- дані записано й перевірено контрольною сумою
- дані фізично записано на носій

### Частина 2. Приклади завдань із розрахунком

**Завдання 2.1.** Задачі надходять так: P1 (прихід 0, обчислення 6), P2 (прихід 1,
обчислення 3), P3 (прихід 2, обчислення 1). Побудуйте діаграму виконання для
FCFS і для SJF, обчисліть середній час очікування в обох випадках і поясніть
різницю одним реченням.

**Завдання 2.2.** Звернення до TLB коштує 1 нс, до пам'яті — 100 нс. Обчисліть
середній час доступу при влучності TLB 95 % для однорівневої таблиці сторінок.
Порівняйте з ідеальними 100 нс і назвіть втрати у відсотках.

**Завдання 2.3.** Рядок звернень до сторінок: 1, 2, 3, 4, 1, 2, 5. Кадрів — три.
Порахуйте кількість сторінкових відмов для FIFO та для LRU. Який алгоритм дав
кращий результат саме на цьому рядку?

**Завдання 2.4.** Програма записує 2 МіБ у файл по 1 байту за виклик. Системний
виклик коштує 1 мкс. Скільки часу піде лише на системні виклики? Скільки —
якщо писати блоками по 4 КіБ? Поясніть, чому різниця не залежить від швидкості
диска.

### Частина 3. Приклад практичного завдання

Запустіть два однакові навантаження з різними значеннями `nice` на одному ядрі,
через хвилину зніміть спожитий процесорний час обох і покажіть, що відношення
збігається з відношенням ваг. Наведіть команди та вивід.

## Варіанти практичної частини

| № | Завдання |
|---|----------|
| 1 | Виміряти кількість перемикань контексту у спокої та під навантаженням, пояснити різницю |
| 2 | Показати різницю між `VmSize` і `VmRSS` для процесу, що виділив пам'ять без запису |
| 3 | Визначити тип двох процесів (обмежений процесором чи вводом-виводом) за їхніми лічильниками |
| 4 | Виміряти кількість дрібних сторінкових відмов при заповненні масиву на 128 МіБ |
| 5 | Порівняти кількість системних викликів `write` при різних розмірах буфера |
| 6 | Показати вплив `nice` на розподіл процесорного часу між двома процесами |
| 7 | Виміряти час холодного й теплого читання файлу, пояснити різницю |
| 8 | Визначити планувальник вводу-виводу для накопичувача й пояснити його вибір |
| 9 | Показати зростання `Dirty` у `/proc/meminfo` під час копіювання великого файлу |
| 10 | Знайти процес із найбільшою кількістю серйозних сторінкових відмов |
| 11 | Виміряти найгіршу затримку пробудження у спокої та під навантаженням |
| 12 | Показати перелік переривань і визначити пристрій, що генерує їх найбільше |
| 13 | Порівняти час запису з `conv=fsync` і без нього, пояснити різницю |
| 14 | Визначити, у якому режимі завантажено систему, і підтвердити це двома способами |
| 15 | Показати, що зміна прав не діє на файловій системі FAT32 |
| 16 | Виміряти `wait_sum` процесу до й після створення конкурентного навантаження |
| 17 | Побудувати дерево процесів і знайти батьківський процес для оболонки |
| 18 | Показати вплив розміру блока на швидкість копіювання командою `dd` |
| 19 | Визначити кількість ядер і зіставити її із середнім навантаженням системи |
| 20 | Знайти в журналі ядра послідовність підключення накопичувача й пояснити кожен рядок |

## Порядок проведення

1. Студент отримує номер варіанта та бланк роботи.
2. Частини 1 і 2 виконуються письмово, без комп'ютера.
3. Частина 3 виконується на робочому місці; результат подається як знімки
   екрана або текстовий файл із командами та виводом.
4. Роботи здаються наприкінці заняття; часткове виконання оцінюється за
   фактично набраними балами.

## Критерії оцінювання

Робота оцінюється за загальними критеріями курсу — див. [Критерії оцінювання лабораторних робіт](#/01-operating-systems/grading).

Додатково для цієї роботи:

- у частині 2 бал знімається за відповідь без обґрунтування, навіть якщо
  числовий результат правильний;
- у частині 3 бал знімається за вивід без пояснення, що саме він показує;
- робота, у якій частина 3 не виконана взагалі, не може бути оцінена вище
  ніж «задовільно».
