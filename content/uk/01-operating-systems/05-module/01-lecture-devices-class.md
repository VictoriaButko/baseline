## Мільйони разів повільніше

Процесор дістає число з кеша першого рівня приблизно за наносекунду. Жорсткий
диск позиціонує головку за сім мілісекунд. Різниця — сім мільйонів разів.

Щоб відчути масштаб, переведімо все в людський час: нехай звернення до кеша
триває одну секунду.

```
┌─────────────────────────────────────────────────────────────────────┐
│          ЗАТРИМКИ В ЛЮДСЬКОМУ МАСШТАБІ (1 нс = 1 секунда)           │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│   Кеш L1              1 нс          1 секунда                       │
│   Оперативна пам'ять  100 нс        1,7 хвилини                     │
│   NVMe SSD            50 мкс        14 годин                        │
│   Пошук на HDD        7 мс          81 день                         │
│   Запит через інтернет 50 мс        1,6 року                        │
│                                                                     │
│   Процесор, який «чекає на диск», у людському масштабі              │
│   чекає майже три місяці. Саме тому ОС не чекає разом із            │
│   ним, а перемикається на інший процес.                             │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

Цей розрив і є причиною всього, що ми вивчатимемо в цьому модулі: переривань
замість опитування, буферизації, кешування, прямого доступу до пам'яті.

**Запитання до аудиторії**: якщо диск у мільйони разів повільніший за пам'ять,
чому програма, що читає файл, не працює в мільйони разів повільніше?

## Скільки пристроїв у вашому комп'ютері

```bash
# Блокові пристрої: диски, розділи, оптичні приводи
lsblk

# Пристрої на шині PCI: відеокарта, мережа, контролери
lspci | head -15

# Пристрої USB
lsusb

# Усі класи пристроїв, відомі ядру
ls /sys/class | head -20

# Скільки всього записів у /dev
ls /dev | wc -l
```

Типова відповідь для звичайного ноутбука — кількасот записів у `/dev`. Кожен із
них ОС має якось класифікувати, бо працювати з клавіатурою й накопичувачем
однаково неможливо.

```
┌─────────────────────────────────────────────────────────────────────┐

│                                                                     │
│   1. ЗА ПРИЗНАЧЕННЯМ                                                │
│      введення (клавіатура, сканер) | виведення (монітор,            │
│      принтер) | зберігання (диск) | зв'язок (мережева карта)        │

│   2. ЗА ОДИНИЦЕЮ ОБМІНУ                                             │
│      блокові (сталий блок, зазвичай 512 Б або 4 КіБ)                │

│                                                                     │
│   3. ЗА ПОРЯДКОМ ДОСТУПУ                                            │
│      довільний (диск: будь-який блок за адресою)                    │

│                                                                     │
│   4. ЗА КІЛЬКІСТЮ КОРИСТУВАЧІВ                                      │

│                                                                     │
│   5. ЗА ШВИДКІСТЮ                                                   │
│      від десятків байтів за секунду до гігабайтів                   │
│                                                                     │

```

### Чому блокові й символьні — найважливіший поділ

Саме він визначає, який набір операцій ОС надає програмі.

| | Блоковий пристрій | Символьний пристрій |
|---|-------------------|---------------------|
| Одиниця обміну | блок сталого розміру | байт |
| Доступ | довільний, за номером блока | послідовний |
| Буферизація | обов'язкова, через кеш сторінок | зазвичай мінімальна |
| Файлова система | можна створити | не можна |
| Приклади | `/dev/sda`, `/dev/nvme0n1` | `/dev/tty`, `/dev/random`, `/dev/null` |
| Позначка в `ls -l` | `b` | `c` |

```bash
# Перша літера в правах показує тип пристрою
ls -l /dev/sda /dev/null /dev/random 2>/dev/null

# brw-rw----  → блоковий
# crw-rw-rw-  → символьний

# Старший номер визначає драйвер, молодший — конкретний пристрій
ls -l /dev/sda /dev/sda1 2>/dev/null

# Які драйвери зареєстровані під якими старшими номерами
cat /proc/devices
```

**Старший і молодший номери** — це адреса пристрою всередині ядра. Старший каже,
який драйвер обслуговує пристрій, молодший — котрий саме це пристрій із тих, що
обслуговує драйвер. Тому `/dev/sda` і `/dev/sda1` мають однаковий старший номер
і різні молодші: один драйвер, різні об'єкти.

### Мережеві пристрої — окремий випадок

Мережева карта не є ні блоковою, ні символьною: у `/dev` її немає взагалі.

```bash
# Мережеві інтерфейси не мають файлів у /dev
ls /sys/class/net
ip -brief link
```

**Чому так.** Блокові й символьні пристрої вкладаються в модель «файл, який можна
відкрити, прочитати й записати». Мережа працює інакше: пакет має адресата,
порядок доставки не гарантований, а сам обмін відбувається не потоком, а
повідомленнями. Натягнути на це файловий інтерфейс можна — так зробили в Plan 9 —
але в UNIX обрали окрему абстракцію, **сокет**. Це добрий приклад того, що
«все є файлом» — зручне правило, а не закон природи.

## Розрив у швидкостях

Таблиця 1 — Типові швидкості обміну

| Пристрій | Пропускна здатність | Затримка |
|----------|---------------------|----------|
| Клавіатура | десятки байтів за секунду | 1-10 мс |
| USB 2.0 | 60 МБ/с теоретично, 35-40 МБ/с на практиці | ~1 мс |
| Жорсткий диск | 150-250 МБ/с | 5-10 мс |
| SATA SSD | 550 МБ/с | ~0,1 мс |
| NVMe SSD | 3000-7000 МБ/с | 20-100 мкс |
| Мережа 1 Гбіт/с | 125 МБ/с | 0,1-0,5 мс (локальна) |
| Оперативна пам'ять | 20-50 ГБ/с | 100 нс |

**Пропускна здатність і затримка — різні речі, і плутати їх не можна.** Вантажівка
з тисячею дисків, що їде добу, має колосальну пропускну здатність і жахливу
затримку. Для копіювання архіву важлива перша характеристика, для роботи бази
даних — друга.

### Розбір помилкового міркування

> «USB 3.0 — це 5 Гбіт/с, тобто 625 МБ/с. Мій зовнішній диск працюватиме так.»

Порахуймо чесно:

```
5 Гбіт/с — це швидкість лінії з кодуванням 8b/10b:
з кожних 10 переданих бітів 8 — корисні.

5 × 0,8 = 4 Гбіт/с корисних = 500 МБ/с

Далі відніміть службові заголовки протоколу USB, витрати
на командний рівень SCSI, і лишиться приблизно 380-450 МБ/с.
А якщо всередині коробки звичайний жорсткий диск, обмежить
не шина, а сам диск — 150-250 МБ/с.
```

Правило, яке варто засвоїти: **швидкість системи визначає найповільніша ланка**,
а паспортні цифри інтерфейсу — це верхня межа для лінії, а не для даних.

## Як пристрій підключено до системи

```
┌─────────────────────────────────────────────────────────────────────┐
│                       ВІД ПРОГРАМИ ДО ЗАЛІЗА                        │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│     Програма                                                        │
│        │  read(), write()                                           │
│        ▼                                                            │
│     Ядро: файлова система, кеш сторінок                             │
│        │                                                            │
│        ▼                                                            │
│     Драйвер пристрою                                                │
│        │  запис у регістри контролера                               │
│        ▼                                                            │
│     Контролер (на материнській платі або самому пристрої)           │
│        │  шина: PCIe, USB, SATA                                     │
│        ▼                                                            │
│     Механіка або мікросхеми пристрою                                │
│        │                                                            │
│        └──► переривання назад до процесора: «готово»                │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

**Контролер** — це невеликий спеціалізований комп'ютер, що керує пристроєм.
Драйвер спілкується з ним через **регістри**: комірки, які виглядають як пам'ять
або порти введення-виведення.

| Регістр | Призначення |
|---------|-------------|
| Стану | чи готовий пристрій, чи сталася помилка |
| Команди | яку операцію виконати |
| Даних | байт або блок для обміну |
| Адреси | куди в пам'яті класти результат (для DMA) |

Обмін через регістр даних байт за байтом означає, що процесор особисто
перекладає кожен байт. Для 4 КіБ це 4096 операцій. Тому існує **прямий доступ до
пам'яті** (DMA): процесор каже контролеру «поклади блок за адресою X» і
звільняється, а контролер після завершення надсилає переривання.

```bash
# Які пристрої використовують DMA-канали (класична шина ISA)
cat /proc/dma

# Області пам'яті, відображені на пристрої
sudo head -20 /proc/iomem 2>/dev/null || head -20 /proc/iomem
```

## Виключні пристрої та спулінг

Диск можна ділити між процесами: операції чергуються, і кожен отримує свої дані.
Принтер так ділити не можна — сторінка з перемішаних рядків двох документів
нікому не потрібна.

```
┌─────────────────────────────────────────────────────────────────────┐
│                   СПУЛІНГ: ЯК ПОДІЛИТИ НЕПОДІЛЬНЕ                   │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│   Процес A ──┐                                                      │
│              ├──► черга завдань на диску ──► демон ──► принтер      │
│   Процес B ──┘        (spool)                друку                  │
│                                                                     │
│   Кожен процес «друкує» миттєво: він лише кладе завдання            │
│   у чергу. Демон друку — єдиний, хто справді володіє                │
│   пристроєм, — виконує завдання по черзі.                           │
│                                                                     │
│   Той самий прийом: черги завдань у кластерах, черги                │
│   повідомлень у розподілених системах.                              │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

```bash
# Черга друку та стан принтерів
lpstat -p -d 2>/dev/null || echo "CUPS не встановлено"
lpq 2>/dev/null
```

Спулінг — приклад **віртуалізації пристрою**: кожен процес бачить власний
принтер, хоча фізичний один. Той самий принцип ОС застосовує до процесора
(кожен процес бачить власний) і до пам'яті (кожен бачить власний адресний
простір).

## Практичне завдання

1. Складіть таблицю всіх блокових пристроїв вашої системи з `lsblk`: розмір, тип,
   точка монтування.
2. Знайдіть у `/dev` три символьні пристрої й поясніть призначення кожного.
3. Порівняйте старші номери `/dev/sda` та `/dev/nvme0n1` (якщо є обидва). Чому
   вони різні?
4. Виміряйте реальну швидкість вашого накопичувача й порівняйте її з паспортною:

```bash
# Запис 1 ГіБ без кешування (обережно: пише файл у поточний каталог)
dd if=/dev/zero of=./test.bin bs=1M count=1024 oflag=direct 2>&1 | tail -1
rm -f ./test.bin
```

## 🎯 Міні-проект (30 хв)

### Завдання: паспорт пристроїв власного комп'ютера

**Кроки:**

1. Зберіть перелік блокових пристроїв із розмірами й типами:

```bash
lsblk -o NAME,TYPE,SIZE,ROTA,MOUNTPOINT
```

Стовпець `ROTA` показує, обертовий це носій (1) чи твердотільний (0).

2. Визначте старший і молодший номери для кожного:

```bash
ls -l /dev/sd* /dev/nvme* 2>/dev/null
```

3. Виміряйте реальну швидкість послідовного читання. Підставте свій диск з
   виводу `lsblk` (`sda`, `nvme0n1`, `vda`); обидві команди лише читають:

```bash
DISK=/dev/sda
sudo hdparm -t "$DISK"
# якщо hdparm немає — те саме засобами dd, в обхід кеша сторінок
sudo dd if="$DISK" of=/dev/null bs=1M count=512 iflag=direct 2>&1 | tail -1
```

4. Складіть таблицю: пристрій, тип, паспортна швидкість (знайдіть у мережі за
   моделлю), виміряна швидкість, відсоток від паспортної.

5. Поясніть розбіжність: де саме «загубилася» різниця?

**Очікуваний результат:** виміряна швидкість становитиме 60-90 % від паспортної.

**Бонус (для допитливих):**

- Порівняйте швидкість із прапорцем `oflag=direct` і без нього. Різниця покаже
  внесок кеша сторінок — саме про нього буде наступна тема.

## Підсумок

| Ознака | Види | Приклад |
|--------|------|---------|
| **Призначення** | введення, виведення, зберігання, зв'язок | клавіатура, монітор, диск, мережа |
| **Одиниця обміну** | блокові, символьні | `/dev/sda`, `/dev/tty` |
| **Доступ** | довільний, послідовний | диск, мікрофон |
| **Спільність** | виключні, спільні, віртуалізовані | принтер, диск, принтер через спулінг |

| Термін | Визначення |
|--------|------------|
| **Контролер** | Спеціалізований процесор, що керує пристроєм |
| **Регістри контролера** | Комірки стану, команди, даних і адреси |
| **DMA** | Перенесення даних у пам'ять без участі процесора |
| **Старший / молодший номер** | Адреса драйвера / конкретного пристрою |
| **Спулінг** | Черга завдань для неподільного пристрою |

**Ключовий висновок:** уся складність керування пристроями виростає з одного
факту — вони на порядки повільніші за процесор і дуже різні між собою. Тому ОС
не працює з пристроями напряму, а будує кілька рівнів абстракції: клас пристрою,
драйвер, контролер. Наступна тема — як саме влаштована ця вертикаль.
